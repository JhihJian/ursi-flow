# 平台 MCP 后端库

## 功能意图

宿主注入登记仓储、凭据查找和策略文件位置后，可以通过 Rust 接口或 Axum 路由访问登记的 Streamable HTTP 服务。协议、授权和限额由库管理，宿主管理入站鉴权与数据落盘。

## 关键功能与验收

### 登记与发现

#### 验收

- 管理 API 可以列出、登记和删除服务。登记成功得到持久的服务标识。删除后，原标识无法用于发现或生成。
- 平台绑定登记保存完整服务地址与可选的凭据引用。引用不存在或值不能用于 Bearer 时拒绝登记。服务记录与列表只含引用。新会话向宿主读取当前值。
- 部署级策略文件存在时，登记和连接必须匹配完整地址与凭据引用。文件策略绑定始终要求该文件。凭据来源与回退规则由宿主决定，库不读取进程环境。
- 使用官方 `rmcp` SDK 协商 Streamable HTTP 会话并逐页请求 `resources/list`，兼容 POST 返回的 JSON 和 SSE。资源数组包含名称、URI、可选媒体类型和描述。每个 HTTP 响应累计不超过 4 MiB，通信不自动重连或重放。
- `server/discover` 使用 2026-07-28 请求元数据，返回服务器声明的版本列表、能力细项、自报身份及说明。旧服务通过 SDK 的 `initialize` 协商，不虚构版本列表。资源行保留可选标题和字节数。
- 检查接口同时返回本次协商的协议版本、对端实现标识及资源、工具、提示词的能力声明。未声明资源能力的服务可完成检查，结果中资源数组为空，且不请求 `resources/list`。
- 协议错误、游标循环、超时或响应超限使整次发现失败。

### 执行器协议检查

#### 验收

- 按已登记的 Streamable HTTP 服务 ID 显式检查协议，沿用出站授权和操作限额。只将成功 `server/discover` 响应中的 `ursi/executorProtocol` 字符串 `"1"` 识别为执行器 v1。未知版本、类型错误、未声明和旧握手有独立结果。
- 检查不请求资源或工具目录，不调用工具，也不改变调用许可。只有完成协议检查才保存归一化结果和时间。失败保留上次结果，并行删除后不恢复登记。
- 列表返回保存的结果，不连接远端。登记请求不接受检查结果。旧登记无需更改即可检查。

### 工具、提示词与模板

#### 验收

- 认证接口按服务能力发现工具、提示词、资源模板；支持分页，重复项、循环游标或限额超出时整次失败。
- 会话建立失败与目录分页失败分别标明阶段，远端 HTTP 或 JSON-RPC 错误仅展示状态码或数字错误码，不回显凭据、响应正文或远端错误消息。
- 工具调用前检查精确名称白名单和可选部署策略，默认拒绝。调用保留原始 MCP 结果，不重放请求。提示词接受字符串参数，返回消息。
- 每个服务独立保存设置。GitHub 工具集和只读头仅发往官方默认 HTTPS 端点，不改变本地调用许可。

### 单个资源预览

#### 验收

- 预览接口接收服务标识和资源 URI，新建会话调用 `resources/read`，返回每个分片的 URI、可选媒体类型和 `text` 或 `blob` 之一。URI 为空或超过 4096 字节时拒绝请求，不建立连接。
- 同一实例的预览、发现、其他远端操作与宿主批量读取共用四个并发名额和 4 MiB 响应上限，单次限时 25 秒。远端 JSON-RPC 错误和连接失败只返回固定的不可用提示，不回显远端原文。预览只读取，不修改服务登记。

### 嵌入宿主

#### 验收

- 构建无需 Workbench 或 Flow。只提供内存仓储和凭据查找的宿主可挂载路由，登记并浏览本机测试服务。
- 宿主可要求所有登记和连接都匹配部署策略。该模式下，策略缺失时拒绝登记和出站访问。
- 批量读取可在一个操作名额内按序读取多个资源。每次读取建立新会话并检查当前策略与凭据，释放操作时归还名额。
