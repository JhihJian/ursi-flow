# ursi-flow Web

React 19 + TypeScript 工作台，提供工作流、角色、运行、产物、沙箱、模型连接和对话七个业务域。默认使用浏览器内模拟 API，可独立完成配置管理、发起运行、审批返工、产物下载和对话演示的页面验收。

演示配置、快照、运行记录、事件和产物保存到当前站点的 localStorage，键为 `ursi-flow-demo-v1`。模型连接与 MCP 仅填写演示用 `credentialRef`，例如 `env:DEMO_MODEL_TOKEN`，不填写真实密钥。模型调用、脚本、工具日志和沙箱资源均为模拟。真实 server API 联合验收覆盖协议和持久化，真实执行链路单独验收。

## 本地运行

使用 Node.js 24 和 npm，在 `web` 目录执行：

```bash
npm ci
npm run dev
```

开发服务监听 `0.0.0.0:5173`，本机访问 `http://localhost:5173`。默认演示模式可在未启动 server 时使用，首页进入工作流。

`.env.example` 可复制为 `.env.local`。`VITE_API_MODE=mock` 使用模拟 API，`VITE_API_MODE=live` 使用网络 API。`URSI_API_PROXY` 指定开发代理目标，默认为 `http://127.0.0.1:8080`。这些模式在启动或构建时确定，修改配置后需重新启动。

```dotenv
VITE_API_MODE=mock
URSI_API_PROXY=http://127.0.0.1:8080
```

`URSI_API_PROXY` 只由开发服务读取。`VITE_*` 会进入浏览器构建配置，凭据应由真实服务解析引用。

## 演示设置

点击侧边栏“演示模式”打开“演示模式设置”，小屏先打开导航菜单。设置提供以下控制：

- **请求延迟**：默认 180ms，可设为 0 至 30000ms。设为 1500ms 后刷新列表，可观察加载提示与按钮等待状态。
- **让下一次请求失败**：保存后，下一个业务请求返回一次模拟 503。设置与重置请求不消费此开关。在角色、产物或连接等列表页开启，再刷新或进入页面，可观察错误与重试恢复。运行详情持续轮询时，轮询也可能消费该开关。
- **重置演示**：确认后恢复初始配置、运行、事件、产物和延迟设置，并重新加载页面。当前浏览器的演示修改会被清除。

刷新页面可读回已保存的演示数据。演示状态由单个标签页管理，同时打开多个标签页修改可能覆盖彼此的保存结果，验收时使用一个标签页。浏览器禁止访问 localStorage 时使用会话内存，刷新后的数据保留以存储可用为前提。外观偏好使用两个独立键：明暗存于 `ursi-flow:theme`，主色调存于 `ursi-flow:palette`。

## 七域独立操作验收

以下步骤使用默认模拟 API，可按域单独操作。各域开始前可重置演示数据恢复相同基线。

| 业务域 | 操作 | 可观察结果 |
| --- | --- | --- |
| 工作流 `/workflows` | 查看“产品需求交付”详情，复制后编辑名称、节点和连线 JSON，添加角色节点，校验并保存，再刷新 | 只读图显示节点类型与依赖，保存内容可读回，副本修改与原流程独立。输入损坏 JSON、环或无效角色时显示校验原因 |
| 角色 `/roles` | 创建角色，编辑系统提示词、模型、文本 Skill 和 MCP，保存并刷新；复制后修改副本，再删除副本 | 配置读回一致，副本拥有独立内容。删除被流程引用的“产品分析师”显示冲突。未保存时离开页面出现确认，取消后草稿保留 |
| 模型连接 `/connections` | 新建连接，填写 HTTP(S) 地址、模型与演示凭据引用，保存、编辑、刷新，点击“模拟验证”，再删除 | 配置修改持久保留，模拟验证显示结果。删除被角色引用的“团队研发模型”显示冲突，列表记录保留 |
| 运行 `/runs` | 进入“客户反馈看板 · 需求确认”，查看节点、日志、任务输入和配置快照，执行下方审批返工步骤 | 轮询显示节点变化，审批操作依据 API 响应更新，事件保留且重复读取不重复展示。终态停止自动轮询 |
| 产物 `/artifacts` | 搜索“代码审查报告.md”，切换“内容预览”和“源文件”，下载并打开文件，按运行和执行轮次筛选 | Markdown 标题和表格可读，源文件保留原文本，下载文件名及内容与所选条目一致，运行链接进入所属运行 |
| 沙箱 `/sandboxes` | 搜索“交付工作区 01”，打开“详情与日志”，尝试释放，再进入关联运行取消任务并返回 | 详情显示标识、模拟资源规格及日志，活动运行拒绝释放；取消确认后沙箱显示已释放并保留日志。页面只有模拟状态、日志与释放操作，没有真实终端或远程连接 |
| 对话 `/chat` | 新建会话，发送“现在有哪些工作流和运行？”，等待流式回复，展开推理与工具块，刷新后重新进入 | 消息分段出现，回复为 Markdown；工具调用显示状态，刷新后会话与消息仍保留。演示回复为本地模板，未调用模型 |

连接验证仅产生模拟响应。角色 Skill 为名称与文本内容，MCP 命令和工作流脚本保存为定义，演示时不会实际执行。

### 审批返工、快照与历史产物

1. 重置演示，进入 `/runs/run-1`，确认“等待人工审批”。查看配置快照中的“产品分析师”提示词。
2. 进入角色管理，修改并保存“产品分析师”的提示词。返回旧运行，配置快照仍显示原提示词。
3. 点击“打回返工”，选择“梳理需求”并确认。摘要变为第 2 次执行，目标及其下游重新推进，历史事件仍可查询。
4. 再次到达审批后点击“通过审批”，等待全部节点完成。交付产物中仍能看到第 1 次和第 2 次执行的文件。
5. 点击“查看全部产物”，按执行轮次筛选，分别查看和下载旧、新产物。进入关联沙箱，确认状态已释放，产物仍可读取。
6. 从“产品需求交付”新建运行，填写任务输入。新运行快照显示更新后的角色配置，旧运行快照保持原样。

运行详情使用串行 GET 轮询，每轮请求完成后等待 1500ms。模拟后端在读取运行列表或详情时按时钟推进，agent 和 script 节点约两秒完成一个，按拓扑依赖顺序执行。审批暂停推进，长间隔读取可补推进多个节点，因此界面更新间隔还包含请求延迟。

### 通用交互与故障恢复

- 切换明暗主题与黑白主色调并刷新，各自保持；黑白下背景、文本、强调与状态色为不同灰度的灰阶，切回彩色恢复原配色。在移动宽度打开抽屉导航，七域入口可用。
- 使用键盘 Tab 进入“跳到主要内容”，检查弹窗焦点、Esc 关闭和标签页方向键操作。
- 搜索无匹配内容时显示空状态。开启一次性故障后刷新，页面显示错误，重试恢复数据。
- 在运行详情提高延迟并切换到另一运行，页面应显示新运行内容。离开详情后停止该页轮询。
- 直接访问 `/runs/run-1` 并刷新仍可进入详情，未知地址显示 404 与返回工作流入口。

## 自动化验证

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` 执行 ESLint、Vitest、tsc 类型检查和默认 Vite 构建。ESLint 检查模块依赖方向，单元与组件测试覆盖模拟接口、状态推进、表单、轮询、对话流及 Markdown 净化等行为。

Playwright 构建并启动 `0.0.0.0:4173` 预览服务，验收桌面与移动导航、主题、深链刷新、404、键盘访问、加载失败恢复，以及两种尺寸下的配置、嵌套确认框、审批返工、历史产物、下载和沙箱操作。运行前保持 4173 端口空闲，测试结束后自动关闭服务。

```bash
npm test -- src/mocks
npm test -- src/modules/roles
npm run test:e2e -- --project=desktop
```

这些测试使用模拟 API 或接口替身。真实服务的协议、认证、事务、SSE 与执行结果按下方联合边界验收。

## 构建与真实服务接入

```bash
# 默认构建包含演示 API
npm run build
npm run preview

# 真实服务模式开发与构建
npm run dev:live
npm run build:live
```

`dev:live` 使用 Vite live 模式，`build:live` 使用 `vite build --mode live` 并生成不包含模拟 API 的静态产物。构建均输出到 `web/dist`。默认构建用于演示，部署真实服务时使用 `build:live`。本地预览监听 `0.0.0.0:4173`。

live 模式通过同源 `/api` 请求网络，失败时显示请求错误，不回退 mock。真实 server 的路由、DTO、错误码和认证协议尚需联调，切换模式只切换传输方式。开发环境可用 `URSI_API_PROXY` 代理；生产静态服务必须将同源 `/api` 接入真实后端，Vite preview 不提供 API 代理。

生产部署在站点根路径 `/`。页面深链需要 history 回退到 `index.html`，`/api`、`/api/*` 与缺失脚本、样式等静态资源应保留各自错误响应。联合验收分别覆盖：

- **真实 server API**：路由与 DTO 对齐、认证、引用约束、快照、审批冲突、持久化、产物归属和生产路由隔离。
- **真实执行链路**：Gateway、Channel、Agent Runtime 与 CLI 的资源准备、凭据解析、模型及脚本执行、产物回收和释放核实。沙箱终端与远程连接需完成相应接入及验收。
