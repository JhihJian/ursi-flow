# 02 定义发布：把一套工作方法交给别人复用

**用户结果：** 工作包维护人能在浏览器中组合提示词或 Skill、执行器、SOP 和验收标准，发布可派工的确定版本。查看旧版时知道当时绑定的是哪一版工具。

**接手材料：** [定义目录契约](../../../server/src/work/catalog/SPEC.md)、[界面设计](../../DESIGN-v2.md)。`web/src/modules/definitions/` 已有三类目录、详情和编辑器草稿。服务端返回的包快照是展开后的动作绑定，不等于原始编辑稿。历史上局部操作曾通过验证，接手后应以自己的基线复验。

**边界与接口：** 负责上述模块、规格与测试。对外提供 `/packages`、`/resources`、`/executors` 及指定修订深链。发起工作的链接只传所查看的包 ID 和修订给 `/items/new`，不负责实际派单。凭据、环境地址和执行命令由部署者管理。

**验收与证据**

1. 仅用页面表单发布提示词 r1、引用它的 Agent r1，再发布包含具名动作、输入、必交文件、SOP 和验收标准的包 r1。详情可追到准确的资源和执行器修订。从旧版本点击派工，链接仍携带 r1。
2. 更新提示词和包，r1 的内容仍可读。编辑历史包时不能因缺少原始动作级声明而静默改写输入输出或删除资源依赖；对无法还原的部分明确要求维护人复核。停用提示说明对新派工的影响。
3. 在缺少可用执行器的环境，先填写包 ID、SOP 和动作，再去补建依赖，回到编辑器时能继续填写原草稿。验证失败时保留用户输入。
4. 本地 Agent、预配沙箱 Agent、固定修订 Flow 三者的配置边界和提示准确。MCP 仅可登记命名引用，页面不承诺运行时注入。交付一次发布记录、一条历史版本深链和草稿往返测试；可使用现有目录 API 独立验收。
