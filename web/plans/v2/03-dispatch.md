# 03 内置派工：从一个包版本可靠地开一张单

**用户结果：** 经办人从清单或一个包的指定版本进入发起表单，核对方法和验收标准、填写本次材料，创建待办理工作项。网络不稳定时仍能找回同一张单。

**接手材料：** [工作项 HTTP 契约](../../../server/src/work/items/HTTP.md)、[界面设计](../../DESIGN-v2.md)。负责 `web/src/modules/work-list/`、模块规格和测试。暂停时 `StartWork.tsx` 的创建按钮引用了提交函数但未调用；该页和清单尚有 lint 问题。先验证真实按钮点击，不以类型检查判定可派工。

**接口与边界：** 从 `/items/new?package=…&revision=…` 读取确定版本；提交 `requestId`、包、修订和输入。使用服务端返回的工作项 ID 进入 `/items/:id`，办理、执行与交付由详情页负责。可预置一个包独立验收，无需定义编辑器或来源模块。

**验收与证据**

1. 在同时有 r1 和 r2 的目录从 r1 深链派工。表单和新单均使用 r1 的标准；字符串、数字、整数、布尔值、对象和数组按声明提交，错型在页面可纠正，`false` 或 `0` 不被当作缺失。
2. 模拟服务已建单但响应丢失：同一参数重试复用 `requestId`，查后台只有一张单；修改材料后作为新派工。连续点击不能额外建单。成功后状态为 `pending`、无尝试记录。
3. 按待验收等状态筛选列表，从某一行进入详情再返回，保留筛选。加载失败有重试，不显示为空清单；无可派工版本可进入工作包目录。移动端可读到包版本、单号、状态。
4. 交回点击级测试、捕获的无凭据请求摘要及同单 ID 对照，确认清单和发起页的 lint 问题在模块内解决。
