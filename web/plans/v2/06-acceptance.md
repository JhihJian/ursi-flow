# 06 联合验收：证明用户在浏览器里办完工作

**交付判断：** 使用真实 Web、真实 Server 和真实 Pi CLI。除登录及部署准备外，定义发布、派工、执行、交付和验收均由浏览器完成。模型可使用本机固定回复端点；报告中明确标注模拟的是模型，不是执行器、工作数据或验收接口。

**准备与边界：** 依据[页面设计](../../DESIGN-v2.md)与[服务端已有验收环境](../../../server/tests/WORK-ACCEPTANCE.md)。此包可先准备测试材料、凭据隔离、独立端口、临时数据目录和清理步骤。只负责独立联合验收资产（建议 `web/acceptance/`）、复跑说明及验收后的顶层 Web 文档。原有 mock 浏览器回归归 01。页面缺陷交回模块负责人，不在验收脚本里绕过。当前没有整条真实浏览器链路通过的结论。

**主场景，可在 01、02、03、05 集成后签收**

1. 关闭 Flow 和来源。浏览器发布资源、引用该资源的本地 Agent 执行器、绑定该执行器的工作包 r1；声明输入编号和必交 `report.txt`。
2. 使用 r1 派 A、B 两单，填写不同编号。发布更改 SOP 和验收标准的 r2；旧单仍显示 r1，不串材料。两单各执行一次，能查到输出，业务状态仍为办理中。
3. A 提交并通过 v1。B 提交 v1，附理由退回，修订后在原单提交 v2 并通过。刷新和深链打开 A v1、B v1、B v2，核对文件、原退回意见、通过版本和清单状态。
4. 桌面完成全程，移动视口至少独立完成从抽屉进清单、打开待审报告、退回、重读旧版。保留能区分单号、尝试 ID、交付版本的证据，去除令牌与私有材料。

**可选能力与发布记录：** 04 就绪后另启配置了 JSON 来源的实例，证明来源列表派工能进同一清单且只允许固定动作。真实沙箱不是主场景依赖，未验证的外部服务单独列出。复跑全站 lint、单测、类型检查、构建及旧 Flow/对话桌面移动测试，分别记录结果；接口拦截版回归不得冒充真实服务验收。

提交简短签收报告：版本、环境、复跑命令、每步观察结果、失败与未测项。只有主场景和基础回归通过、跨端待决风险有明确处理结论，才标记核心工作台可交付。单个扩展的验证状态另列。
