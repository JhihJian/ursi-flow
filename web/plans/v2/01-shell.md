# 01 工作台入口：登录即能继续办事

**用户结果：** 经办人从首页进入工作清单；验收人从一版交付的链接登录后仍看到那一版。部署是否启用 Flow 和来源只影响对应入口。

**接手材料：** [界面设计](../../DESIGN-v2.md)、[应用装配规格](../../src/app/SPEC.md)、[共享层规格](../../src/shared/SPEC.md)。当前有导航、共享客户端与代理草稿，尚无整站回归结论。负责 `web/src/app/`、`web/src/shared/http/`、相关规格、`web/vite.config.ts` 与原有 `web/e2e/` 回归。页面内容由业务包负责。

**对其他包的承诺：** 提供同源带鉴权的 `requestV2` 和 `requestV2Text`，保留 v1 客户端。接入 `workListRoutes`、`sourceRoutes`、`definitionRoutes` 和 `WorkDetail`；允许业务模块独立挂测试路由。未知地址回到清单，桌面侧栏和移动抽屉提供相同入口。

**验收与证据**

1. 无令牌打开指定交付版本，登录后路径和查询串不变；退出后页面不再展示服务端数据。旧请求的 401 不会注销新会话。本地对话仍是匿名演示。
2. Flow 和来源分别返回 404、空数组、503 时，仅集合 404 收起对应入口；空集合保留入口，503 可重试且不阻塞清单。验证移动抽屉和旧 `/flows`、`/runs/:id`、`/flow-config` 深链。
3. 开发代理对两版 API 均可用。报告文件读取成功必须是契约规定的纯文本。模拟 `200 text/html` 及 `204`，客户端报告读取失败，供 05 阻止验收；不把代理首页当报告。
4. 提交客户端与路由测试、旧 Flow 和对话的桌面/移动浏览器回归结果。独立验收可用路由占位，明确记录哪些请求使用了替身。
