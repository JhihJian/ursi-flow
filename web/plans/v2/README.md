# Web v2 研发交接与派工索引

**交付目标：** 经办人在浏览器发布可复用的工作包，按同一版本办理两张单；验收人能分别通过和退回，刷新后仍能区分两单的材料、历次交付和意见。以浏览器连接真实 Server 的业务证据作为产品交付标准。

01 至 05 可同时发放。每包负责人维护自己模块的规格和测试。共用客户端、路由装配和旧浏览器回归归 01；业务模块提供路由或页面导出，不分别修改总路由。06 记录跨包问题并交还对应负责人。跨端协议变更先取得服务端负责人的决定。研发人员、工期和合并次序由项目负责人安排。

## 交接约定

- 页面入口：`/items` 是首页，`/items/new?package=…&revision=…` 接受指定包版本，`/items/:id` 是办理单，`/items/:id/deliveries/:version` 是指定交付版本。`status` 查询参数用于返回清单时还原筛选。目录入口为 `/packages`、`/resources`、`/executors`；来源入口为 `/sources`。
- 工作管理使用同源 `/api/v2`；Flow 工具保留 `/api/v1`。共享客户端提供 JSON 和交付纯文本读取。各包可以用独立测试路由、固定响应或预置单据做模块验收，联合验收必须标明真实组件与替身。
- 每包交回：对应的变更版本、复跑步骤、关键正反例结果、仍需裁决的问题。发现冲突时以冻结的包快照和服务端实际状态为准，不让前端推断成功。
- 首版之外：运行中注入 MCP、沙箱供应、PTY、浏览器远控、通用文件管理和真实第三方平台在线同步。
