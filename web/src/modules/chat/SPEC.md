# 对话前端模块

## 功能意图

为使用者提供就当前工作流与运行记录提问的对话入口：左侧管理会话，右侧阅读消息并继续输入。演示环境的回复由本地模板按当前演示数据生成，界面必须让人清楚看到这是本地演示，不是模型输出。

## 关键功能与验收

### 会话列表与地址

`/chat` 显示未选中会话的空态，`/chat/:sessionId` 显示指定会话。会话列表按更新时间排序，支持搜索、新建、删除与当前项高亮；路由参数是当前会话的唯一来源，直接访问会话地址可加载同一会话。

#### 验收

- 通过导航进入对话页，未选中会话时显示 `开始一段新对话` 与新建入口；新建后地址变为 `/chat/:sessionId` 并显示该会话。
- 搜索按标题与最近消息过滤；无会话与无匹配有不同提示；删除需确认，取消不改变列表，确认后移除会话并回到 `/chat`。
- 列表与消息区使用 `.page-stack-fill` 与 `.panel` 布局，桌面面板填满内容区，会话列表与消息区各自内部滚动；窄屏保持 `min-h` 并由文档滚动，会话列表折叠在对话上方，页面没有横向溢出。
- 读取会话失败显示可重试错误，且不影响已选中的本地消息内容。
- 会话列表加载中显示加载态，加载失败显示可重试错误态，不显示“还没有会话”空态。

### 消息流与流式回复

发送消息调用 `POST /chat/sessions/:id/messages`，响应为 `application/x-ndjson`，逐行给出 `delta`、`tool`、`done` 或 `error`。客户端用 `getApiTransport()` 读取响应流，按行解析并把分段合并到助手消息，`done` 行返回完整消息后替换本地占位消息。

#### 验收

- 发送后立即出现用户消息与助手占位消息，分段到达时逐段追加正文，工具状态按 `tool` 行更新为进行中或已完成。
- 流式期间显示 `停止`，点击后中止读取并保留已收到的片段，不显示错误；结束后按钮恢复为 `发送`。离开页面同样中止在途读取。
- 停止后立即再发送时，旧流的收尾不得把新流的流式状态改回未流式。
- 服务端在演示延迟后分 6–12 段推送，段间有真实延时，中止读取会停止后续分段。
- 失败时以 `role="alert"` 显示可读错误并提供重试入口：错误码经 shared 的白名单映射为固定文案，未知码使用通用提示，服务端原文不直接展示，空占位消息不保留。
- 重新生成复用同一消息接口并附加 `regenerate` 标记，服务端替换末尾助手消息，不重复追加用户消息。

### 消息呈现与输入

用户消息右对齐气泡（`bg-elevated`），助手消息铺满宽度并用 `MarkdownContent` 渲染 Markdown；`reasoning` 与 `tool` 部分为可折叠块，标题为 `推理过程` 与 `工具调用`。

#### 验收

- 助手回复中的 Markdown 标题、列表、引用与强调按样式渲染，用户输入保留换行。
- 推理与工具块默认折叠，展开后显示原文、工具名称、状态与输出。
- 输入框 `aria-label="输入消息"`，Enter 发送、Shift+Enter 换行，输入为空时 `发送` 禁用；未选择会话时输入禁用。
- 新消息或新分段到达后消息区滚动到底部，长文本换行且不产生横向溢出。

### 演示回复与数据引用

回复由 `src/mocks/chat.ts` 的本地模板生成，读取当前演示工作区的工作流与运行记录，并在正文中注明这是本地演示回复、未调用模型。消息接口同步把用户消息与助手消息写入会话，由 mock 后端整树提交保存，会话标题取首条用户消息前 24 字。

#### 验收

- 新会话的第 1 条用户消息决定标题（最多 24 字）；回复正文引用当前工作流数量、运行记录数量与状态，并明确说明未调用模型。
- 刷新页面后会话、消息与标题保持不变；中止或失败后已提交的消息仍可在刷新后读到。
- 让下一次请求失败的演示设置对消息接口同样生效，返回统一的服务不可用错误，演示控制接口不消费该故障。
- 演示环境不使用任何模型选择器或不生效的控件，界面不宣称具备真实模型对话能力。

## 模块职责与验收边界

本域拥有路由、会话状态 store（`sessions`、`currentId`、`streaming`、`error`）、流式读取、消息呈现与输入交互。DTO、HTTP 错误映射与传输注入由 shared 提供，会话数据与流式响应由 mocks 提供，两者通过 `/chat/**` 契约连接。

前端独立验收使用演示 API 与组件测试，覆盖会话列表、发送与流式渲染、停止、删除、刷新持久化与响应式布局。真实模型推理、上下文窗口、计费与流式重放不在本域验收范围内。

真实联合验收需要接入实际的对话服务，核对鉴权、错误码、流式协议一致性、取消语义与多轮上下文行为；在此之前 live 模式只切换请求传输，不宣称具备模型能力。
