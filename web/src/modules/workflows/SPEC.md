# 工作流前端模块

## 功能意图

为流程维护者提供定义管理、依赖查看和运行发起入口。
流程定义与引用校验以 server/workflows 的服务结果为准，运行创建由运行域处理。
模块入口与业务用例分别验收，业务结果以服务端返回为准。

## 关键功能与验收

### 初始化入口

通过 `/workflows` 提供工作流页面，介绍流程定义、依赖查看和发起运行三项能力。

#### 验收

- 路由名为 `workflows`，懒加载页面，标题为“工作流”，描述说明用户用途。
- 页面复用共享占位组件，展示三项能力及“功能准备中”，无模拟业务记录、成功状态或未接通的操作按钮。

### 流程定义与依赖查看（业务接入要求）

通过表单或定义文本创建、编辑和删除定义，以只读 DAG 展示节点类型、边及角色引用。

#### 验收

- 连接真实服务后，保存合法定义并重新打开详情，节点、边和配置与提交值一致。
- 非法图、缺失角色或删除失败展示可定位的服务端错误，保留用户可修正的输入。
- 只读图可区分 agent、script、approval 节点，并与保存的依赖边一致。

### 发起运行（业务接入要求）

从合法定义请求创建运行，由 app 装配进入运行详情的跨域导航。

#### 验收

- 创建成功后依据服务返回的运行标识进入对应详情，运行列表可查询该记录。
- 创建失败展示原因并保留流程上下文，旧运行的定义快照保持不变。

## 模块职责与验收边界

- 本域路由、页面、API 适配、类型与状态归本目录，按功能需要添加文件。
- 前端代码仅依赖 shared 公共能力，跨域导航由 app 装配。
- server/workflows 规格约束服务契约，浏览器经共享 HTTP 层访问服务。
- 独立验收覆盖路由、用途说明、三项能力与准备中状态，仅证明初始化入口可用。
- 业务独立验收可使用接口替身检查输入、错误呈现和响应映射。
- 联合验收连接真实 workflows、roles、runs 与存储，验证引用校验、运行创建和快照隔离。
- 初始化验收与业务验收分别记录，业务完成需取得真实服务联合验收证据。
