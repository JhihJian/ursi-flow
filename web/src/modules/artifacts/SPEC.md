# 产物管理前端模块

## 功能意图

为交付物查阅者提供产物检索、内容查看和执行历史追溯入口。
产物内容与归属以 server/artifacts 为准，当前有效输出由运行域确定。
模块入口与业务用例分别验收，业务结果以服务端返回为准。

## 关键功能与验收

### 初始化入口

通过 `/artifacts` 提供产物管理页面，介绍归属检索、内容查看和历史追溯三项能力。

#### 验收

- 路由名为 `artifacts`，懒加载页面，标题为“产物管理”，描述说明用户用途。
- 页面复用共享占位组件，展示三项能力及“功能准备中”，无模拟业务记录、成功状态或未接通的操作按钮。

### 归属检索与内容查看（业务接入要求）

按 run、node、generation 和 attempt 检索产物，通过稳定标识读取内容与元数据。
generation 表示持有代数，attempt 表示节点累计执行编号，返工后继续递增。

#### 验收

- 同名文件分属不同运行、节点或执行轮次时，筛选结果仅展示匹配归属。
- 内容查看可定位稳定标识、类型、大小与校验信息，重新访问旧标识得到旧内容。
- 缺失、损坏或访问失败显示明确错误，文件访问使用服务授权的内容入口。

### 历史与当前输出（业务接入要求）

保留重试、返工后的历史产物，并依据运行域返回的身份区分当前有效输出。

#### 验收

- 同一 generation 内返工产生递增 attempt，页面分别展示旧轮次与新轮次的产物。
- 旧 generation 或 attempt 的迟到产物保持历史归属，当前输出与运行服务一致。
- 沙箱释放后已回收产物仍可读取，服务返回的契约失败可定位缺失或不匹配项。

## 模块职责与验收边界

- 本域路由、页面、API 适配、类型与状态归本目录，按功能需要添加文件。
- 前端代码仅依赖 shared 公共能力，跨域导航由 app 装配。
- server/artifacts 规格约束服务契约，浏览器经共享 HTTP 层访问服务。
- 独立验收覆盖路由、用途说明、三项能力与准备中状态，仅证明初始化入口可用。
- 业务独立验收可用接口替身检查归属筛选、内容错误和当前输出标识展示。
- 联合验收连接真实 artifacts、runs、sandboxes 与存储，覆盖回收、释放后读取和返工轮次隔离。
- 初始化验收与业务验收分别记录，业务完成需取得真实服务联合验收证据。
