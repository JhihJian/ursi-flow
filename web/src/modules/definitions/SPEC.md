# 工作定义

## 功能意图

维护资源、执行器和工作包，按固定版本核对依赖、发布新版或发起工作。

## 关键功能与验收

### 目录、历史和跳转

#### 验收

- `/packages`、`/resources`、`/executors` 列出最新版本及对象启停状态。资源可按 Skill、提示词和 MCP 引用筛选。读取失败提供重试，成功但无结果显示空态。
- `/:id` 读取最新详情，`/:id/revisions` 展示历史，`/:id/revisions/:revision` 直接打开冻结正文。查看旧版本时仍显示整个 ID 的当前状态。
- 工作包展示目标、SOP、输入输出、交付文件、验收标准，以及每个动作绑定的执行器与资源版本。执行器展示环境或 Flow ID、固定目录修订；引用链接指向具体版本，Flow 链接打开 Flow 编辑器。
- 「发起工作」携带正在阅读的包 ID 与修订号，跳至 `/items/new?package=…&revision=…`。确认停用前告知对新派工和新引用的影响；停用后仍可打开历史版本。

### 表单发布

#### 验收

- 从各目录的 `/new` 可依次发布文本资源、引用它的 Agent 执行器以及固定该执行器版本的工作包，普通流程通过有标签的输入框、选择器和可增删的字段行完成。小屏表单按单列排列。
- MCP 资源只填写服务与凭据引用，不能选为可执行依赖。Agent 支持本地或预配沙箱；Flow 填写 Flow ID 和字符串目录修订，不发送环境或资源。
- 包支持包级资源和输入输出、多个动作、动作级资源、继承或覆盖包声明。交付物按行录入文件名；重复动作名、重复声明字段名不能覆盖先前的输入。
- 指定版本的 `/edit` 基于该版生成草稿。包快照中展开的资源和执行器转为固定引用；包资源与固定执行器已提供的资源默认作为继承项，剩余资源归入对应动作。结构化目标按原 JSON 类型保存。
- 旧包快照无法区分重复资源的原始归属，也不包含原动作级输入输出声明。草稿说明此限制，允许逐动作重设；须勾选「我已核对动作资源和输入输出声明」才能发布。读取固定依赖失败时可重试，不用最新版替代。
- 发布失败显示服务错误并保留草稿，成功后打开响应给出的新版本。停用的 ID 不提供发布入口。
