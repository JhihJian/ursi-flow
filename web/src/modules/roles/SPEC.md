# 角色管理前端模块

## 功能意图

为角色维护者提供提示词、执行器、模型选择、Skills 文件包与 MCP 配置管理入口。
角色定义、连接引用检查和复制语义以 server/roles 的服务结果为准。
模块入口与业务用例分别验收，业务结果以服务端返回为准。

## 关键功能与验收

### 初始化入口

通过 `/roles` 提供角色管理页面，介绍角色配置、Skills 与 MCP、引用与快照三项能力。

#### 验收

- 路由名为 `roles`，懒加载页面，标题为“角色管理”，描述说明用户用途。
- 页面复用共享占位组件，展示三项能力及“功能准备中”，无模拟业务记录、成功状态或未接通的操作按钮。

### 角色定义与能力配置（业务接入要求）

管理角色创建、编辑、复制和删除，维护提示词、执行器、模型选择及完整技能文件包。
结构化 MCP 配置区分 stdio 命令参数与 HTTP 连接参数，敏感字段使用凭据引用。

#### 验收

- 保存并重新打开角色后，提示词、模型选择、技能入口及嵌套文件、MCP 条目完整一致。
- 复制后修改副本保持原角色内容稳定，文件包校验失败展示具体路径或字段原因。
- 非法文件路径、缺失入口或明文敏感参数被服务拒绝时，页面展示脱敏错误。

### 引用约束与快照隔离（业务接入要求）

使用服务返回的连接能力判断和引用冲突，区分当前角色定义与运行冻结配置。

#### 验收

- 缺失或能力不匹配的连接阻止保存，引用中的角色删除显示服务端冲突原因。
- 角色修改后，旧运行仍展示原提示词、Skills、MCP 与模型配置，新运行使用更新配置。
- 列表、详情、错误提示及页面状态中的服务 DTO 均保持凭据明文隔离。

## 模块职责与验收边界

- 本域路由、页面、API 适配、类型与状态归本目录，按功能需要添加文件。
- 前端代码仅依赖 shared 公共能力，跨域导航由 app 装配。
- server/roles 规格约束服务契约，浏览器经共享 HTTP 层访问服务。
- 独立验收覆盖路由、用途说明、三项能力与准备中状态，仅证明初始化入口可用。
- 业务独立验收可用接口替身检查文件包提交、字段错误及复制后的页面状态。
- 联合验收连接真实 roles、connections、workflows、runs 与存储，验证引用约束及快照隔离。
- 初始化验收与业务验收分别记录，业务完成需取得真实服务联合验收证据。
