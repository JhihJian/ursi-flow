# 运行记录前端模块

## 功能意图

为运行操作者提供任务目录、节点进度、事件日志、冻结配置、产物与人工审批入口。运行状态、执行轮次和审批结果依据 API 响应展示，页面不推演服务端状态机。

实现由 `RunsView.tsx`（目录）、`RunDetailView.tsx`（详情）、`RunSnapshot.tsx`（冻结配置）、`useRunDetail.ts`（读取与轮询 hook）与 `runState.ts`（状态判定、时间格式、事件合并、返工目标计算）组成；`routes.tsx` 声明 `/runs` 与 `/runs/:id` 两条懒加载路由。

## 关键功能与验收

### 运行列表与详情路由

`/runs` 提供紧凑目录，`/runs/:id` 动态懒加载详情。仅列表路由在 route handle 设置 `nav: true`，详情不进入主导航。

#### 验收

- `GET /runs` 返回的运行展示名称、所属流程、状态、节点进度、执行轮次与更新时间，按更新时间倒序。
- 支持名称、流程名、标识搜索及状态、工作流过滤，状态与工作流筛选初值取自地址查询 `status`、`workflowId`。空列表、无匹配、加载和请求失败可区分，失败可重试。
- 点击名称进入对应详情，直接访问详情地址可加载同一运行。桌面采用左内容右摘要，窄屏上下堆叠。

### 串行轮询、节点与事件

`useRunDetail` 通过 `GET /runs/:id` 读取完整状态，每轮请求结束后用 timeout 等待 1500ms 再读。运行事件以 API 事件 ID 去重，首次收到时分配稳定展示序号。

#### 验收

- queued、running、waiting 状态持续刷新。慢请求不重叠，succeeded、failed、cancelled 终态停止自动轮询，仍可手动刷新。
- 路由标识变化或组件卸载清理 timeout 并取消在途 AbortController，旧响应不能覆盖新运行；详情视图按标识重建，旧运行的选中节点与弹窗状态不残留。
- 请求失败保留上次成功数据和可重试错误。节点步骤显示当前状态、角色、最近事件时间，选中后查看当前输出并过滤日志。
- 事件可按节点及 state、log、tool 类型筛选，返工后保留历史事件，重复响应不重复展示或改变已有序号。
- 展示序号仅用于前端阅读，当前完整响应轮询不宣称具有服务端持久游标或 SSE 补读能力。

### 冻结配置与关联资源

任务输入和配置快照按详情响应展示。产物从 `GET /artifacts?runId=...` 读取，保留执行轮次信息。

#### 验收

- 角色名称、模型、执行器、提示词、Skills、MCP、模型连接与流程定义均从 `snapshot` 读取，当前配置编辑不影响历史展示。
- 产物列表显示名称、节点、轮次、大小与生成时间，产物请求失败独立显示并可重试，不覆盖运行状态。产物在运行 `updatedAt` 变化或强制刷新时重读。
- 产物导航携带 `/artifacts?runId=...`，具体条目追加产物 id，沙箱导航携带 `/sandboxes?id=...`。
- 返工后产物区仍能访问历史轮次。读取失败不能将历史产物错误解释为已删除。

### 审批、返工与取消

仅 waiting 且包含 waiting_approval 节点时提供审批。打回目标限定为已完成的传递祖先节点，API 负责最终合法性判断。

#### 验收

- 通过审批请求 `POST /runs/:id/approve`，打回确认弹窗提交 `POST /runs/:id/reject` 与 `{ targetNodeId }`。
- 返工选项排除审批自身、无关支路、后继及未成功祖先，提交前再次检查当前候选集合。历史事件与产物仍保留，当前轮次按响应更新。
- 非终态运行可确认取消，请求 `POST /runs/:id/cancel`。仅依据服务响应显示取消结果。
- 写操作等待在途读取结束，提交期间暂停轮询并禁用重复操作。403 权限错误、409 冲突及其他失败显示错误并重新读取最新状态。
- 请求失败不报告成功，审批弹窗保留选择与错误，成功后关闭。

## 模块职责与验收边界

- 本域拥有列表、详情、轮询生命周期、审批交互和展示事件合并。DTO、HTTP、通用控件与反馈由 shared 提供，跨域资源通过地址关联。
- 单元与组件测试覆盖事件去重与返工目标（`runState.test.ts`）、串行轮询与动作串行（`useRunDetail.test.ts`）、审批与取消交互（`RunDetailView.test.tsx`），组件测试使用 `createMemoryRouter` 提供 data router。
- Mock 独立验收可使用每两秒推进节点的演示 API，覆盖等待审批、通过完成、打回增加 attempt、取消、事件保留、产物历史、403/409 和轮询清理。
- Mock 的工具日志、输出、产物及沙箱状态用于检验前端闭环，不提供真实 CLI、脚本、模型或容器执行证据。
- 真实联合验收连接 runs、配置域、artifacts、sandboxes、transport 与存储，验证冻结配置、审批状态冲突、返工轮次及历史产物归属。
- 服务端持久事件游标、SSE 重放、迟到执行隔离、Gateway 资源释放和真实 CLI 执行分别由实际服务与执行链路联合验收，完整快照轮询验收不覆盖这些机制。
