# SSH 终端

## 功能意图

ssh-web 为内网主机提供独立的浏览器 SSH 终端。用户维护一份 SSH 连接配置（主机、端口、用户名、密码或密钥），点击连接即由服务端用 russh 建立会话，前端用 xterm.js 通过 WebSocket 操控远端 PTY。服务与页面由同一个 Rust 进程托管，数据保存在本机 SQLite，不依赖 ursi-flow 的其他模块。界面为todo-web 的出版物风格。

## 关键功能与验收

### 连接配置管理

#### 验收

- 左侧列表按名称（不区分大小写）排序列出所有连接，每项显示名称与 `username@host:port`。点击列表空白外的连接项即发起会话。
- 列表空白处或连接项右键打开菜单：空白处为 `New connection`，连接项为 `New connection`、`Edit`、`Delete`。侧栏标题行右侧另有 `+` 按钮直接新建。
- 连接字段在底部编辑面板维护：名称（唯一）、主机、端口（默认 22）、用户名、认证方式（password / key）与对应凭证（密码；或 ssh-web 所在机器上的私钥绝对路径与口令，密钥口令无则留空）。保存时校验必填项与端口范围，名称重复返回明确错误。
- 删除连接需输入连接名称二次确认，名称不匹配时不执行并提示。
- 密码与密钥口令只写不读：任何 API 响应都不回传密码与密钥口令。编辑连接时密码留空表示保持原密码，密钥路径与口令留空表示清空。内网个人工具场景下凭证按明文存于本机 SQLite（`~/.ursi/ssh/ssh.db`），不做加密，这是有意接受的边界。

### 终端会话

#### 验收

- 点击连接后服务端同步建立 SSH：TCP 连接超时 10 秒，认证失败、主机不可达等失败原因直接作为错误显示在界面上，不产生会话。成功后右侧终端区建立 WebSocket 并展示远端 shell。
- 终端为 xterm.js 面板，PTY 类型 `xterm-256color`，初始尺寸取自面板实际大小（避免 80×24 闪排）。窗口缩放时通过 ResizeObserver 自适应并同步远端，列行上限 500。终端面板提供暗色（默认）与亮色（白底）两套主题，在终端区右键菜单切换，选择跨刷新保留。
- 键盘输入即时送达远端；输出按原始字节流渲染，粘贴长文本自动分片发送。终端历史保留 5000 行，可滚动回看。终端区右键菜单提供 `New connection`、`Reconnect`（关闭当前会话并重连当前连接，终端回到新 shell）与亮暗色切换。
- 服务端推送的事件以消息形式内联显示在终端尾部：错误为红色，远端退出（含退出码）为黄色。
- 会话不持久化：WS 断开或退出 shell 后会话即销毁，远端进程随通道关闭而结束；页面刷新或重开需要重新连接。多标签、自动重连不在范围内。
- 服务器主机密钥不做校验（`check_server_key` 恒通过），这是内网工具的明确边界。
- 服务端不保留 SSH 会话于 WS 之外，同一时间一个会话只接一个终端。

### 服务与接口

#### 验收

- 服务默认监听 `0.0.0.0:8091`（`PORT` 可覆盖），托管静态页面与同源 API；数据库路径可用 `URSI_DATA_DIR`（默认 `~/.ursi`）与 `SSH_DB_PATH` 覆盖。接口契约见 [server/HTTP.md](server/HTTP.md)。
- `GET /api/health` 返回 `ok`。连接、会话的增删查与连接建立全部走同源 `/api` 前缀，错误统一为 `{error, code}` JSON。
