# SSH 终端

## 功能意图

ssh-web 为内网主机提供独立的浏览器 SSH 终端，也是 ursi-flow 工作区的一栏模块。用户以「名称 + 一条 ssh 命令」维护连接配置，点击连接即由服务端启动系统 OpenSSH 子进程（`ssh -tt`）建立会话，前端用 xterm.js 通过 WebSocket 操控远端 PTY。认证（密码、口令、agent）、跳板、`~/.ssh/config` 别名等全部交给 OpenSSH 自身处理，交互提示直接出现在终端里。远端有 tmux 时会话接入 `tmux new -A -s <会话名>`：浏览器断开后远端会话保活，重新连接自动恢复屏幕；无 tmux 时回退普通 shell 并提示。服务与页面由同一个 Rust 进程托管，数据保存在本机 SQLite，不依赖 ursi-flow 的其他模块。界面为 todo-web 的出版物风格；独立入口与工作区嵌入共用同一套组件，样式作用域在模块容器内，API 前缀由入口注入。

## 关键功能与验收

### 连接配置管理

#### 验收

- 左侧为树状连接面板（固定 200px）：连接为父行，点击即选中并展开该连接的 tmux 会话子级（含默认入口 main、客户端数标记 ●、创建时间）；右键连接行为 `New connection`、`New session`、`Edit`、`Delete`，空白处为 `New connection`，标题行另有 `+`（新建）与 ↻（刷新会话列表）。点会话子行不在侧栏内切换，而是在终端区顶部标签栏打开/激活对应标签。
- 打开的会话以顶部标签栏呈现（orca 风格标签条）：每个标签显示会话名 · 连接名，点标签激活、点 × 或中键关闭，标签栏尾部 `+` 新建会话；同一 (连接, tmux 会话) 只允许一个标签。多个标签常驻堆叠渲染，仅激活的可见，切标签不重建、不重连 SSH，非激活标签的输出照常写入。
- 列表空白处或连接项右键打开菜单：空白处为 `New connection`，连接项为 `New connection`、`New session`、`Edit`、`Delete`。侧栏标题行右侧另有 `+` 按钮直接新建。
- 连接字段在终端区底部升起的面板维护，仅两项：名称（唯一）与 ssh 命令（如 `ssh jhihjian@10.0.0.5`，支持 `~/.ssh/config` 别名、`-p`、`-i`、`-J` 等全部 OpenSSH 参数）。服务端保存时做基本校验：命令首词必须是 `ssh`，其余原样保留。
- 删除连接需在侧栏底部内联确认区输入连接名称二次确认，名称不匹配时不执行并提示；删除时该连接的会话标签一并关闭。
- 命令原样存于本机 SQLite（`~/.ursi/ssh/ssh.db`）并完整回传展示，无独立凭证字段，不存在"只写不读"的凭证。

### 终端与 tmux 会话

#### 验收

- 布局为左侧树状连接面板 + 右侧顶部会话标签栏与终端区：嵌入 ursi-flow 工作区时同一布局装进 420px 起的栏内，侧栏固定 200px，标签栏与终端占满剩余宽度。布局纯 flex 实现，不用可拖拽分隔条（折叠后重开靠远端 tmux 恢复屏幕）。
- 选中连接后，树中该连接下实时列出远端 tmux 会话（`GET /api/connections/{id}/tmux-sessions`，实时执行远端 `tmux ls` 不缓存）；远端无 tmux 时显示「远端无 tmux，连接后将回退普通 shell，断开即结束」；SSH 失败（认证失败、不可达）时错误显示在该区。默认入口 main 展示为「默认会话 ssh-main」。
- 点击任一会话项（含默认入口）即在顶部标签栏打开（或激活）标签并启动全新 OpenSSH 子进程：认证失败、主机不可达等失败原因原样显示在终端区（OpenSSH 自身的错误输出），不产生会话。WS 握手即启动子进程，服务端无会话注册表。新建 tmux 会话经标签栏 `+` 或右键 `New session` 展开内联表单，名称限 ASCII 字母数字下划线连字符（1–64），服务端与前端同校验；重名由远端 `tmux new -A` 语义兜底（直接 attach 已有会话）。
- 远端有 tmux 时，PTY 启动命令为 `tmux new -A -s <会话名>`：SSH 断开、刷新页面或关闭浏览器后远端 tmux 会话与其中进程继续运行；重新点击同一会话即 attach 回去，屏幕内容完整恢复。tmux 内 `exit` 退出 shell 会结束 tmux 会话，前端收到退出码。改名、杀会话等管理操作由用户在终端内执行 tmux 命令完成，GUI 不重复造轮子。
- 远端没有 tmux 时自动回退普通 shell，并在终端内显示黄色提示「远端无 tmux，已回退普通 shell，断开后会话不保留」；回退判断由远端一行启动命令完成，服务端不解析输出。
- 终端为 xterm.js 面板，PTY 类型 `xterm-256color`。初始列行由 xterm 实测的 cell 尺寸与面板盒子算出（扣掉内边距与滚动条宽度），并随 WS 握手参数直接用于服务端建 PTY：连接后不会先按 80×24 排版再被 resize 冲刷，握手期间面板尺寸变化会在 WS 打开时补发一次 resize。窗口缩放（含拖拽面板分隔条）时经 ResizeObserver 自适应，列行连续两帧稳定后才落盘，resize 命令 debounce 100ms 同步远端，列行上限 500。
- 渲染使用 xterm 的 Unicode 11 宽度表并补零宽连接符折叠（中文、emoji、ZWJ 序列不量错格）。WebGL 渲染仅在 WebGL2 可用且渲染器不是软件渲染时启用，否则留在 DOM 渲染；上下文丢失后释放 GPU 上下文、退回 DOM 并重排重绘，60 秒内连续丢失 3 次以上不再重试。跨屏拖动或缩放导致 devicePixelRatio 变化、以及切回标签页时，自动修复画布像素比并重绘整个视口。
- 终端内搜索：右键菜单「Search in terminal」或 `Ctrl/Cmd+F` 打开搜索条（快捷键在模块容器内拦截，指针或焦点不在模块内时不枪宿主同名快捷键），支持区分大小写与正则开关、显示命中计数（如 `3/14`）、增量高亮所有命中并标出当前命中；Enter/Shift+Enter 跳转下一个/上一个，Esc 关闭并把焦点还给终端。搜索装饰色按亮暗主题分别取值，保证两种底色上都看得见。
- 输出中的 URL 可 `Ctrl/Cmd+点击`打开，悬停时在终端区左下角显示完整 URL 与打开方式提示。被软换行折断的长 URL 由同一个解析器跨行拼回，首行和续行整段都可点；解析按中文句读与句末标点收尾，不会把后面的句号、右括号吞进链接。
- 终端面板提供暗色（默认）与亮色（白底）两套主题，在终端区右键菜单切换，选择跨刷新保留。两套主题的 ANSI 调色板、滚动条滑条颜色与最小对比度（暗 3:1、亮 4.5:1）分别取值；切换主题只改 xterm 的 theme，不重建终端、不重连 SSH，滚动内容与远端会话保持原样。
- 键盘输入即时送达远端；输出按原始字节流渲染，粘贴长文本自动分片发送。终端历史保留 5000 行，可滚动回看。终端区右键菜单提供新建 tmux 会话与亮暗色切换。
- 服务端推送的事件不打断终端：消息以带颜色的文本内联写入终端尾部（错误红色，远端退出黄色，tmux 内 `exit` 后退出码可见），同时在终端区底部显示一条事件条说明结果，终端已有内容保留供回看。
- 服务端不持久化任何会话：WS 断开即终止 ssh 子进程，同一时间一个 tmux 会话只接一个终端；持久性完全由远端 tmux 承担。多标签仅为前端形态：关闭标签即断开对应 WS，远端 tmux 会话保留。嵌入工作区时面板折叠即卸载全部终端，重开点击会话重新 attach 恢复屏幕，折叠窄条上实时显示激活标签的会话与连接状态（连接中/已连接/已退出/出错/未连接）及打开数。服务端侧的会话保活、自动重连不在范围内。
- ssh 子进程以 `ssh -tt` 强制分配远端 PTY，`StrictHostKeyChecking=accept-new` 首次连接自动接受主机密钥；服务端不做额外主机密钥校验，这是内网工具的明确边界。

### 工作区嵌入

#### 验收

- ssh-web 以 `@ursi/ssh-web/module` 接入 ursi-flow 工作区外壳（栏序 todo、fs、ssh、pi-web），`createSshModule({ apiBaseUrl })` 工厂创建独立的 store 实例，不设模块级单例；独立入口与嵌入共用同一套组件与布局。
- 嵌入时宿主 vite 把 `/api/ssh-web/*` 代理到 8091 并重写为 `/api/*`（HTTP 与 WS 同规则），服务端路由保持 `/api` 不变；模块所有请求（含终端 WS）都走注入的前缀。
- 样式全部作用域在 `.ssh-embed` 容器内，类名带 `ssh-` 前缀，右键菜单 portal 进容器并以容器坐标系定位，不越栏、不吃宿主样式；亮暗主题偏好存于带模块前缀的 localStorage 键（`ssh.terminal-light`）。
- `Ctrl/Cmd+F` 仅在指针或焦点落在 ssh 模块内时拦截，其余场景不干扰宿主快捷键。

### 服务与接口

#### 验收

- 服务默认监听 `0.0.0.0:8091`（`PORT` 可覆盖），托管静态页面与同源 API；数据库路径可用 `URSI_DATA_DIR`（默认 `~/.ursi`）与 `SSH_DB_PATH` 覆盖。接口契约见 [server/HTTP.md](server/HTTP.md)。
- `GET /api/health` 返回 `ok`。连接增删改查、tmux 会话列表与终端 WS 全部走同源 `/api` 前缀，错误统一为 `{error, code}` JSON。
