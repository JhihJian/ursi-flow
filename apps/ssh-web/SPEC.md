# SSH 终端

## 功能意图

ssh-web 为内网主机提供独立的浏览器 SSH 终端。用户以「名称 + 一条 ssh 命令」维护连接配置，点击连接即由服务端启动系统 OpenSSH 子进程（`ssh -tt`）建立会话，前端用 xterm.js 通过 WebSocket 操控远端 PTY。认证（密码、口令、agent）、跳板、`~/.ssh/config` 别名等全部交给 OpenSSH 自身处理，交互提示直接出现在终端里。远端有 tmux 时会话接入 `tmux new -A -s <会话名>`：浏览器断开后远端会话保活，重新连接自动恢复屏幕；无 tmux 时回退普通 shell 并提示。服务与页面由同一个 Rust 进程托管，数据保存在本机 SQLite，不依赖 ursi-flow 的其他模块。界面为 todo-web 的出版物风格。

## 关键功能与验收

### 连接配置管理

#### 验收

- 左侧列表按名称（不区分大小写）排序列出所有连接，每项显示名称与 ssh 命令摘要。点击连接项选中并加载远端 tmux 会话列表，不再直接建会话。
- 列表空白处或连接项右键打开菜单：空白处为 `New connection`，连接项为 `New connection`、`Edit`、`Delete`。侧栏标题行右侧另有 `+` 按钮直接新建。
- 连接字段在终端区内的编辑面板维护，仅两项：名称（唯一）与 ssh 命令（如 `ssh jhihjian@10.0.0.5`，支持 `~/.ssh/config` 别名、`-p`、`-i`、`-J` 等全部 OpenSSH 参数）。服务端保存时做基本校验：命令首词必须是 `ssh`，其余原样保留。
- 删除连接需输入连接名称二次确认，名称不匹配时不执行并提示。
- 命令原样存于本机 SQLite（`~/.ursi/ssh/ssh.db`）并完整回传展示，无独立凭证字段，不存在"只写不读"的凭证。

### 终端与 tmux 会话

#### 验收

- 界面为两级面板：左侧连接列表，中间 tmux 会话列表，右侧终端区（react-resizable-panels 可拖拽调宽）。
- 点击连接后中间栏实时列出远端 tmux 会话（`GET /api/connections/{id}/tmux-sessions`，实时执行远端 `tmux ls` 不缓存）；远端无 tmux 时显示「远端无 tmux，连接后将回退普通 shell，断开即结束」；SSH 失败（认证失败、不可达）时错误显示在中间栏。顶部 `默认会话 ssh-main` 入口加 `↻` 刷新按钮，下方是带客户端数标记（●）与创建时间的会话列表。
- 中间栏底部提供新建 tmux 会话表单，名称限 ASCII 字母数字下划线连字符（1–64），服务端与前端同校验；重名由远端 `tmux new -A` 语义兜底（直接 attach 已有会话）。
- 点击任一会话项（含默认入口）即启动全新 OpenSSH 子进程：认证失败、主机不可达等失败原因原样显示在终端区（OpenSSH 自身的错误输出），不产生会话。WS 握手即启动子进程，服务端无会话注册表。
- 远端有 tmux 时，PTY 启动命令为 `tmux new -A -s <会话名>`：SSH 断开、刷新页面或关闭浏览器后远端 tmux 会话与其中进程继续运行；重新点击同一会话即 attach 回去，屏幕内容完整恢复。tmux 内 `exit` 退出 shell 会结束 tmux 会话，前端收到退出码。改名、杀会话等管理操作由用户在终端内执行 tmux 命令完成，GUI 不重复造轮子。
- 远端没有 tmux 时自动回退普通 shell，并在终端内显示黄色提示「远端无 tmux，已回退普通 shell，断开后会话不保留」；回退判断由远端一行启动命令完成，服务端不解析输出。
- 终端为 xterm.js 面板，PTY 类型 `xterm-256color`，初始尺寸随 WS 握手参数（`cols`/`rows`）直接用于服务端建 PTY，无 80×24 闪排。窗口缩放（含拖拽面板分隔条）时经 ResizeObserver 自适应，resize 命令 debounce 100ms 同步远端，列行上限 500。WebGL 渲染可用时启用（不可用自动回退 DOM 渲染）。终端内搜索：右键菜单打开搜索条，Enter/Shift+Enter 跳转下一个/上一个，Esc 关闭。终端面板提供暗色（默认）与亮色（白底）两套主题，在终端区右键菜单切换，选择跨刷新保留。输出中的 URL 可 Ctrl/Cmd+点击打开。
- 键盘输入即时送达远端；输出按原始字节流渲染，粘贴长文本自动分片发送。终端历史保留 5000 行，可滚动回看。终端区右键菜单提供新建 tmux 会话与亮暗色切换。
- 服务端推送的事件以消息形式内联显示在终端尾部：错误为红色，远端退出（含退出码）为黄色。
- 服务端不持久化任何会话：WS 断开即终止 ssh 子进程，同一时间一个 tmux 会话只接一个终端；持久性完全由远端 tmux 承担。多标签与服务端侧的会话保活、自动重连不在范围内。
- ssh 子进程以 `ssh -tt` 强制分配远端 PTY，`StrictHostKeyChecking=accept-new` 首次连接自动接受主机密钥；服务端不做额外主机密钥校验，这是内网工具的明确边界。

### 服务与接口

#### 验收

- 服务默认监听 `0.0.0.0:8091`（`PORT` 可覆盖），托管静态页面与同源 API；数据库路径可用 `URSI_DATA_DIR`（默认 `~/.ursi`）与 `SSH_DB_PATH` 覆盖。接口契约见 [server/HTTP.md](server/HTTP.md)。
- `GET /api/health` 返回 `ok`。连接增删改查、tmux 会话列表与终端 WS 全部走同源 `/api` 前缀，错误统一为 `{error, code}` JSON。
