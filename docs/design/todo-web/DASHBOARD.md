# SUMM-Todo 看板设计

看板沿用 SUMM-Todo-Web 的出版物式视觉语言，把只读展示扩展为可维护项目与任务的独立应用。前端使用 React 19、TypeScript、Zustand、`@dnd-kit/core` 与 `react-resizable-panels`，后端使用 Rust + axum + rusqlite。

## 页面结构

```text
┌────────────┬────────────────────────────┐
│ 项目列表    │ 当前项目的任务表             │
│ 可拖拽接收  ├────────────────────────────┤
│ 右键菜单    │ 任务详情（从下往上弹出）      │
└────────────┴────────────────────────────┘
```

两栏由 `Group` / `Panel` / `Separator` 组织，项目栏默认 240px 固定像素宽度，内容栏自适应。布局通过 `useDefaultLayout` 存入 `localStorage`，刷新后恢复。分隔线占 6px 宽，中间画 1px 细线，悬停时显示 `⋮` 和深色线，双击恢复默认宽度。

Projects 面板可折叠。表头 `«` 调用面板的 `collapse()`，折叠到 32px；把分隔线拖到最小宽度附近也会自动折叠。折叠态不渲染项目列表，改为单列书脊式信息条。

排法用 `writing-mode: vertical-lr` 加 `transform: rotate(180deg)`，文字从下往上读；默认的 `text-orientation: mixed` 让拉丁字母随行旋转、中日韩字符保持直立。逐字直立（`upright`）会让拉丁字母松散，自上而下读也不如书脊式顺手，这两种都试过。

折叠态所有文字统一字号，避免不同字号导致列内左右错位。结构上是「展开按钮 + 文字区」两段 flex：文字区 `.collapsed-rail` 用 `flex: 1 1 auto` 加 `min-height: 0` 取得确定高度，文字按钮再用 `max-height: 100%; overflow: hidden` 在自身裁剪。因为整块转了 180°，裁剪口落在视觉顶部，先把累计时间等尾部内容截掉，项目名开头始终可见，完整内容保留在 `title` 中。

由于元素本身是竖排，`margin-block` 会被解析成左右外边距，折叠文字改用 `margin-top/bottom: auto` 实现短名称垂直居中。

点 `»` 或信息条调用 `resize()` 恢复折叠前的像素宽度，双击分隔线则回到默认宽度。折叠后的宽度由同一布局保存，刷新后保持。

两栏各自纵向滚动，滚动条隐藏但内容仍可滚动。视觉变量、字体、间距和表格样式沿用参考项目：衬线字体做标题，等宽字体做数据，纯灰度、直角、无阴影和渐变。

## 数据流

Zustand store 保存项目、任务、当前选中项目和筛选条件。组件只读取 store 并调用动作，所有请求集中在 `api/client.ts`。

- 启动时读取项目，选中活跃任务最多的项目，再加载该项目的任务与最近七天分布。
- 修改项目或任务后统一刷新项目、任务与最近七天分布，避免局部数据过期。
- 任务表请求带递增序号，快速切换项目或筛选日期时丢弃过期响应。
- 每 30 秒查询今日完成数，数值增加时播放提示音、发送桌面通知并刷新任务表。
- 服务端错误直接显示在提示框中，不插入演示数据。

## 拖拽

`@dnd-kit/core` 的 `DndContext` 包住两栏。任务行首的 `⠿` 是拖拽手柄，指针移动超过 6px 才开始拖拽，因此普通点击仍打开详情。拖拽时显示单行预览，原行降低透明度。拖动开始后状态标签和项目项出现虚线放置轮廓，悬停目标再加实色高亮。

两类放置目标：

| 目标 | 数据 | 结果 |
| --- | --- | --- |
| 任务表上方的状态标签 | `{ type: 'status', status }` | `PUT /api/tasks/{id}` 改状态 |
| 左侧项目项 | `{ type: 'project', projectId }` | `PUT /api/tasks/{id}` 改 `project_id` |

拖到 `blocked` 时先弹窗询问阻塞原因，取消则放弃这次拖拽：`todo_core` 的状态机要求阻塞必须带原因，缺原因服务端会返回 400。拖拽不维护本地顺序，只表达状态和归属，和待办库现有字段一致。状态迁移与开始、完成时间由 `todo_core::Task::transition` 决定，服务端只负责把库里的行读成 `todo_core::Task`、迁移后再整体写回，见[服务端契约](../../../apps/todo-web/server/HTTP.md)。因此拖到未填结果的完成任务会被拒绝，界面提示 `E_RESULT_REQUIRED`；详情面板在状态为 done 时把结果标为必填。

## 项目操作

界面不放常驻按钮，操作按区域分给右键菜单：项目侧栏只做项目的新增、编辑、删除，任务列表只做任务的新增和删除。

| 区域 | 右键对象 | 菜单项 |
| --- | --- | --- |
| 项目侧栏 | 项目项 | `New project`、`Edit project`、`Delete project` |
| 项目侧栏 | 列表空白处 | `New project` |
| 任务列表 | 任务行 | `New task`、`Delete task` |
| 任务列表 | 列表空白处 | `New task` |

项目项不再提供新建任务，避免同一件事出现在两个区域。项目多到撑满侧栏时空白处不可见，所以 `New project` 同时放在项目项菜单里。任务列表同理：行的菜单带删除，空白处只给新增。删除不会直接执行：菜单会换成确认态，标题行显示 `Delete "名称"?`，再点一次才真正删除。项目与任务共用这套确认方式，确认菜单在各自元素下方重新定位弹出。

菜单是 `ContextMenu` 组件，用 `createPortal` 渲染到 `body`，按指针坐标定位并夹在视口内。点其它地方、按 `Esc`、滚动或改变窗口大小时关闭；关闭判定挂在 `pointerdown` 的捕获阶段，并且先判断事件目标是否在菜单内，否则菜单内的点击会在 `click` 之前就把菜单关掉。

项目的名称、描述、路径用底部面板编辑，复用任务详情的版式：衬线体大标题、说明与路径并排、底部 `Cancel` / `Save`。新建和编辑共用同一块面板，靠 `editing.id` 区分，并用 `key` 保证切换项目时表单重新初始化。

## 任务详情

选中的任务会在任务表左侧显示深色标记并加深行底色。行悬停使用比选中更浅的灰度叠加，进行中和阻塞行也有一致的悬停反馈。详情面板不提供删除入口：删除统一走任务行右键菜单的二次确认，面板底部只留 `Close` 与 `Save`，避免同一动作在两处出现。

内容栏顶部只有一行控件，不再写 `Tasks` 标题和 `drag to` 说明：左边是最近七天的分布条，右边是状态标签，两端各自贴住内容区边缘。栏内边距收到 8px，这一行下方留 4px 接表头，视觉上贴着面板上沿。滚动时整行吸顶。

状态标签左侧是最近七天的分布条，结构与 pi-sessions 的按日筛选一致：一行「按日筛选」、日期范围 `MM-DD — MM-DD`、`全部` 与 `今天`，下面一行是分布条。每天一根，`flex-grow` 取当天数量、`flex-basis: 0`，宽度按数量占比分配；零数量保留 `min-width: 3px`，空白日仍然可点。条形区随头部剩余宽度伸展，因此不再固定 `112px`，也不需要单独占位的日期标签。数据来自 `GET /api/stats/daily?days=7&project=`，按任务创建日期统计，缺失日期补 0。点击某天切换 `dayFilter` 中的该天，`todayKey()` 给出「今天」的键；任务按 `GET /api/tasks?project=&dates=` 拉取，`dates` 是逗号分隔的选中日期，可多选。`全部` 清空数组并在有筛选时去掉下划线高亮；再次点击同一天从选择里移除。按天筛选和按状态筛选都只改动任务查询，不关闭已打开的详情面板：同一份详情可能暂时不在筛选结果里，但内容仍然可编辑。

标签既是拖拽放置目标，也是筛选入口。点击切换 `statusFilter`，再次点击同一标签清空；筛选在客户端对已加载的任务做 `filter`，所以标签上的计数始终按当前项目的全量任务统计，切换项目也沿用当前筛选。筛选为空时表体提示 `No <status> tasks`。标签用 `aria-pressed` 表示是否生效。

详情是一块停靠在任务列表下方的面板。内容栏分成两段：任务表滚动、详情面板贴底，详情面板用 `flex: none` 参与纵向排列，所以列表被压缩后仍然独立滚动，最后一行不会被面板遮住。项目名称、任务数、累计时间只出现在项目列表里，内容栏不再重复展示，项目描述和路径放在项目项的 `title` 里，悬停可看。

弹出效果只靠入场动画：面板挂载时播放 `detail-sheet-rise`，从 `translateY(100%)` 升到原位并淡入，200ms 结束；`prefers-reduced-motion` 下关闭动画。关闭时不播放退场动画，直接卸载，避免为退出多存一份状态。

### 连续文档

详情不是分块表单，而是从上到下一条连续的文档：大标题（无边框、随内容长高的 `textarea`、衬线体）、一行元信息（`status` 下拉、`pri` 下拉、`tags` 输入、`workspace` 输入、`session` 输入、时间）、`Record` 与 `Result` 两个 Markdown 编辑区、底部 `Close` / `Save`。标题行右侧只有一个复制按钮 `⧉`，点击把面板内容拼成 Markdown 交给剪贴板：标题写成一级标题，状态、优先级、标签、时间写成无序列表，记录与结果分别放进 `## Record` 和 `## Result` 小节，逻辑在 `src/lib/task-markdown.ts`。复制成功时图标短暂变为 `✓`。元信息里的下拉和输入框去掉边框，只在悬停和聚焦时描边，让整块看起来是一段文字而不是一堆控件。每个控件前置 10px 的小标签（`status`、`pri`、`tags`、`workspace`、`session`），否则两个下拉挨在一起时看不出哪个是优先级。优先级改动保存后会按新优先级影响任务表排序。

两个编辑区都是所见即所得的 Markdown 编辑区，没有源码与预览两栏，也不存在「写／预览」切换。做法对齐 prosemirror.net/examples/markdown：

- `markdown-it`（commonmark，`html: false`）把库里的 Markdown 解析成文档，`prosemirror-markdown` 的 `MarkdownSerializer` 在每次改动后序列化回 Markdown 交给保存逻辑。文档结构是 `prosemirror-schema-basic` 加 `addListNodes`，覆盖标题、段落、引用、代码块、行内代码、链接、粗斜体、分隔线、图片和有序/无序列表。
- 输入规则即时把语法变成样式：`**加粗**`、`*斜体*`、`` `代码` `` 去掉标记后套用 mark；`# `、`- `、`1. `、`> `、```` ``` ```` 和 `---` 在行首直接换块类型。行内规则的左侧边界接受任意非单词字符，所以中文标点后面接着写 `**加粗**` 也生效。
- 键位用 `prosemirror-keymap` 拼装：`Ctrl/Cmd+B`、`Ctrl/Cmd+I`、`Ctrl/Cmd+\`` 切换 mark，列表里 `Enter` 拆项、`Tab` 缩进、`Shift-Tab` 提升，`Ctrl/Cmd+Z` 撤销，其余交给 `baseKeymap`。
- 空文档用一个 widget 装饰显示占位提示；编辑器与 `markdown-it`、ProseMirror 相关代码放成独立分块，由 `React.lazy` 在打开详情时加载，主包维持在 350KB 左右。

局域网用 `http://192.168.x.x` 打开时不是安全上下文，`navigator.clipboard` 为 `undefined`。复制统一走 `src/lib/clipboard.ts`：安全上下文用 `navigator.clipboard.writeText`，否则插入一个离屏 `textarea` 执行 `execCommand('copy')`。任务 ID 复制和详情复制都用它，避免只在 https 下可用。

编辑器只覆盖 CommonMark 子集。GFM 表格、任务列表、删除线不在 schema 里，输入后会按普通文本保存；真实待办库里没有这类内容，需要时再补 schema 与解析规则。原始 HTML 不会被解析成标签，写进去只是文本。

任务模型有两个自由文本字段：`log` 存工作过程的记录，`result` 存工作结果，两个编辑区共用同一套 Markdown 编辑器。两者都是可选字段，互不覆盖；完成任务与撤销完成都不动 `log`。状态切到 `done` 且 `Result` 为空时，底部提示 `Result required to finish`，保存会被拦下，规则与 `todo_core` 状态机一致。Agent 可通过 `POST /api/tasks/{id}/result/append` 往 `result` 追加一段 Markdown，服务端用空行分隔拼接，接口契约见[服务端契约](../../../apps/todo-web/server/HTTP.md)。

### 调整高度

顶部 10px 的横条是拖拽手柄，悬停时细线加粗并露出 `⋯`。拖动时把 `pointermove`、`pointerup` 挂在 `window` 上，指针移出面板甚至移出窗口仍能继续调整；不用 `setPointerCapture` 是因为面板高度随手势变化会重排，坐标容易跳。

高度写进内联 `height`，限制在 200px 与「面板高度 − 120px」之间，后者保证任务列表至少留一行。松手时把最终高度存进 `localStorage` 的 `todo-web.detail-height`，刷新后沿用；双击横条恢复 360px 默认值。改高只保留这一条路径，`max-height` 兜住上限，不再另设展开按钮。

## 任务关系图

任务区右上角的 `列表` / `图` 切任务表与关系图。视图存在 `localStorage` 的 `todo-web.view`，刷新后保留。

关系图的数据来自独立的 `GET /api/tasks?project=`：按日筛选会截断前置链，图要用当前项目的全量任务。store 另存 `graphTasks`，请求带递增序号丢弃过期响应；切到图视图、切换项目、以及图视图下的任务增删改都会重新拉取。视图状态与任务表筛选互不影响，所以切换视图不关闭详情、也不清空筛选。

只画未结束任务的规则在 `src/lib/task-graph.ts`。默认集合是待办、进行中与阻塞；完成与已取消只有在直接相邻于未结束任务时保留，例如已完成的前置任务、已完成的父任务。只放宽一层，是为了在“完成任务后仍看得见它对后续任务的影响”和“不要把整条历史链拖进图里”之间取平衡。引用了被隐藏任务或其它项目任务的边直接丢弃，避免出现连不到节点的线。

布局是自带的最长路径分层，不引入图形库：先用深度优先挑出回边，只在前进边上松弛层级，因此 `pre_id` 出现环也不会把层数越推越深；同层节点按状态、优先级和标题排序，列宽取该列最宽节点，行内垂直居中。节点用绝对定位的按钮，连线用底层 SVG 路径，父子和前置的线型在 CSS 里区分。横竖滚动交给图区域自己，头部固定在顶上。

点击节点直接 `openTask`，与点任务行一致；图里不提供拖拽与右键操作，状态与归属修改仍走任务表。

## 边界

- 不做登录和权限，服务只应在可信网段或反向代理后使用。
- 不创建或迁移数据库结构，读写现有 SUMM-Todo 库。
- 界面按桌面宽度设计，窄屏时靠面板内部滚动，不提供移动端折叠布局。

## 关联工作区与会话

任务新增两个自由字符串元信息：`workspace` 记录关联工作区，`session_id` 记录关联会话。字段加在 `todo-web/core` 的 `todo_core::Task` 上，服务端 `db.rs` 把它们列入 `TASK_FIELDS`，因此读写在有列的库上自动生效，没有列就跳过。

真实待办库由 SUMM-Todo CLI 建表，不含这两列，所以 `db::ensure_database` 在启动时用 `PRAGMA table_info` 检查，缺列就 `ALTER TABLE tasks ADD COLUMN ... TEXT`。迁移只做加列，不改类型、不写默认值，旧数据保持为空。空字符串按未设置处理：请求里传 `null` 或空串都会写成 `NULL`。

界面把它们放在详情元信息行的 `workspace`、`session` 两个输入框里，随同标题一起保存。复制为 Markdown 时，只有填写的字段才会输出 `- Workspace:` 和 `- Session:` 两行。
