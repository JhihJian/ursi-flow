# SUMM-Todo 看板设计

看板沿用 SUMM-Todo-Web 的出版物式视觉语言，把只读展示扩展为可维护项目与任务的独立应用。前端使用 React 19、TypeScript、Zustand、`@dnd-kit/core` 与 `react-resizable-panels`，后端使用 Rust + axum + rusqlite。

## 页面结构

```text
统计栏：项目数 · 今日 · 本周 · 本月 · 全部
┌────────────┬────────────────────────────┬──────────────┐
│ 项目列表    │ 周期统计对应的任务表         │ 活动任务      │
│ 可拖拽接收  ├────────────────────────────┤              │
│ 右键菜单    │ 任务详情（从下往上弹出）      │              │
└────────────┴────────────────────────────┴──────────────┘
```

三栏由 `Group` / `Panel` / `Separator` 组织，默认宽度为 240px、自适应、300px。项目栏与活动任务栏使用像素宽度，内容栏保留相对宽度。布局通过 `useDefaultLayout` 存入 `localStorage`，刷新后恢复。分隔线占 6px 宽，中间画 1px 细线，悬停时显示 `⋮` 和深色线，双击恢复默认宽度。

Projects 面板可折叠。表头 `«` 调用面板的 `collapse()`，折叠到 32px；把分隔线拖到最小宽度附近也会自动折叠。折叠态不渲染项目列表，改为单列书脊式信息条。

排法用 `writing-mode: vertical-lr` 加 `transform: rotate(180deg)`，文字从下往上读；默认的 `text-orientation: mixed` 让拉丁字母随行旋转、中日韩字符保持直立。逐字直立（`upright`）会让拉丁字母松散，自上而下读也不如书脊式顺手，这两种都试过。

折叠态所有文字统一字号，避免不同字号导致列内左右错位。结构上是「展开按钮 + 文字区」两段 flex：文字区 `.collapsed-rail` 用 `flex: 1 1 auto` 加 `min-height: 0` 取得确定高度，文字按钮再用 `max-height: 100%; overflow: hidden` 在自身裁剪。因为整块转了 180°，裁剪口落在视觉顶部，先把累计时间等尾部内容截掉，项目名开头始终可见，完整内容保留在 `title` 中。

由于元素本身是竖排，`margin-block` 会被解析成左右外边距，折叠文字改用 `margin-top/bottom: auto` 实现短名称垂直居中。

点 `»` 或信息条调用 `resize()` 恢复折叠前的像素宽度，双击分隔线则回到默认宽度。折叠后的宽度由同一布局保存，刷新后保持。

统计栏保持固定高度，三栏各自纵向滚动，滚动条隐藏但内容仍可滚动。视觉变量、字体、间距和表格样式沿用参考项目：衬线字体做标题，等宽字体做数据，纯灰度、直角、无阴影和渐变。

## 数据流

Zustand store 保存项目、当前任务、活动任务、三份周期统计、当前选中项目和周期。组件只读取 store 并调用动作，所有请求集中在 `api/client.ts`。

- 启动时读取项目，选中活跃任务最多的项目，再并行加载任务、三份统计和活动任务。
- 修改项目或任务后统一刷新项目、任务、统计和活动任务，避免局部数据过期。
- 任务表请求带递增序号，快速切换项目或周期时丢弃过期响应。
- 每 30 秒查询今日完成数，数值增加时播放提示音、发送桌面通知并刷新数据；每 60 秒刷新活动任务。
- 服务端错误直接显示在提示框中，不插入演示数据。

## 拖拽

`@dnd-kit/core` 的 `DndContext` 包住统计栏下方的三栏。任务行首的 `⠿` 是拖拽手柄，指针移动超过 6px 才开始拖拽，因此普通点击仍打开详情。拖拽时显示单行预览，原行降低透明度。状态栏前显示 `drag to` 提示；拖动开始后状态标签和项目项出现虚线放置轮廓，悬停目标再加实色高亮。

两类放置目标：

| 目标 | 数据 | 结果 |
| --- | --- | --- |
| 任务表上方的状态标签 | `{ type: 'status', status }` | `PUT /api/tasks/{id}` 改状态 |
| 左侧项目项 | `{ type: 'project', projectId }` | `PUT /api/tasks/{id}` 改 `project_id` |

拖拽不维护本地顺序，只表达状态和归属，和待办库现有字段一致。状态迁移与开始、完成时间由 `todo_core::Task::transition` 决定，服务端只负责把库里的行读成 `todo_core::Task`、迁移后再整体写回，见[服务端契约](../../../todo-web/server/HTTP.md)。因此拖到未填结果的完成任务会被拒绝，界面提示 `E_RESULT_REQUIRED`；详情面板在状态为 done 时把结果标为必填。

## 项目操作

界面不放常驻按钮，操作按区域分给右键菜单：项目侧栏只做项目的新增、编辑、删除，任务列表只做任务的新增和删除。

| 区域 | 右键对象 | 菜单项 |
| --- | --- | --- |
| 项目侧栏 | 项目项 | `New project`、`Edit project`、`Delete project` |
| 项目侧栏 | 列表空白处 | `New project` |
| 任务列表 | 任务行 | `New task`、`Delete task` |
| 任务列表 | 列表空白处 | `New task` |

项目项不再提供新建任务，避免同一件事出现在两个区域。项目多到撑满侧栏时空白处不可见，所以 `New project` 同时放在项目项菜单里。任务列表同理：行的菜单带删除，空白处只给新增。删除不会直接执行：菜单会换成确认态，标题行显示 `Delete "名称"?`，再点一次才真正删除。项目与任务共用这套确认方式，确认菜单在各自元素下方重新定位弹出。

菜单是 `ContextMenu` 组件，用 `createPortal` 渲染到 `body`，按指针坐标定位并夹在视口内。点其它地方、按 `Esc`、滚动或改变窗口大小时关闭；关闭判定挂在 `pointerdown` 的捕获阶段，并且先判断事件目标是否在菜单内，否则菜单内的点击会在 `click` 之前就把菜单关掉。

项目的名称、描述、路径用底部面板编辑，复用任务详情的版式：衬线体大标题、说明与路径并排、底部 `Cancel` / `Save`。新建和编辑共用同一块面板，靠 `editing.id` 区分，并用 `key` 保证切换项目时表单重新初始化。

## 任务详情

选中的任务会在任务表左侧显示深色标记并加深行底色，活动面板中同一条任务也同步标出。行悬停使用比选中更浅的灰度叠加，进行中和阻塞行也有一致的悬停反馈。

详情是一块停靠在任务列表下方的面板。内容栏分成两段：任务表滚动、详情面板贴底，详情面板用 `flex: none` 参与纵向排列，所以列表被压缩后仍然独立滚动，最后一行不会被面板遮住。项目名称、任务数、累计时间只出现在项目列表里，内容栏不再重复展示，项目描述和路径放在项目项的 `title` 里，悬停可看。

弹出效果只靠入场动画：面板挂载时播放 `detail-sheet-rise`，从 `translateY(100%)` 升到原位并淡入，200ms 结束；`prefers-reduced-motion` 下关闭动画。关闭时不播放退场动画，直接卸载，避免为退出多存一份状态。

### 连续文档

详情不是分块表单，而是从上到下一条连续的文档：大标题（无边框、随内容长高的 `textarea`、衬线体）、一行元信息（状态、优先级、标签、时间、工具按钮）、Markdown 正文、底部工具条。元信息里的下拉和输入框去掉边框，只在悬停和聚焦时描边，让整块看起来是一段文字而不是一堆控件。

正文是左写右看的并排布局：左边 `textarea` 写 Markdown，右边实时渲染，不再有「写／预览」切换。输入值先用 `useDeferredValue` 降一档优先级再交给渲染，长文打字不会被 Markdown 解析卡住。

两边滚动按比例联动：一侧滚动时按 `scrollTop / (scrollHeight - clientHeight)` 换算另一侧，并用 `scrollOwner` 标记忽略自己触发的回滚，避免来回抖动。内容栏窄于 900px 时改为上下排列，编辑区固定占 45%，渲染区占余下空间。

渲染交给 `react-markdown` 配 `remark-gfm`，支持表格、任务列表、删除线、自动链接等 GFM 语法。这两组依赖放在 `MarkdownPreview` 模块里用 `React.lazy` 加载，主包维持在 350KB 左右，Markdown 相关代码另成 168KB 分块。渲染时只挂 `remarkPlugins`，不加 `rehype-raw`，所以备注里的原始 HTML 会作为文本显示，不会被执行。

任务模型只有 `result` 一个自由文本字段，正文即写在这里；状态切到 `done` 且正文为空时，底部提示 `Result required to finish`，保存会被拦下，规则与 `todo_core` 状态机一致。

### 调整高度

顶部 10px 的横条是拖拽手柄，悬停时细线加粗并露出 `⋯`。拖动时把 `pointermove`、`pointerup` 挂在 `window` 上，指针移出面板甚至移出窗口仍能继续调整；不用 `setPointerCapture` 是因为面板高度随手势变化会重排，坐标容易跳。

高度写进内联 `height`，限制在 200px 与「面板高度 − 120px」之间，后者保证任务列表至少留一行。松手时把最终高度存进 `localStorage` 的 `todo-web.detail-height`，刷新后沿用；双击横条恢复 360px 默认值。右上角 `⤢` 是展开开关，展开时改用 `height: calc(100% - 120px)`，再点回到记住的高度。

## 边界

- 不做登录和权限，服务只应在可信网段或反向代理后使用。
- 不创建或迁移数据库结构，读写现有 SUMM-Todo 库。
- 界面按桌面宽度设计，窄屏时靠面板内部滚动，不提供移动端折叠布局。
