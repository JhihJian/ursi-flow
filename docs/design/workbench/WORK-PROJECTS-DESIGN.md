# 工作区：全部事项与项目规划

状态：已实现。

**全局侧栏的「工作」是事项与项目规划的统一入口。**「全部事项」覆盖已归入项目和未归入项目的工作项。项目以可编辑的地图组织画布，再用每张画布中的任务卡和关系组织事项。待办和大纲从同一份项目快照汇总和定位内容。待办、画布和清单中的事项共享同一个 `WorkItem`。工作包生成、Flow 和执行器由各自入口显式触发。

## 迁移什么

| PlanWeave 能力 | Workbench 对应设计 |
| --- | --- |
| Canvas Map、Todo 与可展开的项目树。 | 地图与待办放在项目内，画布、任务卡和事项可通过项目大纲定位。新建项目附带默认画布。 |
| Canvas Map 上一张画布对应一个节点，显示画布间关系，可选中查看、拖动排布、打开画布。 | 保留项目总览。地图节点显示名称和 TODO 进度，选择画布或关系线打开侧栏，双击节点或点击「打开画布」进入该画布的图编辑器。 |
| 单张画布上每个 Task 是一个图节点，卡内堆叠多个 Block。 | Task 对应「任务卡」，Block 对应现有 `WorkItem`。可用工具栏创建任务卡，拖动换位置、连线、增删或重接关系。卡内预览 TODO，选中卡可新建或加入事项，条目菜单可排序或移动。 |
| 项目 TODO 视图跨画布汇总 Block，用状态分布、画布阶段卡和分组展示，点击打开 Block Inspector。 | 项目 TODO 面板保留状态分布、画布摘要和分组。用人工办理状态替换执行状态，条目显示「画布 / 任务卡」路径，点击打开浏览器内的事项侧栏，并提供「在画布中定位」。 |

例如，「客户交付」项目有「材料准备」和「验收」两张画布。地图上用箭头标出两张画布的计划顺序。进入「材料准备」，拖放两张任务卡「材料收集」和「材料核对」，把「收齐样本」「补客户授权」放在第一张卡，把「核对客户名单」放在第二张卡。之后从全项目 TODO 点开「补客户授权」，可直接跳回「材料准备」并突出显示对应任务卡里的这一条。办完后手动改为已完成，画布、地图与 TODO 同步反映进度。

## 三个视图如何协作

### 项目管理和地图

- 项目列表支持新建、置顶和「继续上次」。项目内用「地图」「待办」切换视图。借鉴 PlanWeave 的项目树，宽屏将可收起的「项目大纲」停靠在当前项目左侧，切换画布时保持打开。屏幕较窄时使用抽屉，为主视图留出空间。
- 大纲按画布、任务卡和事项展开，显示卡内顺序和人工状态。分支箭头只控制展开，名称链接直接定位。当前 URL 决定选中项及其展开路径。已删除的画布提供返回地图的入口，已移动的事项可跳到当前画布。
- 项目地图与任务卡画布共用顶部工具栏，提供新建节点、新建关系、查看关系、重置布局及图形和列表切换。地图节点显示名称、人工状态统计和打开入口。详情显示所选画布的前序和后续关系，或所选连线的前项和后项。点空白可清空选择。
- 保留原 `/work-items` 作为全局清单和存量事项入口。项目和画布改名保持原 ID。画布或项目仍有 TODO 时，提示先移动或移出事项，再允许删除。删除最后一张画布时要求先建替代画布，或删除整个空项目。

### 画布编辑器

- 任务卡显示名称和按顺序排列的 TODO 标题、状态。任务卡、关系、画布设置和 TODO 共用详情区域，按需打开。选中任务卡可新建或加入已有事项，条目菜单可排序、移动或移出。移出只解除归属，事项保留在全局清单。窄屏列表保留这些操作。
- 连线表达**规划先后**，箭头从前项指向后项。地图关系连画布，画布关系连同一画布内的任务卡，两层独立维护。跨画布的详细拆分通过画布关系和导航表达，首版无需跨画布任务卡连线。拒绝跨作用域、重复、自环和成环的关系。所有关系都与办理状态独立：前项仍待开始时，后项也可被人工标记完成。
- 支持选中、拖动、连接、断开和重接任务卡。条目从一张卡移到另一张卡时，两张卡及其关系保持原样。删除任务卡前须移走卡内所有事项，确认后清理该卡的关系与坐标。窄屏用按任务卡分组的列表完成查看、建项、移动和打开详情。

- 悬停或键盘聚焦节点时，图上突出直接相连的依赖。悬停或聚焦连线时突出该线，已选中的连线优先。缩略图用于浏览大图，缩放控件显示当前比例。
- 右键或 `Shift+F10` 按目标打开菜单。空白处可新建节点、新建关系或重置布局。节点、关系线和 TODO 提供对应的打开、编辑、移动或删除操作。编辑和删除确认在模态对话框完成，草稿和冲突提示留在对话框内。
- 同一图中的编辑、增删和快照重读保留平移与缩放。新节点落在视口外时，画布平移到该节点并保持缩放。切换图、定位节点或显式适应视图时重新定位。

### 项目 TODO 面板

- 顶部显示全项目办理状态分布和各画布摘要，可点摘要筛选该画布。下方按「待开始」「进行中」「已完成」分组，支持按画布、任务卡和类别过滤，所有条目均可浏览。在筛选状态下明确展示筛选范围，地图计数仍取各画布的完整数据。
- 点击 TODO 打开共用的事项详情侧栏，可编辑标题、说明、类别和人工状态，也可打开既有完整详情，查看工作包和生成历史。画布卡内的 TODO 行打开同一个侧栏。侧栏保留事项链接及「在画布中定位」操作。
- 定位时按 `workItemId` 查最新归属，切换到目标画布，待图加载并布局后居中目标任务卡，滚动卡内列表并突出对应 TODO 行。从面板进入时保留筛选和返回位置。若事项已移出当前项目，提示当前归属并提供全局详情入口，不在旧画布上定位。

## 数据与交互边界

### 服务端：规划结构和工作项共用一个存储

| 记录 | 含义 |
| --- | --- |
| 项目、画布、任务卡 | 层级分别是项目 → 画布 → 任务卡。三者均用稳定 ID。任务卡是规划分组，保存名称，办理状态和工作包归属都在工作项层维护。 |
| TODO 放置 | 按 `workItemId` 保存 `{taskCardId, rank}`，一项至多一个位置。画布和项目由父级查得。未放置的工作项仍出现在全局清单。 |
| 规划关系 | 分别记录同项目内的画布关系和同画布内的任务卡关系。存节点 ID，不存坐标或运行策略。 |
| 布局 | 项目地图和每张画布各保存一份节点坐标、布局修订。拖动结束保存，重置清除对应布局。新节点使用默认排布，状态变化不重排已放置节点。 |
| `workListItems` | 标题、说明、类别、手动状态、内容修订仍来自原工作项。TODO 与统计都是视图，不建立第二份事项状态。 |

服务端 `work/planning` 统一装配事项与项目接口。`items` 维护事项内容、状态和修订，`projects` 管理项目、事项归属和工作区快照，`canvas` 维护两层图与布局。工作包与生成器通过工作规划模块查询事项。`work.json` 保留原有 `workListItems` 和 `workProjects`，项目记录内保存图、布局和放置。卡内创建一次提交事项和位置；删除事项一次提交记录删除、归属清理和工作包解绑，保留包、文件、生成来源及历史。移动、移出和图编辑保持事项内容修订。

### 接口：读取工作区，独立写入结构、布局和事项

`GET /api/v2/work-projects/{projectId}/workspace` 在一次 Store 读取中返回项目、画布、任务卡、已放置工作项、规划边和布局。地图进度、任务卡列表和 TODO 分组由这份快照派生。

`POST …/commands` 用项目结构修订保护画布、任务卡、关系、创建并放置事项及移动排序。`GET /api/v2/work-items/{id}/placement` 读取单项最新归属。跨项目转移分为从源项目「移出」和在目标项目「加入」两步。`PUT …/layout` 保存地图或单张画布的布局，使用对应的布局修订。事项编辑沿用原 `PUT /api/v2/work-items/{id}` 和内容修订。冲突返回 `409`，客户端提示并重读快照。完整字段见[项目规划 HTTP 契约](../../../workbench/server/src/work/planning/PROJECTS-HTTP.md)。

### Web：统一路由与按需读取

`workbench/web/src/modules/workspace` 装配清单 `/work-items` 和项目 `/work-projects`，保留项目内的 `/map`、`/canvases/:canvasId`、`/todo` 原有深链。`itemId` 记录正在查看的事项，`focusItemId` 和 `focusCardId` 记录画布定位。待办筛选使用 `canvasId`、`taskCardId` 和 `category`，从待办定位画布再返回时恢复。项目列表按需加载。地图、画布、待办和大纲共用当前项目快照；切换项目取消旧读取。应用壳只渲染统一导航入口。

地图和画布共用独立的 Web `modules/canvas` 模块。该模块基于 `@xyflow/react` 渲染调用方提供的坐标、边和节点内容，只对外报告拖动、选择、连线等图形事件。项目工作区负责生成地图节点和任务卡节点，处理规划写入。PlanWeave 与 [Flow Runtime Web](../../../flow-runtime/web/package.json) 已使用同一图库。详情侧栏沿用 Workbench 的主题、表单和 HTTP 客户端。借鉴 PlanWeave 的组件结构和交互，按 Workbench 数据模型重写投影。若复制源代码片段，保留 PlanWeave 的 MIT 许可证与版权声明。

项目工作区直接访问 Workbench 服务端，关闭 Flow 时仍可完整使用。PlanWeave Runtime、Electron IPC、就绪队列、派发、资源锁和评审门禁留在迁移范围之外。

## 验收

[桌面与窄屏浏览器用例](../../../workbench/web/patches-acceptance/tests/work-projects.spec.ts)在关闭 Flow 的真实服务上综合验证建项目、开画布、建卡、多条 TODO、状态编辑、跨视图定位和刷新恢复。服务端覆盖同作用域关系、成环验证、删除保护、修订冲突、重启恢复和删除回滚。全局工作项与项目 TODO 共用同一条内容记录，原详情和包历史入口继续可用。

画布复制、另存为项目、外部目录绑定以及导入现有 PlanWeave 项目文件是独立能力。实际需要内容搬迁时，再为项目元数据、画布、Task、Block、关系和布局做一次性导入映射，运行记录与执行配置留在源项目。
