# 工作清单

工作清单记录要做的事，工作包保存某一次工作用到的文件。清单只承载事项信息：标题、说明、类别和办理状态。生成工作包由[工作包生成器](WORK-PATCH-GENERATOR-DESIGN.md)独立承担，生成结果可通过归属字段关联到工作项。例如，「每周客户反馈」是一条持续工作，每周用生成器读取一次反馈服务的资源就得到一个独立的包。上周的包仍能打开，本周的包也归在同一工作项下。

## 清单怎么用

清单提供新建、查看、编辑和删除。新建只需标题，默认类别为「一次性工作」，状态为「待开始」。说明可留空。列表可按类别、状态或两者的组合筛选，每行显示标题、类别、状态和关联工作包数。详情页分为工作说明、生成记录、关联工作包三部分，包名链接到已有的[工作包编辑台](PATCH-STUDIO.md)。

类别说明这件事做一次还是持续做：一次性工作如本月材料核查，持续工作如每周整理客户反馈。状态表示进度：待开始、进行中或已完成。两类工作都可以处于三个状态中的任意一个。改变进度不改变类别，生成工作包也不改变进度。

## 当前归属

**一个工作包当前关联零或一个工作项，一个工作项可以关联零到多个包。** 唯一的归属字段是文件型工作包 `workPatches.workItemId`，可空、非空时必须引用有效工作项。工作项详情按这个字段查询包。配置包不参与该关系。

| 操作 | 结果 |
| --- | --- |
| 手动建包 | 可不选工作项。稍后可从包详情选择、改绑或清除归属。 |
| 生成器关联工作项生成 | 服务端把当前项设为归属。生成来源见[工作包生成器设计](WORK-PATCH-GENERATOR-DESIGN.md)。 |
| 移动包或解绑 | 当前归属可变，生成记录保持原样。外部资源变化不会改写已生成的文件。 |
| 删除工作项 | 确认框显示受影响的包数。在一次存储更新中清空这些包的归属并删除工作项。包、文件和生成记录照常可读。 |

## 页面与接口

「工作清单」页面 `/work-items` 使用独立集合 `/api/v2/work-items`，契约见[工作清单 HTTP](../../../workbench/server/src/work/worklist/HTTP.md)。旧派工记录的处理见[旧数据升级](../../../workbench/server/README.md#旧数据升级)。

## 验收场景

- 未配置 MCP 时，创建一条待开始工作，将类别改为持续工作、状态改为进行中，刷新后按这两个条件查到该项，再删除。全过程无需执行环境。
- 手动建一个无归属包，把它关联到某项后再改绑。两个工作项的包列表随之更新。删除该项时保留所有包；从已删除工作项生成的包仍显示原始来源。
