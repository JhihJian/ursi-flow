# 工作包生成器设计

工作包生成器（`WorkPatchGenerator`）是可复用、可独立运行的 Python 定义。用户可以试运行并查看只读文件，也可以在提交运行时关联一个工作项，生成一个归属该事项的工作包。两种操作共用一条执行流程和统一的运行请求，都可以从「生成记录」查回结果。

生成器把脚本定义从工作项中独立出来：事项只记录要做的事，不再保存资源引用和 Python 源码。生成器复用现有 MCP 读取、Python 隔离和包目录登记。发布定义只更新配置；生成由调用方显式发起，与工作项类别、办理状态和 Flow 运行独立。

## 定义与用法

- **发布生成器。** 定义包含 `generatorId`、名称和不可变修订。每个修订保存 Python 源码和输入别名。发布新版不影响已有运行记录。
- **独立试运行。** 在生成器详情选择修订，按别名选择已登记的 MCP 资源，运行成功后打开只读结果文件。
- **关联工作项生成。** 提交运行时附带 `workItemId`，事项须已存在。生成成功后发布归属该事项的可编辑包；事项在发布前被删除时整次回滚。

## 运行与发布

1. **登记。** 调用方提供 `runId`，提交统一形态 `{generator:{id,revision}, resources, workItemId?}`。Workbench 在取数前登记运行，校验生成器修订、资源别名对应关系和事项存在性，固定生成器修订、输入引用和适用的工作项快照。同一 `runId` 提交相同请求返回原记录，提交不同请求返回 `409`。主动再生成时使用新 `runId`。
2. **转换。** Workbench 通过平台 MCP 授权读取资源，将当次快照交给隔离的 `transform(item, resources)`。试运行的 `item` 为 `None`；关联工作项时为受理时的事项快照（ID、标题、说明、类别、状态）。脚本按别名读取快照，返回包名 `name` 和文件列表 `files`。授权读取、隔离和文件限额见[转换契约](../../../workbench/server/src/work/generation/CONVERSION.md)。
3. **发布。** 校验并落盘文件后，在同一笔存储更新中登记结果目录、运行结果及工作包（仅关联工作项的运行）。发布时只校验事项仍存在，已删除则整次回滚。登记完成后文件才可访问。读取、转换、校验或发布失败时，运行保留失败阶段，无可见半成品。服务重启后，未完成的运行记为中断，已发布结果按原 `runId` 查回。

## 生成记录与结果

「工作包生成器」页面和工作项详情都可打开对应的「生成记录」（后者按 `workItemId` 预筛选）。记录保留运行时间、服务端验证的发起身份（当前为共享令牌认证的工作台管理员，不能区分个人）、生成器修订、输入来源与摘要，以及状态和结果链接或失败原因。外部资源正文和凭据不进入记录。

从记录可打开当时的生成器修订，也可查看试运行的只读文件列表或跳到生成的工作包。包的来源面板可返回原运行。包的当前归属单独维护，删除工作项会解除当前归属，生成记录保持原样。工作包可编辑，包链接打开的是当前内容，记录中的文件清单描述生成时的结果。

API 提供[定义与运行](../../../workbench/server/src/work/generation/GENERATORS-HTTP.md)两个入口：`/api/v2/work-patch-generators` 管理定义和修订，`/api/v2/work-patch-generation-runs` 提交运行、查询列表和详情。试运行和关联工作项的生成走同一个运行入口。

## 验收

- 关闭 Flow，发布生成器第 1 版并独立试运行，从记录打开只读文件。以 `workItemId` 关联事项生成关联包后再发布第 2 版，原运行仍指向第 1 版。
- 同一 `runId` 重试只对应一次运行和一个结果。删除工作项后，已发布的包仍可打开，包和原运行仍可双向跳转。
- 模拟 MCP 读取失败、脚本输出非法或发布前事项被删除，能从记录查到原因，且无新包或可见目录。
