# 工作包生成器设计

工作包生成器（`WorkPatchGenerator`）是可复用、可独立运行的 Python 定义。用户可以试运行并查看只读文件，也可以把指定版本绑定到工作项，在需要时生成一个关联工作包。两种操作共用一条执行流程，都可以从「生成记录」查回结果。

现行工作项把资源引用和 Python 源码一起保存在[内嵌配方](WORK-LIST-DESIGN.md)中。生成器把脚本定义从工作项中独立出来，复用现有 MCP 读取、Python 隔离和包目录登记。发布定义或保存绑定只更新配置。生成由用户显式发起，与工作项类别、办理状态和 Flow 运行独立。

## 定义与用法

- **发布生成器。** 定义包含 `generatorId`、名称和不可变修订。每个修订保存 Python 源码和输入别名。发布新版不改变已有绑定。
- **独立试运行。** 在生成器详情选择修订，按别名选择已登记的 MCP 资源，运行成功后打开只读结果文件。
- **从工作项生成。** 工作项保存 `{id, revision}` 和各别名的 `(serverId, uri)`。点击「生成工作包」，使用已保存的配置读取资料并创建一个新包。旧包和工作项的办理状态保持不变。

## 运行与发布

1. **登记。** 调用方提供 `runId`。Workbench 在取数前登记运行，固定生成器修订、输入引用和适用的工作项快照。同一 `runId` 提交相同请求返回原记录，提交不同请求返回 `409`。主动再生成时使用新 `runId`。
2. **转换。** Workbench 通过平台 MCP 授权读取资源，将当次快照交给隔离的 `transform(item, resources)`。独立试运行的 `item` 为 `None`。脚本按别名读取快照，返回包名 `name` 和文件列表 `files`。授权读取、隔离和文件限额沿用[现有转换契约](server/src/work/worklist/CONVERSION.md)。
3. **发布。** 校验并落盘文件后，在同一笔存储更新中登记结果目录、运行结果及工作包（仅工作项生成），发布前复核工作项修订。登记完成后文件才可访问。读取、转换、校验或修订检查失败时，运行保留失败阶段，无可见半成品。服务重启后，未完成的运行记为中断，已发布结果按原 `runId` 查回。

## 生成记录与结果

「工作包生成器」和工作项详情都可打开对应的「生成记录」。记录保留运行时间、服务端验证的发起身份（当前为共享令牌认证的工作台管理员，不能区分个人）、生成器修订、输入来源与摘要，以及状态和结果链接或失败原因。外部资源正文和凭据不进入记录。

从记录可打开当时的生成器修订，也可查看试运行的只读文件列表或跳到生成的工作包。包的来源面板可返回原运行。修改或清除生成器绑定只影响后续运行。包的当前归属单独维护，删除工作项会解除当前归属，生成记录保持原样。工作包可编辑，包链接打开的是当前内容，记录中的文件清单描述生成时的结果。

API 提供[定义与运行](server/src/work/worklist/GENERATORS-HTTP.md)两个入口：`/api/v2/work-patch-generators` 管理定义和修订，`/api/v2/work-patch-generation-runs` 提交运行、查询列表和详情。试运行和工作项生成走同一个运行入口。

## 验收

- 关闭 Flow，发布生成器第 1 版并独立试运行，从记录打开只读文件。绑定第 1 版生成关联包后再发布第 2 版，已有绑定和原运行仍指向第 1 版。
- 同一 `runId` 重试只对应一次运行和一个结果。删除工作项后，已发布的包仍可打开，包和原运行仍可双向跳转。
- 模拟 MCP 读取失败、脚本输出非法或发布前工作项被修改，能从记录查到原因，且无新包或可见目录。
