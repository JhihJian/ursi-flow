# 在 Workbench 快速配置基于 Agent 的执行器（设计提案）

平台在「新建执行器」提供「基于 Agent 配置」入口，首个运行后端为 Pi。用户配置、试运行、发布和选择的始终是同一个执行器。例如，「工单核查」的第 3 版就是 `executorRef: {id: "工单核查", revision: 3}`。平台内部持有该版本的配置快照，快照随执行器版本管理，不单独命名、发布或选择。

## 配置人员和经办人各做什么

1. **配置。** 在执行器页填写名称和固定指令，选择 Skills、受管模型和获准的业务 MCP 工具。提示词、Skill 编辑与文件选择可复用[现有编辑组件](PATCH-STUDIO.md)。可选用已有配置包预填表单；直接填写即可发布，已有配置包后续变化不影响已发布的执行器。
2. **试运行。** 在同一页选择一份样例工作包，填写本次任务，查看实际用到的资源和生成的报告。平台固定本次试跑的草稿内容，并使用与正式执行相同的 Pi 调用链。编辑草稿后，页面将上次试跑标为旧配置的结果。
3. **发布和使用。** 点击「发布执行器」生成一个修订。经办人在工作包页选择「工单核查 @3」并填写任务，后续沿用平台的执行记录、取消和制品查看入口。新提示词或新工具清单发布为 @4，已有尝试继续绑定 @3。

## 平台边界与开发项

| 建设项 | 设计决策 | 验收 |
| --- | --- | --- |
| 执行器编辑和发布 | 扩展[现有执行器发布接口](server/src/work/catalog/HTTP.md) `POST /api/v2/executors`，允许一组受限的 Agent 配置字段。发布时校验并在同一事务内登记执行器修订及私有配置绑定。固定提示词、Skill 正文和附件、工具名和参数 schema 摘要、受管模型配置版本。运行程序、路径和凭据仍由管理员控制。 | 只发布一次，只产生一个可选的执行器版本；修改预填来源或草稿不会改变旧版。 |
| 执行器选择与调度 | 扩展[尝试入口](server/src/work/executor/mod.rs)，接收 `executorRef`、可选 `workPatchId` 和 `workInstruction`。Server 解析版本，冻结运行器绑定和配置摘要。Pi 是 Agent 配置方式的首个驱动；Flow 仍走自己的驱动。 | 同一 ID 换执行器修订或输入返回 409；查询、取消均路由至原运行器。 |
| Pi 运行器 | 新增 `pi-executor-mcp`，实现既有[启动、查询、取消协议](EXECUTOR-MCP.md)。固定配置由平台只读提供，与业务材料分开。持久任务宿主按 `attemptId` 去重，用 Pi SDK 创建隔离会话，只加载本版资源。固定指令作为系统上下文，本次任务单独传入。只读 `inputs/`，向 `artifacts/` 写交付文件。 | 丢失启动回执并重启 Workbench 后能查回原任务；无法核实已发出的 prompt 时标记 `unverified`，不自动重发。 |
| 业务 MCP 工具 | 在已有只读资源接入之外建设工具目录与授权。配置页按工具勾选，运行时核验「执行器本版声明 ∩ 当前授权」。凭据由服务端解析。首版只开放审核过的只读工具。 | 给「工单核查」勾选 `tickets.get` 后可以查工单，不能修改工单；撤销读取授权后旧版也不能继续调用。 |

## 实施顺序

先走通「执行器页填写提示词、选择 Skill、发布、选版运行、下载报告」，验证一个执行器版本足以驱动 Pi。随后接入试运行和业务工具勾选。业务工具调用能力尚未就绪时，发布校验应明确拒绝带工具依赖的配置。验收以配置人员全程无需编辑 JSON、经办人全程只需选择执行器版本和工作材料为准。
