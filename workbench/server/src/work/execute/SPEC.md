# 工作项执行

## 功能意图

执行已开始办理的工作项所绑定的动作，保存每次执行的证据，以供经办人跟踪、取消和交付。

## 关键功能与验收

### 受信本地 Agent

#### 验收

- 启动前在同一次存储更新中校验工作项状态、核对动作绑定并追加尝试。同一工作项再次执行该动作时获得新的尝试 ID，旧尝试仍可查询。不支持的资源和执行器组合显式报错。
- 尝试成功后，若经办人尚未提交交付，工作项仍为 `working`，交付历史不变。执行结果只更新尝试，工作项的交付和验收状态由办理模块变更。
- 使用真实发布的包创建工作项，即使包、动作和执行器都声明了资源，也只解码快照中投影的执行器及合并去重的资源正文；升级资源不改变旧单的提示词。包和动作端口格式由目录在发布时校验，执行器不声明业务端口。
- Agent 仅通过管理员配置的可执行文件和工作区调用 Pi。SOP、输入、skill 和 prompt 正文经标准输入传入。执行时间、输出和并发有上限，取消或退出时清理本次进程组。
- 当前执行计划通过内部执行器集成注册表选择受信本地 Agent 适配器。注册表按能力、就绪状态、优先级和容量筛选候选；旧 Flow 快照不会被重新派发，查询、取消和人工核实均标记为不可用。
- 尝试的 `workspace` 是平台分配的目录能力引用 `{id, access, purpose}`，不是宿主路径。本地 Agent 和 Flow 的 `id` 为 `default`，沙箱为环境别名。后端输出或诊断中的工作区、制品目录宿主路径不随尝试返回。
- 创建尝试时冻结执行器集成和配置边界：平台选择后保存不透明的 `executorIntegration.id/revision`，后续查询、取消、恢复和结果记录不得重新选择；同时保存配置版本、普通配置值、secret 的 `irreversible` 或 `internalRef` 状态，以及 `configPackage.sourceRef`。平台为每次尝试生成新的 `configPackage.snapshotRef` 和只读 `configPackage.capability`，重试不得复用；secret 值、locator、`directoryId` 和宿主路径不进入尝试或执行器请求。缺少配置的旧结构使用兼容的空配置。

### 尝试记录、制品目录与两类日志

#### 验收

- 启动时选择并预留内部执行器集成，在同一次存储更新中校验工作项状态、绑定动作、冻结 `workInstruction` 和 `configPackage`、分配 `artifactDirectory` 并追加尝试。尝试记录 `id`、动作、状态、逻辑执行器、冻结的 `executorIntegration`、资源、`workspace`、`workInstruction`、`configPackage`、`artifactDirectory`、`platformLog`、`executorLog`、`executorLogPage` 和旧 `output` 字段。
- 制品目录登记在虚拟目录模块中，平台通过 `URSI_ARTIFACT_DIR` 向执行器提供写入能力。当前内置 Pi 调用使用 `--no-tools` 等隔离参数，实际制品写入能力尚待后续执行器切片；平台只把目录标识和清单对外公布，不公布宿主路径；清单经 `/v2/directories/{id}/tree` 读取。
- 每次尝试独占新的制品目录，重试不覆盖历史制品。尝试结束（成功、失败、取消、待核实）后目录与其记录一起冻结，此后写入、建目录、移动和删除返回 409，读取和清单仍可用。
- 平台记录日志按序追加尝试创建、尝试结束、制品目录冻结、人工核实和重启恢复等事件，每条含序号、时间、事件类型、摘要和当时状态。执行器记录日志暂只承接 Agent 标准输出，按来源和顺序保存；恢复、核实和查询都不会覆盖它或旧 `output`。
- 服务重启把未结束的尝试转为 `unverified` 时，恢复提示写入 `recoveryNotice` 和新平台日志事件，不覆盖执行器留下的 `output`；已中断尝试的制品目录同时冻结。
- Flow 和沙箱当前只登记并冻结独立制品目录，尚未收集后端产物；`executorLogPage` 是执行器自建静态日志页的预留入口，当前恒为 `null`，平台不生成任何跳转地址。
- 配置包执行请求只允许传递尝试专属的能力引用，适配器不得把配置包目录解析为公开宿主路径。配置快照只在创建尝试时生成，查询、恢复和重试不会修改旧尝试。
- 内部集成注册表只在服务端装配，不提供公共管理路由。每个集成声明不透明身份、实现修订、能力、就绪状态、优先级和容量；选择时优先使用优先级高的集成，同优先级先选正在运行的尝试较少者，再按注册顺序选择。在复制配置包之前预留容量。没有就绪候选返回不可用，候选全满返回繁忙，两种情况均不分配快照或登记尝试。已冻结的集成修订不在注册表时，列表保留历史，详情、取消和核实返回 503，不会重新选择。服务重启不恢复旧 lease，未结束尝试按既有恢复规则转为 `unverified`。

### 显式绑定的独占沙箱

#### 验收

- 沙箱 ACP 后端尚未迁移到当前执行器契约。带旧沙箱字段的历史快照不会启动、查询或核实沙箱会话，而是返回不可用；构建 Server 不依赖沙箱源码或客户端二进制。
- 单次事务预留执行位置。收到 `new` 的真实 sessionId 后，Store 中应已有该 ID 和环境别名，才允许发送一次 prompt。活动或待核实的沙箱尝试阻止新的沙箱尝试，包括重启之后。
- 仅原 prompt 的 `end_turn` 可判成功。已发送的 prompt 判取消需原响应 `cancelled` 和相同会话停止的状态证据；正常收尾还需关闭回执。控制通知、CLI 退出和零散 update 均不能单独证明结果。

### 断开恢复与人工核实

#### 验收

- 响应丢失后可按工作项查回尝试。重启后未结束的尝试转为 `unverified`，保留中断前状态；恢复、查询和核实均不重放执行。
- 人工核实只接受 `unverified` 尝试。操作者必须提供非空证据及原因，结论只能为失败或取消。一次更新同时保存原状态、结论和依据，保留原输出；再次核实或核实期间尝试已变更时返回冲突。
- 沙箱已登记会话时须在原环境查得相同 ID、`closed` 且 `pid:null`；建会话阶段重启且尚未登记 ID 的尝试没有发送过 prompt。
- 旧 Flow 或沙箱尝试不能进入当前人工核实流程。系统保留历史记录，但对其查询、取消和核实返回不可用，不会重放后端请求。
- 未核实前交付被拒绝，核实且没有其他活动或待核实尝试后可显式交付。核实本身不改变工作项状态，也不能代替验收。

### 迁移边界

#### 验收

- 本次只完成 `workspace + workInstruction → artifactDirectory` 的尝试侧契约。派工模板仍用 `inputs`/`outputs` 端口声明，Flow 仍以工作项 `input` 作为变量，交付仍提交文本文件对象，尚未从制品目录选择文件。
- `output` 作为旧字段保留，与制品目录并存；执行详情不再把它当作执行器的唯一产物。
