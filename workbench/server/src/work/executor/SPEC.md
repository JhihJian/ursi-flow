# 执行器尝试

## 功能意图

让已认证的调用方用自己持有的尝试 ID 提交冻结指令、核对后端状态，并读取本次产生的文件。Workbench 负责尝试和只读制品目录，通过管理员配置的本机 stdio MCP 程序访问执行后端。

## 关键功能与验收

### 固定执行入口

#### 验收

- 启动、查询和取消均要求管理令牌。未配置 `URSI_EXECUTOR_BIN` 时，已认证的启动返回 503，不产生后端运行。
- 每次工具调用以独立会话运行固定的绝对路径，子进程只得到契约列出的环境变量；无需在平台只读 MCP 服务中登记。

### 按 ID 启动、查回与取消

#### 验收

- 调用方 PUT 小写 UUID、UTF-8 指令和可选工作包，获得对应尝试。同 ID 同参数重复 PUT 复用同一次运行；改动指令或工作包返回 409。
- 丢失启动回执后，用原 ID GET 可核对仍在运行或已结束的后端任务。即使服务重启，GET 也不重发启动；只有调用方显式以相同参数 PUT 才可按原 ID 重发幂等启动。
- POST 取消只作用于对应尝试；以实际后端状态确认终态。尚无终态证据时可继续 GET 查询。

### 输入与只读制品

#### 验收

- 各次尝试有独立 workspace，工作包输入放在 `inputs/`，`artifacts/` 用于输出。公开引用对应本次 ID，不公布宿主绝对路径。
- 运行中或待核实不发布 `artifactDirectoryId`。确认终态并收集制品后，该 ID 可用于查询目录树、读取文件；新增或覆盖文件返回 409。已发布目录不包含 `inputs/` 的内容。
