# 工作清单

## 功能意图

经办人按类别和办理状态维护工作事项。事项只承载事项信息，不包含生成流程；文件型工作包由[工作包生成器](../generation/SPEC.md)独立生成，可通过归属字段关联到事项。

## 关键功能与验收

### 维护事项

#### 验收

- 仅提供标题即可新建。初始类别为 `one_time`，状态由服务端固定为 `pending`，新建请求不能指定状态。说明为空、修订为 1，请求携带未知字段返回 400。
- `one_time` 和 `continuous` 两类事项均可处于 `pending`、`active` 或 `completed` 状态。只修改其中一个字段时另一个保持原值；列表支持分别筛选或取交集，重启后仍可按最后保存的值查询。
- 旧库在取得存储锁后一次升级：原类别 `continuous` 改为 `continuous` + `pending`，其他三种原类别改为 `one_time` 并作为状态保留。升级仅改这两个字段，保留事项修订、包归属与生成记录；同时清除历史内嵌配方字段与 `workListGenerations` 表，之后再次打开时保持记录原样。
- PUT 修改事项内容时递增修订，重复保存相同内容保持修订。提交过期修订返回 409，保留已保存的内容。

### 删除和解绑

#### 验收

- 删除事项和清除关联包的 `workItemId` 在一次存储更新中完成。已改绑其他工作项的包保留其归属。
- 删除后仍能通过原包 ID 和目录 ID 读回包、文件及生成来源；对应生成记录保持原样。
