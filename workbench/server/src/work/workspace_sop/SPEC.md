# 手动工作包与 SOP

## 功能意图

经办人按工作包类型提交一份需求和材料，由指定版本的 SOP 运行并取得本次产物。工作包草稿不绑定 SOP，执行时才选定并冻结版本。内置 Echo 在当前进程中只读材料，不需要外部服务。

## 关键功能与验收

### 定义与准备

#### 验收

- 初次启动即可使用单条线索报告类型。类型给出推荐默认 SOP `receipt@1`，必交材料为 `finding` 和 `source`。创建工作包只接受类型和需求，不接受也不保存 SOP 绑定。
- 草稿允许材料未齐；材料齐全且需求非空时工作包就绪。文件名是显示信息，两个工作包的同名文件独立保存，压缩包不解压。

### SOP 版本选择

#### 验收

- `GET /sops` 返回所有已发布版本的数组，包含内置 `receipt@1`，按标识和修订号排序。发布新修订不改变已发布版本的内容。
- 每次执行提交 `{"sop":{"id","revision"}}` 或 `{}`。后者按类型的推荐默认引用解析。解析成功后才进入冻结。
- 本次执行的完整定义，包含 id、revision、executor 和 config.title，冻结在 `attempt.sop`。同一工作包可以显式换版，旧尝试和旧回执保持各自版本不变。
- 引用的版本不存在时返回 404，工作包保持未冻结，也不新增尝试。

### 执行与取件

#### 验收

- 执行时冻结需求、材料清单和本次尝试的 SOP 修订绑定；新尝试读取实际上传的字节并写出带内容摘要的回执。结果不代表漏洞判断或交付验收。
- 同单重跑生成新尝试。按单号和尝试号查看或下载该次回执，读取另一单的尝试不能取得成果。重启不丢失历史。
