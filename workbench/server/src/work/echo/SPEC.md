# Echo SOP 执行器

## 功能意图

接收回执 SOP 只有一个执行器：读取工作区已收存的材料正文，生成一份可下载的接收回执。执行动作与冻结工作区同时发生，失败也留下尝试记录，便于重跑。

## 关键功能与验收

### 执行前置校验

#### 验收

- 需求只有空白字符时返回 400，工作区保持未冻结，不新增尝试。
- 声明的每个材料角色都已有材料时才执行。缺少任一角色返回 400，错误信息点名该角色的标签，不写库。
- 工作区只保存创建时解析好的 SOP 修订快照。执行器为 `echo` 的任意修订都按该修订的标题执行，其他执行器视为工作区数据损坏。

### 原子冻结与尝试隔离

#### 验收

- 校验通过后，在同一笔存储更新里把工作区标记为冻结并追加尝试；冻结后不能再改需求或材料，但仍可重跑。
- 每次执行使用独立的尝试标识，回执按尝试标识存放在独立的 `receipts` 字典，重跑不会覆盖旧尝试或旧回执。
- 执行失败（材料文件缺失、材料不是普通文件、目录不可用）返回详情并记录 `failed` 尝试，`error` 只说明材料角色，不含服务端路径。

### 回执内容

#### 验收

- 回执在每次执行时重新读取材料文件的二进制内容，记录服务端实际读到的字节数和 FNV-1a 64 位内容摘要。摘要明确标注为内容校验用途，不作为密码学签名。
- 回执字典包含工作区标识、尝试标识、类型、标题、需求、SOP 修订、生成时间、材料清单和渲染后的正文，可直接作为标准 JSON 存入工作数据。
- 正文按标题、需求、材料表格组织。上传文件名只用于展示，控制字符被移除，管道符转义，不参与任何路径。

### 材料定位与读取安全

#### 验收

- 材料路径为 `store.dir()/workspace-files/<材料目录>/<角色>`。材料记录带服务端分配的 `blob` 时优先使用它，否则使用工作区 UUID，与材料上传模块一致；上传文件名不进入路径。
- 材料目录与角色必须是单级名称，拒绝 `.`、`..`、路径分隔符和控制字符。
- 打开材料文件使用 `O_NOFOLLOW` 并核对为普通文件，材料目录也拒绝符号链接，避免读出工作目录以外的内容。

### 回执读取

#### 验收

- 只有属于该工作区且状态为 `succeeded` 的尝试才能取回执，否则返回 404。
- 回执以 UTF-8 纯文本返回，带 `nosniff`。带下载参数时使用 `attachment; filename="receipt.md"`。鉴权由统一的传输层完成，接口不返回文件系统路径。

| 方法 | 路径（相对 `/api/v2`） | 结果 |
| --- | --- | --- |
| POST | `/workspaces/{id}/attempts` | 校验、冻结、执行并返回工作区详情 |
| GET | `/workspaces/{id}/attempts/{attempt}/receipt` | 回执正文；`?download=true` 时作为附件下载 |
