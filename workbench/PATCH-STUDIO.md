# 工作包与配置包编辑台

工作包和配置包各自是一条 `{id,name,directoryId}` 记录，分别持久化到 `workPatches` 与 `configPatches`。`directoryId` 指向独立的虚拟目录资源。虚拟目录可以单独创建和读写，不需要先有包。工作包的目录可自由整理；配置包目录中的 `AGENTS.md`、`skills/`、`mcp.json` 各有固定用途。两种包独立创建，以目录内容为准。

## 模块分工

| 开发单元 | 负责 | 不负责 |
| --- | --- | --- |
| 虚拟目录资源 | 注册目录 ID，提供按相对路径操作目录和文件的接口，维护磁盘私有根 | 工作包、配置包等业务元信息 |
| 包记录 | 保存名称与目录 ID；新建时分配资源，配置策略提供初始文件和路径规则 | 存储文件树或正文 |
| 通用资源管理器 | 文件树、页签、文件编辑与查看、上传与目录导入、文件操作 | 判断何为需求、技能和提示词 |
| 工作包与页面框架 | 新建、选择目录，管理桌面和窄屏中的可用空间，工作包直接打开资源管理器 | 配置、派工或执行的表单 |
| 配置包编辑器 | 对应文件的系统提示词、Skills、MCP 三个入口。技能附属文件复用资源管理器 | 启动工具、连接 MCP、选择执行器 |
| 交互检查 | 在真实浏览器复查桌面布局和窄屏切换，确认编辑确实写入文件 | 运行智能体或测试业务交付 |

## Grasp 对照

参考的是 Grasp 的 `web/src/views/AgentStudioView.vue` 及 `components/agent/AgentFilesPanel.vue`、`StudioTabStrip.vue`、`MarkdownSplitEditor.vue`。`App.vue` 中的 `route-view-wrap` 只是路由内容的可用区域。桌面优先把空间给树和当前文件，文件列表和内容可以单独滚动；窄屏把选文件、读写文件分成两个视图。继续使用 Workbench 自己的导航、鉴权与视觉主题。
