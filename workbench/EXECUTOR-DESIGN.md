# 执行器概念与结构

## 结论

在本项目中，**执行器（Executor）是一个可复用、可发布、可固定版本的执行定义**。它回答一个问题：

> 派工模板中的某个动作，交给哪一种执行后端，以什么输入输出契约、依赖和运行边界执行？

执行器属于工作定义目录中的可发布对象。它描述执行方式，执行尝试记录实际运行事实，文件目录承载工作材料。

- 派工模板（`/api/v2/packages`）定义目标、办理说明、动作和验收标准，并为每个动作绑定执行器版本。
- 工作包（Work Patch，`/work-patches`）保存本次工作要处理的文件目录，目前独立于执行定义，不保存动作或执行器绑定。
- 配置包（`/config-patches`）说明一组可独立维护的配置文件内容。
- 一次执行记录实际启动过什么、运行在哪个获准环境、结果是什么。

一个执行器可以被多个派工模板动作复用。一个派工模板可以在不同动作上绑定不同执行器。发布新版执行器不会修改已经绑定旧版本的派工模板或历史工作项。

## 四层边界

### 1. 执行器定义

执行器定义是工作定义目录中的业务对象，使用稳定的 `id` 标识，并按 `revision` 发布不可变版本。当前对象状态是启用或停用，版本正文只读。它与 Work Patch 的目录记录属于不同资源。

它包含：

- 执行器类型：`agent` 或 `flow`。
- 执行目标：本地 Pi Agent、预配 ACP 沙箱 Agent，或固定目录修订的 Agent Flow。
- 输入声明：动作可以传入的字段名和类型。
- 输出声明：动作可以得到的字段名和类型。
- 资源依赖：执行时需要的已发布 Skill 或提示词版本。
- 类型专属字段：Agent 的环境，Flow 的 `flowId` 和 `flowRevision`。

执行器定义只描述允许怎样执行，不保存运行中的会话、进程号、日志、临时目录或最终交付物。

### 2. 环境选择与运行环境

执行器中的环境字段是环境选择策略，表示允许使用哪类后端。运行环境是执行后端实际提供的能力和位置，由部署配置或环境提供方管理，并在执行尝试启动时确定。执行器版本不创建或占有运行环境。

当前支持两种 Agent 环境：

- `local`：在 Server 所在机器上使用管理员配置的 Pi 程序。
- `sandbox`：使用管理员预配的独占 ACP 沙箱。沙箱不可用、授权不匹配或不满足隔离要求时拒绝执行，不能自动退回本地环境。

Flow 不接收 Agent 的 `environment` 字段。它只引用 `flowId` 和字符串形式的 `flowRevision`，由 Flow Runtime 按固定目录修订执行。

环境的程序路径、命令行、工作目录、环境变量、凭据和沙箱分配属于部署与运行管理边界。浏览器发布字段只选择环境策略，不写入主机路径和秘密。

### 3. 执行尝试

执行尝试（`Attempt`）是工作项上的一次实际运行。工作项创建时已经冻结派工模板版本及其动作快照，尝试以这份快照作为唯一执行计划来源。尝试记录：

- 工作项和动作。
- 工作项创建时固定的派工模板版本。
- 快照中绑定的执行器 `id` 与 `revision`。
- 快照中已经解析的资源正文投影。资源解析发生在派工模板发布阶段，尝试不重新解析资源最新版。
- 实际采用的环境和后端运行标识。

尝试单独保存进行中、成功、失败、取消和待核实状态。重试会生成新的尝试，不覆盖旧记录。执行结果只更新尝试，不自动签署交付或业务验收。

### 4. 业务结果

执行器返回的是一次工具调用的结果或证据。工作项的交付、验收和最终业务状态由工作管理模块处理。

因此：

- 执行成功不等于工作项已交付。
- 执行失败不等于工作项被业务拒绝。
- 执行器不能直接修改工作项状态或签署验收结论。
- Flow 节点历史、Agent 会话事件和沙箱资源状态仍由对应后端负责，Server 只保存关联标识和业务摘要。

## 结构

### 公共外壳

发布请求使用以下结构；服务端发布成功后，在版本响应中追加 `revision`，最新版详情另外返回 `active`：

```json
{
  "id": "排查助手",
  "kind": "agent",
  "resources": [],
  "inputs": {
    "ticket": "string"
  },
  "outputs": {
    "report": "string"
  }
}
```

说明：

- `id` 是对象标识，不是文件路径。
- `revision` 由服务端递增，发布请求不能指定；版本响应和历史正文会返回它。
- `active` 表示整个对象是否允许新引用和新派工，由最新版对象详情返回；历史版本以只读正文为准。
- `kind` 决定类型专属字段和后端适配器。
- `resources` 是可选的 `{id, revision}` 数组，引用已发布资源。每个引用必须固定版本。
- `inputs` 和 `outputs` 是可选的字段名到 JSON 类型名的声明，字段名不能重复或包含路径。省略表示该方向没有结构化字段。
- 未声明输入或输出表示没有该方向的结构化字段，不代表可以随意注入主机参数。

### Agent

```json
{
  "id": "排查助手",
  "kind": "agent",
  "environment": "local",
  "resources": [
    { "id": "排查规范", "revision": 3 },
    { "id": "报告格式", "revision": 1 }
  ],
  "inputs": {
    "ticket": "string"
  },
  "outputs": {
    "report": "string"
  }
}
```

`environment` 可省略，语义等同于 `local`。允许值只有 `local` 和 `sandbox`。

Agent 使用 Server 配置的可执行程序。执行器版本可以声明资源引用，但不声明程序路径、命令、模型、密钥或主机目录。发布时服务端校验资源存在、处于启用状态、版本可读且类型可被当前后端使用；当前 Agent 不接受 MCP 注入。

### Agent Flow

```json
{
  "id": "复现验证",
  "kind": "flow",
  "flowId": "reproduce-fix",
  "flowRevision": "2026-11-19.1",
  "inputs": {
    "ticket": "string"
  },
  "outputs": {
    "verification": "string"
  }
}
```

Flow 执行器必须同时提供 `flowId` 和 `flowRevision`。`resources` 可以省略或为空数组，非空资源注入会被拒绝；Flow 不接受 `environment` 字段。Flow 目录的修订由 Runtime 校验；修订不匹配时拒绝启动，不能静默运行最新版。

## 资源与配置包

### 资源引用

执行器的 `resources` 是已发布资源的版本引用，不是资源正文。发布时服务端解析并校验引用，执行器被派工模板使用时再将实际需要的资源正文冻结到派工模板动作快照。

当前资源类型为：

- `skill`：执行步骤或领域知识。
- `prompt`：提示词正文。
- `mcp`：服务和凭据的命名引用。当前执行后端不支持把 MCP 注入执行器，因此不能作为可执行依赖发布。

同一资源的同一版本只保留一次；同一资源引用不同版本则拒绝发布。

### 配置包的关系

配置包是 Workbench 中独立维护的文件目录，包含 `AGENTS.md`、`skills/` 和 `mcp.json` 等文件。它解决的是「一组配置文件如何组织、编辑和复用」，执行器解决的是「一次动作由哪个后端执行」。

因此当前模型中：

- 执行器不复制配置包目录，也不把配置包路径写入执行器正文。
- 配置包参与执行时，需要在派工模板中增加独立的配置包版本引用，并在工作项创建时冻结；这个引用契约独立于 `resources`，由后续执行流程设计定义。
- Work Patch 目录是本次工作的文件输入，配置包目录是可复用的配置内容，两者均不自动变成执行器。
- 执行器当前只引用工作定义目录中的 `resources`，读取 `/config-patches` 需要明确的派工模板引用。

这条边界允许先独立建设执行器管理页面，同时不破坏当前配置包和工作包的独立编辑能力。

## 发布、绑定与冻结

执行器的生命周期如下：

1. 在 `/executors/new` 填写一个新执行器定义。
2. 服务端校验类型字段、输入输出、资源引用和后端兼容性。
3. 发布成功后生成 `revision`，该版本不可修改。
4. 派工模板发布时，动作绑定一个已启用执行器的固定 `{id, revision}`。
5. 发布派工模板时校验输入输出兼容性，并把执行器及资源投影进派工模板动作快照。
6. 创建工作项时保存派工模板版本，后续执行读取这份快照，不跟随目录最新版变化。
7. 启动尝试时再次检查运行所需授权和环境可用性，记录实际环境与后端运行标识。
8. 停用执行器对象后禁止新引用、新版发布和新派工，已发布版本与历史尝试继续可读。

输入输出兼容性在派工模板发布时检查：

- 执行器要求的输入必须由派工模板或动作提供同名同类型字段。
- 执行器产生的输出必须满足派工模板或动作要求的同名同类型字段。
- 校验失败时整个派工模板版本不发布，也不占用新的版本号。

## 管理页面应展示什么

执行器管理页展示的是执行器定义，不伪装成运行监控页。

### 列表

每行显示：

- 执行器名称和 `id`。
- 类型：Agent 或 Agent Flow。
- 执行环境，或 Flow ID 与固定修订。
- 最新版本号。
- 对象状态：已启用或已停用。
- 资源依赖数量和输入输出字段数量。

列表的「新建执行器」只进入定义编辑页，不启动执行。执行中的状态、最近一次结果和运行日志属于工作项执行记录，不放在执行器定义列表中作为定义字段。

### 详情

详情页按「总览、版本历史」组织。总览展示当前版本的完整结构、执行边界、资源版本、输入输出和引用它的派工模板入口。历史页展示每个冻结版本，并允许打开只读正文。

详情页可以发布新版或停用整个执行器对象。停用必须说明：新派工和新引用会被阻止，历史工作项和历史版本仍可查看。

### 编辑

编辑页根据 `kind` 只展示适用字段：

- Agent：执行环境、资源引用、输入和输出。
- Agent Flow：Flow ID、Flow 目录修订、输入和输出。

页面不提供程序路径、Shell 命令、模型密钥、主机目录、MCP 连接参数、运行中的会话控制或执行结果编辑入口。

## 适用范围

以下能力属于工作项执行、工作包目录或后续运行管理模块：

- 在浏览器中直接启动或管理一个常驻 Agent 进程。
- 用执行器保存 Work Patch 的工作文件。
- 用执行器保存一次执行的输出和交付物。
- 通过修改已发布版本影响历史工作项。
- 把配置包、资源、执行环境和执行器 ID 放入同一层业务结构。
- 为尚未接入的后端预留任意命令、插件或动态加载机制。
