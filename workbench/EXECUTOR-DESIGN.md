# 通用执行器设计

**现行接口分定义和尝试两类。** `/api/v2/resources` 和 `/api/v2/executors` 发布、读取和停用定义，见[定义目录契约](server/src/work/catalog/HTTP.md)。`/api/v2/executor-attempts/{attemptId}` 独立管理一次运行，调用管理员固定的单个本机 stdio MCP 执行器。外部程序按[执行器 MCP 契约](EXECUTOR-MCP.md)接入，固定修订的 Flow 是[参考实现](FLOW-EXECUTOR-DESIGN.md)。首版尝试不按目录中的定义选择后端。

## 定义与运行分开

执行器定义回答「用什么能力完成工作」，一次执行尝试记录「这次用了哪些输入，得到了哪些结果」。发布定义与提交尝试是两个独立操作。主机路径、命令行、环境变量和凭据属于部署配置，不进入公开定义。

发布定义的示例：

```json
{
  "id": "排查助手",
  "resources": [{"id": "排查规范", "revision": 3}],
  "configSchema": {
    "fields": [{"key": "agentConfig", "label": "执行配置", "type": "configPackage"}]
  }
}
```

服务端为每次发布分配 `revision`。资源修订与执行器修订分别管理。`configSchema` 描述配置字段，不保存运行中的会话或制品目录。

## 首版尝试

一次调用遵循 `workspace + workInstruction → artifactDirectory`：

| 对象 | 由谁提供 | 用途与生命周期 |
| --- | --- | --- |
| `workspace` | 平台 | 为一次尝试分配目录引用，可从指定工作包准备 `inputs/` 文件。 |
| `workInstruction` | 调用方提供，平台冻结 | UTF-8 文本，写明任务、材料和输出要求。启动后按该文本执行，无需重新读取最新版定义。 |
| `artifactDirectory` | 平台分配，执行器写入 | 执行器向独占的 `artifacts/` 写入文件；确认终态并完成收集后，平台发布只读 `artifactDirectoryId`。 |

调用方用同一小写 UUID 和相同参数 PUT 查回原尝试，必要时显式按原 ID 重发幂等启动。GET 只核对原运行、按需收集制品，不启动。`unverified` 可继续查询，此时不发布目录。要重新执行一遍工作，调用方须使用新 ID。

## 配置快照与结果摘要（提案）

拟在调用需要配置包时为本次尝试复制 `AGENTS.md`、Skills 和 MCP 配置，保存来源标识与内容摘要，只向后端提供只读快照。源配置包和工作包仍可编辑。

建议的结果描述：

```ts
type ExecutorOutput = {
  artifactDirectory: ArtifactDirectoryRef
  status: "succeeded" | "failed" | "cancelled" | "unverified"
  summary?: string
  backendRunRef?: string
}
```

`summary` 用于快速浏览，文件才是可查阅的制品。失败或取消的尝试可保留已收集的部分结果并标出状态。执行结果不改变工作清单项的类别。

## 后端选择与重试（提案）

拟由私有注册表把逻辑执行器绑定到适配器。每个集成声明不透明的 ID、实现修订、兼容能力、就绪状态、容量和管理员优先级。平台按能力筛选并预留容量，将选定的 `{id, revision}` 与输入、配置快照及后端标识一起记入尝试。没有可用后端时拒绝启动；选定后端失败时不静默改用其他环境。

连接中断后，平台先按后端标识核对结果。缺少完成证据时标为待核实，不自动重放可能产生副作用的调用。发起新一轮工作时，使用新的尝试标识、工作区、制品目录和日志序列，原记录仍可查。

## 日志与执行详情（提案）

拟按尝试标识提供稳定的详情入口，依次展示：

1. **平台记录日志。** 展示输入冻结、授权、后端启动、状态变化、恢复和制品冻结等事件。每条记录含时间、顺序和脱敏摘要。
2. **执行器记录日志。** 保留后端输出、阶段事件或 Flow 节点摘要及其来源。平台恢复提示与原始输出分别记录。
3. **制品目录。** 列出冻结文件及状态，便于核对成功结果或诊断部分输出。重试后的详情仍可区分两次尝试的制品。

有后端运行记录时可提供对应链接。执行器自定义静态日志页也是可选扩展：页面只读取获准尝试的日志与制品。路径、资源托管及访问控制仍需单独定义。
