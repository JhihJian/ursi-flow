# Flow 工作台

## 功能意图

使用同源 HTTP 服务维护 Flow 包、运行和配置，通过独立的本地对话入口保留演示体验。登录后的首页是工作清单，经办人在同一工作台里发布定义、派工、办理、交付与验收；结构与边界见 [Web v2 界面设计](DESIGN-v2.md)。

## 关键功能与验收

### 工作台工作清单与办理

#### 验收

- 登录后首页是工作清单，可从已发布的包版本发起待办理工作项，并在详情页开始办理、执行固定动作、提交文本交付、通过或退回。
- 定义、来源、办理与验收的页面行为与边界分别见 `src/app/SPEC.md`、`src/modules/*/SPEC.md`；真实浏览器业务链路的验收资产见 [acceptance](acceptance/SPEC.md)。

### 真实浏览器双单链路

#### 验收

- 在 `web/` 下执行 `npm run test:acceptance`，用真实构建产物、真实 Server 与真实 Pi CLI 跑完：关闭 Flow 与来源时在浏览器发布提示词、引用它的本地 Agent 执行器与工作包第 1 版，按同一版本派两张单并填写不同材料编号。
- 同一命令覆盖发布第 2 版后两张旧单仍显示第 1 版的 SOP、验收标准与固定执行器资源；两单各执行一次都读到执行输出且状态仍为办理中。
- 同一命令覆盖一张单通过第 1 版、另一张单附意见退回后在同一张单提交第 2 版并通过，并用刷新与深链核对文件、退回意见与通过版本；模型只用本机固定回复端点，报告必须写明模拟范围。
- 另起的 `json-file` 来源实例上，来源列表派工进入同一清单且页面只提供获准动作；移动视口完成抽屉进清单、打开待审报告、退回与重读旧版。
- 验收资产在 `web/acceptance/`，每次运行使用独立临时目录、回环端口与新令牌，服务进程只继承白名单环境，结束后停止进程并清理临时业务数据。

### 工作区操作

#### 验收

- 登录后可创建、读取、编辑、验证和删除含多个文件的包。更新携带读取时的目录 revision。
- 从已保存包在 default 工作区启动运行，列表与深链可查看真实状态、参数和历史；停止请求后重新读取运行结果。
- 可读取运行配置并更新模型和最大并发数。

### 认证、导航与对话

#### 验收

- 无令牌不发出业务请求，手动输入后仅通过 Authorization 请求头认证。刷新保持登录，退出清除会话令牌。
- 桌面和移动导航均区分真实服务和本地演示，后端失败显示错误。
- 对话会话可在未登录时创建、流式展示与刷新恢复，消息不发送到运行服务。
