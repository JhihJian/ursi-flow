# 联合验收

## 功能意图

用真实 Web、真实 Server 和真实 Pi CLI 证明经办人与验收人能在浏览器办完一段完整工作：发布资源和执行器、按同一版本派两张单、各自执行、交付、退回与重交、按版本验收。它是产品交付判断的依据，不是模块单测的替代品，也不修改被测页面。

## 关键功能与验收

### 双单链路

#### 验收

- 关闭 Flow 与来源的真实 Server 上，浏览器发布提示词和引用它的执行器，通过 HTTP 发布绑定该执行器的派工模板第 1 版，再在浏览器按该版本派两张单，填写不同材料编号。
- 发布第 2 版后，两张旧单仍显示第 1 版的派工模板修订、办理说明、验收标准和固定执行器与资源版本，不出现新版材料。
- 两张单各执行一次后读到真实执行输出，业务状态仍为办理中；每次执行只向模型端点发一次请求，用户消息只含本单编号、开单时快照里的动作、SOP 与提示词。
- 一张单通过第 1 版；另一张单提交第 1 版后附意见退回，修订后在同一张单提交第 2 版并通过。刷新与深链重开三个交付版本，各自显示对应文件、原退回意见和通过的版本号。
- 断言依据来自真实服务端返回的单号、尝试 ID 与交付版本，模型端点只模拟模型。

### 移动视口

#### 验收

- 移动视口从抽屉进入工作清单，经待验收筛选打开待审报告，读取交付文件后填写意见并退回，再进入旧版交付深链核对文件与退回意见。
- 目标动作在浏览器内完成；待审材料可以用真实 HTTP 接口准备，但不允许用接口拦截冒充业务响应。

### 来源派工

#### 验收

- 另行启动配置 `json-file` 来源的 Server 后，来源目录、条目与派工在浏览器内可操作，派出的单据出现在同一工作清单并显示来源、条目与获准动作。
- 页面的固定动作只列出该来源获准的动作，即使工作包快照里有其他动作也不提供。

### 环境隔离与复跑

#### 验收

- 每次运行使用独立的临时数据目录、独立回环端口和新生成的令牌，服务进程只继承白名单环境，不继承操作者的模型凭据。
- 运行结束后停止本次启动的进程组并删除临时业务数据与私有来源文件，同一台机器可重复复跑。
- 一条 npm 命令完成构建、启动与全部场景；场景失败时保留日志、截图与追踪，断言实际观察值写入报告。
