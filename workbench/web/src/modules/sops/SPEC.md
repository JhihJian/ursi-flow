# SOP 管理

## 功能意图

维护回执型 SOP 的已发布修订，让经办人在工作区绑定前查看每版配置，并从任一版发布新版。

## 关键功能与验收

### 修订目录与配置

#### 验收

- `/sops` 读取 `GET /sops`，按 SOP 标识分组列出全部已发布修订，显示回执标题、标识、修订号和执行器，最新修订带标记。每项进入 `/sops/:id/revisions/:revision`，分组标题旁提供 `/sops/:id/revisions`。
- 读取失败显示故障与重试，成功但无修订时显示空态，并提供 `/sops/new` 入口。
- `/sops/:id/revisions` 从同一集合中筛出该标识的修订，按从新到旧排列，标记最新版，可从最新版发布新版。
- `/sops/:id/revisions/:revision` 显示该修订的固定配置：标识、修订号、执行器和回执标题，并说明回执标题只写在回执开头，不是 SOP 正文。历史修订标明当前最新修订号，并说明发布新版不会修改旧修订与已有工作区绑定。
- 打开不存在或非法的修订显示未找到，并提供回到该 SOP 修订列表的入口。`/sops/:id` 打开该 SOP 的修订列表。

### 发布与校验

#### 验收

- `/sops/new` 发布新 SOP；`/sops/:id/revisions/:revision/edit` 读取该固定修订并预填标识与回执标题后发布新版。标识在基于旧版时只读，新版沿用同一个 SOP。
- 执行器用选择器呈现，只显示该执行器的适配字段。当前只有内置 `echo`，适配字段为回执标题，页面说明它用于回执抬头而不是 SOP 正文。
- 标识只接受 1 至 80 个字母、数字、短横线或下划线；回执标题去除首尾空白后不能为空、必须单行且不超过 256 字节。本地校验与服务端规则一致，错误提示不提交请求。
- `POST /sops` 只发送 `{id, executor, config:{title}}`，不发送修订号。成功后进入响应给出的 `id` 与 `revision` 页面，不使用本地推断的修订号。
- 发布失败或校验失败保留已填内容并显示错误，成功后不再保留草稿。请求进行中不能重复提交。
