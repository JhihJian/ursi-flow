# 派工记录

## 功能意图

为经办人和验收人提供可筛选的工作项入口，并从已发布的派工模板版本发起待办理工作项。派工只创建单据，执行与交付由详情页负责。

## 关键功能与验收

### 清单与状态筛选

#### 验收

- `/items` 按全部、待办理、办理中、待验收和已交付查询服务端工作项；筛选是链接，地址里的 `status` 是唯一状态来源，刷新和前后翻页保持同一筛选。
- 每行一个链接，同屏可读到派工模板与版本、单号、来源、经办人和业务状态；窄屏逐项带名称，宽屏由表头承担同样的说明。
- 行链接带上当前 `status`，从详情返回时回到原筛选。
- 成功的空数组显示空态并给「发起工作」入口；加载失败显示故障和重试，不把故障误报为空态。

### 从模板版本发起

#### 验收

- `/items/new?package=...&revision=...` 以地址里的模板和修订为准：该修订在模板的修订列表里就用它，否则用最新版；选择模板或修订会改写地址，表单按版本重新加载而不沿用上一版的草稿。
- 表单展示所选版本的办理说明、验收标准、交付物和输入声明，只提交 `requestId`、模板、修订和输入。
- 字符串、数字、整数、布尔值、对象和数组按声明转换。空文本不是 `0`，`false` 和 `0` 是有效值并照常提交；错型在字段旁说明，已填内容保留，改正后才能提交。
- 布尔输入默认 `false` 并始终随请求发送，不会被当作缺失字段。

### 防重与失败处理

#### 验收

- 请求标识按模板、修订和输入的完整内容生成：同一组参数在响应丢失或可重试失败后沿用同一个 `requestId`，改动任一参数生成新标识。
- 提交进行中按钮禁用且重复触发只发一次请求，离开页面后迟到的响应不再跳转。
- 成功用服务端返回的标识进入 `/items/:id`；服务端冲突和其他故障保留全部表单内容并显示错误，不跳转到未知工作项。

### 目录缺失与停用

#### 验收

- 目录加载失败显示故障和重试。没有启用中的派工模板时显示空态并提示联系管理员，不显示空表单。
- 深链指向已停用或不存在的派工模板时说明原因并拒绝派工。存在其他可用模板时可就地改选。
