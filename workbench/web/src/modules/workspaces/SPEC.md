# 工作包

## 功能意图

让经办人按需求创建工作包，准备各角色材料，执行时从全部已发布 SOP 版本中显式选择，并查看每次尝试使用的版本与回执。工作包数据与工作项、工作包定义互不影响；创建和准备阶段不绑定 SOP。

## 关键功能与验收

### 列表、新建与版本目录

#### 验收

- `/workspaces` 读取 `GET /workspaces`，逐项显示需求、类型名称、材料数、执行次数、最近尝试状态和是否冻结；每项进入 `/workspaces/:id`。页面、空态和操作入口统一使用「工作包」称呼。
- 列表加载失败显示故障和重试；成功空列表显示空态并给 `/workspaces/new` 入口。
- `/workspaces/new` 读取 `GET /workspace-types`，只提供类型选择和需求输入，并展示所选类型的角色标签；不读取 `GET /sops`，也不展示 SOP。需求为空不能提交；提交 `POST /workspaces` 的正文只含 `typeId` 和 `requirement`。
- 创建成功后进入新工作包的准备页；创建失败保留已填需求并显示错误。类型目录为空或故障不显示空表单。
- 准备页和结果页共用独立的执行控件，读取 `GET /sops` 返回的全部已发布版本并以下拉选择。默认选中本类型推荐的 `sop` 引用，允许显式换版；目录读取失败时只在执行区报告并禁用执行，需求编辑和材料上传不受影响。
- 客户端路径保持 `/workspaces`、`/workspaces/new`、`/workspaces/:id` 和 `/workspaces/:id/result`。

### 需求、材料与冻结

#### 验收

- `/workspaces/:id` 读取详情，显示类型、角色和已有材料名称与大小；详情没有顶层 `sop` 字段。
- 保存需求调用 `PATCH /workspaces/:id`，正文只含 `requirement`；空白需求不能保存，失败保留草稿。
- 每个角色可选择一个文件，上传调用 `PUT /workspaces/:id/materials/:role?name=<编码后的文件名>`，正文是文件原始字节，不使用 JSON 或表单编码。
- 已上传的角色在首次执行前可撤回：调用 `DELETE /workspaces/:id/materials/:role`，成功后该角色回到未上传状态并可重新上传；其他角色材料不受影响，失败保留原材料并报告原因。
- `frozen` 为真时需求文本框、保存、上传和撤回都不可用，并明确说明仍可执行；未冻结时才允许修改需求和材料。
- 任何请求进行中都不重复提交；401 沿用共享客户端的登录处理。

### 执行与回执

#### 验收

- 准备页执行时，需求有未保存修改则先保存，保存失败不发起执行；随后以执行控件选中的版本调用 `POST /workspaces/:id/attempts`，正文为 `{sop:{id,revision}}`，并进入结果页。
- 每次尝试保存当时的完整 `sop` 快照。结果页按尝试展示各自使用的 SOP 标题、标识和修订号，重跑可换版而不改变旧尝试的版本。
- 执行失败也读取服务端保存的失败尝试，不在页面上丢弃记录；冻结后仍可再次执行。
- 结果页保留全部尝试历史，并可从执行控件显式换版再次执行。
- 回执内容按 `GET /workspaces/:id/attempts/:attempt/receipt` 读取 `text/plain` 并显示原文；读取失败只影响该次回执。
- 下载回执复用鉴权读取，再以 `receipt.md` 交给浏览器保存；非文本、空正文和页面响应都按读取失败处理。
