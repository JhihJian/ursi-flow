# 工作包与配置包编辑器

## 功能意图

用户只需要包名和文件内容。每个包是一条记录，记录里带一个目录标识；工作包与配置包分别保存，内容统一交给虚拟目录管理。经办人可用已发布的执行器修订运行工作包。

## 关键功能与验收

### 包记录与目录

#### 验收

- `GET/POST /api/v2/patches/{kind}` 的每项为 `{id,name,directoryId}`。新建只提交 `name`，包标识与目录标识都由服务端生成。
- 文件型工作包按 `workItemId` 显示当前归属，详情中可关联、改绑或清空；仅提交新归属，不改文件和生成来源。来源面板保留生成时的工作项标题、修订和资源摘要。由生成器创建的包可从来源面板打开原运行，链接在当前归属变更或清空后继续可用。归属操作仅面向工作包。
- 工作包列表显示来源、创建时间、是否已执行及执行结果。名称进入目录，独立的「执行详情」按钮暂未设置链接，保持禁用。配置包列表不显示执行字段。
- 编辑台按记录的 `directoryId` 打开目录：深链与切换都从包列表解析记录，新建直接使用创建响应里的记录，不自行拼装目录地址。
- 列表读取失败显示可重试错误。地址里的标识既不在列表中也不是刚创建的记录时显示找不到包，不向未知目录发起请求。

### 在包内查看与编辑

#### 验收

- `/work-patches` 可创建空包，桌面查看树及编辑区，窄屏可从文件列表进入编辑器再返回。上传和目录导入保留文件内容和相对层级。
- 显式保存后重读同一文件可得到原文。二进制材料可取回，不经文本解码再保存。

### 选择执行器并运行工作包

#### 验收

- 工作包列表和包详情的「运行工作包」都进入 `/work-patches/:id/execute`。配置包没有运行入口；浏览列表、编辑包时均不读取执行器目录或修订。
- 执行页先查询该 ID 的工作包记录。不存在时提示找不到工作包，读取失败可重试；两种情况都不加载执行器或运行面板。执行页不读取包内文件、配置包或工作项。
- 只列出启用的执行器。选中一个执行器后才加载它的全部已发布修订，包括旧版；目录或历史加载失败可重试。按版本运行需要 Agent 快照。通用修订显示为不可选，不影响同一执行器的旧 Agent 修订。切换执行器立即清除上一个修订，未选定可运行修订时不能启动。
- 切换到「启动 Flow」才读取可用流程；须选定 Flow 和 Agent 修订才能启动，成功进入返回的运行详情。直接执行模式不依赖 Flow 可用。
- 运行面板接收选定的 `{id,revision}` 和当前 `workPatchId`，负责本次指令、请求和结果。面板存储按工作包隔离。

### 配置文件视图

#### 验收

- 打开配置包默认选中首个标签「总览」，使用与工作包相同的根目录资源管理器。总览与专用视图查看同一份文件；切换时可取消放弃草稿，已保存内容在另一视图可见。
- `/config-patches` 独立创建和选择配置包。系统提示词保存在 `AGENTS.md`。Skills 源自 `skills/` 下的目录。MCP 内容保存在 `mcp.json`，错误 JSON 不能覆盖已有文件。
- MCP 页可直接选择受管模型和获准的只读工具，也可使用平台默认模型。选择写入当前 `mcp.json` 草稿，显式保存后对新试跑和新发布生效；执行器页只选配置包。
- 两种页面通过同一鉴权的虚拟目录客户端，按各自记录的 `directoryId` 访问包根相对路径，不创建执行记录。
- 执行器配置选择器复用配置包列表接口，但使用窄 API 只暴露 `{id,name}`。`directoryId` 只属于配置包编辑台的目录访问边界，不渲染到配置选择器、不作为宿主路径展示，也不进入执行器配置发布请求。
