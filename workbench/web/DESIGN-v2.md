# Web v2：工作清单与办理详情

本文记录派工办理路径的原始目标结构。下文历史名称「工作包」在当前界面称为「派工模板」；手动工作包和独立 SOP 的入口及职责见[工作领域设计](../WORK-DOMAINS.md)。现有页面见 [Web 工作台设计](DESIGN.md)，实体归属见 [Server 规格](../server/SPEC.md)。登录后的首页是工作清单：经办人从这里找到要办的单，验收人切到「待验收」即可打开交付物。两者使用同一张工作项详情，看到同一套材料和标准。

## 导航与页面层级

| 导航分组 | 页面 | 进入详情后 |
| --- | --- | --- |
| 日常工作 | **工作清单**（默认） | 一行一张单。选择一行进入办理详情；「发起工作」按已发布包版本开单。 |
| 日常工作 | **外部来源**（可选） | 来源列表 → 来源条目 → 预设动作 → 新工作项。来源可定制列表列和条目布局，派工统一进入工作清单。 |
| 工作定义 | **工作包** | 查看某一版本的目标、SOP、输入、动作、交付物和验收标准；从该版本发起工作，或编辑后发布新版。 |
| 工作定义 | **资源库** | 按 Skill、提示词、MCP 引用筛选；详情展示内容、当前状态及历史版本。 |
| 工作定义 | **执行器** | 查看执行器版本、workspace 与 workInstruction 契约、资源依赖、artifactDirectory 能力和环境策略；跳到固定的执行器过程日志页或后端详情。概念与结构见[执行器设计](../EXECUTOR-DESIGN.md)。 |
| 运行工具 | **Flow 工具**（可选） | 集中现有 Flow 包编辑、运行历史和运行配置。保留 `/flows`、`/runs`、`/flow-config` 的深链。 |

本地对话保留为单独标注的演示入口。它不出现在工作项的动作列表中。导航在桌面用侧栏，移动用现有抽屉。工作项、定义版本和交付版本可深链，登录后返回原位置。

## 工作清单与发起

清单顶部是「全部｜待办理｜办理中｜待验收｜已交付」筛选和主按钮「发起工作」。桌面表格展示工作项标识、工作包及版本、来源、经办人、业务状态；移动列表优先保留工作包、单号和状态。经办人是办理时填写的姓名，部署令牌不代表个人身份，因此首版不提供「我的待办」。空清单提供发起入口，加载失败留在原页重试。

发起表单先选工作包版本，展示其 SOP 摘要和验收标准，再按输入声明填写材料，确认后创建待办理工作项。没有可用包时，提供进入工作包目录的链接。派工请求响应丢失时，相同参数沿用原 `requestId`。来源条目派工则显示服务端公布的动作名和条目材料；包绑定由服务端决定，页面不提供替换包、执行器或材料的控件。两种派工都只创建单据，执行需要另行发起。

## 工作项详情

页首常驻工作包名称与派工版本、单号、经办人和**工作项状态**。正文设三个页签，默认随状态落位：待办理和办理中进入「办理」，待验收和已交付进入「交付与验收」。从清单返回时保留此前的状态筛选。

| 页签 | 展示顺序与主要操作 |
| --- | --- |
| **办理** | 先看本次输入与来源，再看开单时的 SOP、交付要求及固定动作。待办理显示「开始办理」和经办人字段；办理中可选动作、核对绑定的执行器版本并「执行一次」。来源派工单只显示获准动作。 |
| **执行记录** | 一行一次尝试，展示动作、执行器与版本、workspace、artifactDirectory 和尝试状态。进入执行详情后先看平台记录日志，再看执行器记录日志和制品目录；日志查看器暂留空位，Flow 可打开对应 Run 的节点历史。 |
| **交付与验收** | 并排展示包快照中的验收标准和所选交付版本的文本文件，小屏改为上下排列。办理中可提交文本文件并关联本单尝试；有活动或待核实尝试时显示原因及对应记录。待验收只对当前版本提供「通过」「退回」，退回须填意见。旧版只读，保留文件、意见；已交付时标出通过的版本。 |

例如，同一张工单上可以同时看到「办理中」和「分析原因：执行成功」。经办人还需提交报告；待审报告被退回时，详情页回到办理状态并显示退回意见，第二版报告仍提交到同一单。若另一人已经验收，迟到的操作收到冲突后重读工作项，保留用户未提交的文字，不把旧版意见自动发到新版。

## 工作定义与运行边界

三类定义共用「目录 → 指定版本 → 发布新版」结构。行内明确区分对象是否启用与正在阅读的版本。工作包动作直接展示如「分析原因 → 排查助手 v2 → 日志 Skill v1」的绑定关系。旧单详情始终读 `packageSnapshot`，查看目录最新版是独立操作。停用前提示会阻止新派工，已发布历史仍可查。

Agent 执行器显示本地或预配沙箱；Flow 执行器显示 `flowId` 和固定目录修订。MCP 当前仅展示命名引用，禁止作为可执行依赖发布。PTY、浏览器、通用文件管理和云端沙箱供应不设页面。来源首版支持管理员配置的 JSON 导出，不在浏览器中编辑连接或凭据。

新业务页访问同源 `/api/v2`，Flow 工具继续使用 `/api/v1`。沿用现有 Bearer 登录和退出处理。可选模块仅在其集合接口明确未挂载时收起入口；401 进入登录，服务故障显示错误和重试入口，成功返回空列表才显示空态。派发动作后按尝试 ID 读取执行详情；若启动响应丢失，先查本单尝试，不自动再次执行。`unverified` 显示「待核实」并提供核实入口，要求填写证据、原因，只允许后端支持的结论。

## 首版浏览器验收

使用真实 Server，在浏览器内发布一项资源、一个执行器和一个工作包，从同一包版本发起两张单。发布包新版后，两张旧单仍显示原 SOP 和验收标准。两单分别执行并提交文本报告，一单通过，另一单退回后重新提交。刷新详情，确认第一单仍是已交付，第二单两版文件及退回意见可分别打开。关闭 Flow 和来源扩展后，本地 Agent 仍可完成同一条办理路径。
