# 05 办理与验收：在原单上办完、退回并重交

**用户结果：** 经办人按开单时的要求执行工作，验收人依据同一版标准审阅实际报告。工具执行成功只说明某次尝试完成；一张工作项是否交付，取决于具体交付版本的验收结论。

**接手材料：** [工作项接口](../../../server/src/work/items/HTTP.md)、[执行尝试与核实](../../../server/src/work/execute/API.md)、[页面设计](../../DESIGN-v2.md)。负责 `web/src/modules/work-detail/`、模块规格和测试。三个页签与部分组件测试已有草稿。可用待办理、办理中、待核实、待审和已退回的预置工作项独立验收。01 提供版本化纯文本读取，03/04 只需传入工作项 ID。

**验收与证据**

1. `/items/:id` 按业务状态定位「办理」或「交付与验收」。工作项显示派工快照，不取目录最新版；来源单只展示获准动作。本地、Flow、沙箱均按后端已提供的信息呈现。
2. 点击执行一次，后端已受理但浏览器断线时，只查原单尝试，不自动重发。取消以实际结果为准。`unverified` 显示待核实、阻止交付，提交核实需要依据，不能把它标成成功。
3. 交付有两份文件时，两份均成功读取才提供验收操作。让一个文件返回 HTML、空响应或读取错误，页面说明哪份不可读，不能发出通过请求。此项与 01 的纯文本响应校验配合，可用替身单独验收。
4. 仅当前待审版本允许通过或退回，退回需理由。旧页迟交验收遇 409 后刷新状态、保留填写内容，不把意见自动附到新版。在 `/items/:id/deliveries/:version` 刷新仍显示对应版本的文件与意见。
5. 交回成功、失败、取消、待核实与退回重交的状态证据，以及桌面/窄屏的关键操作。PTY、浏览器远控、聊天式输出及沙箱供应不在此包内。

**需裁决的跨端并发边界：** 验收接口已有版本约束，提交新版交付的接口却未要求“起草时看到的最后交付版本”。双标签页中，A 起草，B 提交 v1 后又被退回，工作项重新成为 `working`，A 的旧稿可能直接成为 v2。先用两标签页复现并保留证据。建议由产品和 Server 负责人决定是否增加原子版本前置条件；若采纳，约定冲突时不写新版本、保留草稿并展示最新退回意见。若暂缓，发布说明明确剩余风险。仅在提交前刷新页面不能保证消除竞态。本工作包不授权直接改变服务端协议。
