# 04 来源派工：把外部条目带入统一工作清单

**用户结果：** 操作者查看一个外部条目的材料，从允许的动作中选一个，开出可追溯的待办理单。来源页面决定如何展示，管理员的配置决定按什么包和动作派工。

**接手材料：** [来源契约](../../../server/src/work/sources/SPEC.md)、[JSON 来源配置示例](../../../server/src/work/sources/README.md)。负责 `web/src/modules/sources/` 及模块测试与规格。已有列表、条目和派工页面草稿，暂停时派工按钮未调用处理函数，条目“刷新”是否真正重读需要复验。

**接口与边界：** 页面从 `/sources` 进入。根据来源、条目与动作访问固定派工端点，请求体只包含 `requestId` 和 `action`。返回 ID 后进入 `/items/:id`。01 决定是否显示来源导航，05 限制该单可执行的动作。首版只验收管理员提供的 JSON 导出，凭据、路径和映射不在浏览器配置。

**验收与证据**

1. 准备含两条记录的导出文件，检查列表、详情、动作名称。替换文件后手动刷新，详情显示新材料；之前派出的单仍保留旧材料。
2. 点击允许的动作，在通用工作清单找到该单，来源标识、条目 ID、动作及包版本正确。请求无客户端指定的包、执行器或输入。新单没有执行记录。
3. 模拟派工收到后响应丢失；原请求重试只产生一单。若其间服务端材料变化导致冲突，页面要求重新核对，不静默改参数再派。列表为空、条目已删除、来源不可用三种情况可区分。
4. 提交一次来源到通用详情的操作记录及刷新、重试的请求断言。可用独立测试路由和私有导出文件验收，第三方在线连接与定制平台页面另行立项。
