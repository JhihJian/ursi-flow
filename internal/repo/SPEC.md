# internal/repo

## 功能意图

repo 是持久化层。它定义存储接口并基于 SQLite 实现，负责工作流定义、角色、运行与节点状态、观测事件的持久化，保证状态提交的一致性。上层模块只依赖存储接口，不直接依赖 SQLite 实现细节。

## 关键功能与验收

### 存储接口

定义领域对象的存储接口：工作流与角色的读写、运行与节点状态的读写与更新、观测事件的追加与查询。engine 与 api 通过该接口访问持久化。

#### 验收

- 存储接口覆盖工作流、角色、运行、节点状态、观测事件的创建、读取、更新、查询。
- 接口实现可在测试中替换为内存实现，用于隔离测试引擎逻辑。

### SQLite 实现

以 SQLite 为默认实现：启用 WAL 与 busy_timeout 支持并发读写；表结构与迁移幂等，重复执行迁移不产生错误。

#### 验收

- 启动时自动建表，重复启动不报错。
- 并发读写运行状态不丢失更新、不报锁错误。
- 数据持久化到磁盘，进程重启后读回一致。

### 状态提交一致性

节点状态更新与观测事件追加在同一事务中提交，避免状态已更新而事件缺失，或事件已存在而状态未变。状态提交携带运行代数守卫，拒绝过期写入。

#### 验收

- 提交节点状态与事件时，二者要么同时成功要么同时失败。
- 携带过期代数的状态更新被拒绝，不覆盖新状态。
