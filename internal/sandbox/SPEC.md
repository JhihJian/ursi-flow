# internal/sandbox

## 功能意图

sandbox 是 kernel 侧的执行环境接入层。它面向 engine 提供环境句柄（domain 的 `ExecutionEnv` 实现）与生命周期编排：经 gateway 控制面创建与释放沙箱，经运行面端点直连沙箱完成命令执行、输入注入、输出与产物收集，并管理沙箱内 git 仓库工作区（clone、输入落位、产物回收）与凭据注入。它也是 gateway 控制面 REST 契约在 kernel 侧的客户端实现。

模块内含 `SandboxControl` trait 的两个实现：gateway HTTP 客户端（生产形态）与 in-process fake（无 Docker 环境的开发与 engine 测试），二者同一接口，engine 不感知差异。

## 关键功能与验收

### gateway 控制面客户端

封装 gateway 契约 C1（生命周期 REST）：创建、查询、启动、停止、删除沙箱，凭据与镜像规格透传。响应解析与错误映射与 gateway 契约一致；契约结构由 golden JSON fixture 双侧锁定。

#### 验收

- 向 fake gateway（in-process）发起创建，能拿到受理响应并轮询到 running 与端点。
- 对 404/409/501 错误的映射与 gateway 契约一致，契约 fixture 变更时双侧测试同时失败。

### 环境生命周期编排

节点执行前确保环境就绪（沙箱 running、工作区就位），执行后收集输出与产物，运行结束释放环境。释放失败不阻塞运行终态，残留资源由 gateway 侧对账清理。

#### 验收

- 节点执行前环境已启动且输入就位；节点完成后输出与产物被收集。
- 运行结束（成功、失败或取消）后环境被释放；fake 实现下可断言释放调用发生。

### 工作区与输入输出

提供沙箱内 git 仓库工作区的准备（clone / 复用），把输入（上游产物、运行上下文）写入工作区约定路径，并从约定路径读出产物。文件不存在时返回明确错误。

#### 验收

- 写入输入后，环境内指定路径出现输入内容。
- 读取输出返回环境中产出文件内容；文件不存在时返回明确错误。
- 两个并行运行使用不同工作区，互不写入对方目录。

### 凭据注入与脱敏

把执行器运行所需的凭据（模型 Key、MCP 凭据、git 凭据）经沙箱创建规格注入环境，凭据值不落入产物、日志与上报事件的明文。

#### 验收

- 凭据注入后执行器可在环境内读取使用。
- 输出、日志与上报事件中不包含凭据明文。
