# internal/executor

## 功能意图

executor 是执行器抽象与适配层。它定义统一的执行器接口，把单次过程的输入与能力配置交给具体执行器运行，并把不同 agent CLI 适配为统一协议。executor 只负责「如何启动与解析某个 CLI」，能力定制（提示词、模型、Skills、MCP）是角色的属性，executor 负责把这些属性渲染为该 CLI 可用的配置。

## 关键功能与验收

### 执行器统一接口

定义 `Runner` 接口：接收输入（提示词、上游产物上下文、运行上下文）与配置（模型、Skills、MCP、凭据），返回结果（输出、产物、用量、错误）。engine 仅依赖该接口，不感知具体 CLI。

#### 验收

- `Runner` 接口可被 engine 依赖调用，具体执行器实现该接口。
- 执行成功返回输出与产物；执行失败返回非空错误。

### 能力配置渲染

把角色能力定制字段渲染为具体执行器可消费的配置：提示词写入任务描述，模型与思考强度转为 CLI 参数，Skills 物化为技能文件，MCP 工具渲染为 CLI 的 MCP 服务配置。

#### 验收

- 给定一个含模型与 MCP 工具的角色，渲染后生成的 CLI 配置包含对应模型参数与 MCP 服务条目。
- 给定含 Skills 的角色，渲染后在执行环境中物化对应技能文件。

### 执行器适配

内置 mock 执行器（确定性输出，用于测试与演示）与至少一个真实 agent CLI 执行器。新增执行器通过实现 `Runner` 接口接入，不改动 engine。

#### 验收

- mock 执行器返回预设的确定性输出，用于端到端验证调度逻辑。
- 真实 CLI 执行器能启动 CLI、传入提示与配置、解析输出为统一结果。
- 新增一个执行器适配器无需改动 engine 与 domain。

### 流式事件上报

执行过程中把工具轨迹与日志以 domain 的 `TelemetryEvent` 契约上报给事件接收方，供过程可观测使用。

#### 验收

- 执行器运行期间产生的工具调用与日志以 `TelemetryEvent` 形式持续上报。
- 事件上报不影响执行器的最终结果返回。
