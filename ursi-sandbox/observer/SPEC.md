# 沙箱网络观测服务

## 功能意图

`ursi-observer` 是 Docker 宿主机上的可选 Linux 服务。管理员可经配对的 Gateway，针对一次容器运行采集网络报文，并在采集结束后取回 PCAP。观测不改变沙箱的能力、网络路径或工作区。

## 关键功能与验收

### 锁定采集目标

服务仅监听专用目录内的 Unix socket。开始采集时，固定目标的进程句柄和网络命名空间，再向同一本机 Docker daemon 核对容器身份、运行状态、PID 和启动时间。

#### 验收

- 同一目录只允许一个 Observer 持有者，同一沙箱同时最多有一次活动观测。
- 仅接受 Gateway 供应的独立默认桥接容器。宿主网络命名空间、共享网络模式或无法确认目标仍是该次运行时，开始请求返回冲突。容器退出后原观测结束，不跟随重启或重建后的容器。

### 写入分段 PCAP

采集线程进入目标网络命名空间，在全部接口上接收报文，不按端口或协议过滤。每段是独立的 Linux cooked v2（SLL2）PCAP；TLS 载荷保持密文。

#### 验收

- 正常结束后，分段从 1 编号，各有自己的 PCAP 文件头（链路类型 276）。`bytes` 包含文件头与记录头，各段总大小不超过单次观测配额。
- 配额不足以写入下一批记录时以 `limited` 结束。内核缓冲丢包和用户态队列丢包分别计入 `kernel_drops`、`queue_drops`；观测到丢包或截断时可见 `degraded`。无过滤不构成零丢失保证。

### 结束与取回

记录以沙箱 ID 和观测 UUID 定位，独立于 Gateway 数据库及沙箱卷。Observer 保存状态快照，调用方用同一组 ID 停止、查询和下载。

#### 验收

- 活动时请求停止返回 202，表示停止请求已受理，下载返回 409。正常收尾后可再次停止并取得终态，按段号下载已有文件；不存在的段返回 404。`error` 终态可读取已有分段，文件可能仅含写入成功的前缀。
- Observer 异常退出后，用原目录重启。若租约已释放且快照没有结束时间，查询返回 `interrupted`，不续采。分段数从目录恢复，报文和丢包计数仍来自最后一次快照，最后一段可能不完整。
- 删除沙箱后，只要观测记录还在且 Gateway 仍连接同一 Observer，持有 ID 的管理员仍可查询和下载。服务不按时间或磁盘水位清理历史。
