# ursi-sandbox

## 功能意图

为独立工具和工作流引擎提供同一种可回收的执行环境。调用方拥有任务的业务含义，沙箱拥有资源和执行状态。交付包括 Gateway、Runtime、Client、可选的[宿主机网络观测服务](observer/SPEC.md)和独立的[沙箱管理控制台](web/SPEC.md)。

## 关键功能与验收

### 独立构建与交付

沙箱独立锁定构建依赖。镜像提供系统程序，bundle 提供会话服务和监督配置，管理员在运行时供应最小配置。

#### 验收

- 只取本目录，在具有 Linux 构建工具和依赖的机器上能按锁文件构建 Gateway、session-service、Client 和 Observer 四个二进制并打包 bundle，不需要 Flow 源码、数据库或服务。
- 镜像和 bundle 不包含管理员模型凭据、SSH 私钥或服务令牌。

### 公共协议执行

Gateway 负责供应和回收，Runtime 负责会话。客户端通过 ACP WebSocket 子集提交文本任务，SSH/SFTP 独立访问工作区。

#### 验收

- 已准备工作区后，客户端可创建会话、收到文本及完成响应、显式关闭会话。断线不能视为任务完成或允许重放。
- 重启沙箱保留数据；显式删除后所属容器与数据卷释放。应用层的角色选择、审批、重试和产物归属不进入沙箱协议。

### 按需观测网络

管理员可为一个 Docker Gateway 单独配对一个 Observer。观测在宿主机执行，不随沙箱创建而自动开始。

#### 验收

- 不配置 Observer 时，沙箱生命周期保持可用，观测接口对合法管理请求返回 501。
- 启用后，管理员能为运行中的沙箱开始观测、按 ID 停止采集，并下载已结束观测的 PCAP 分段。删除沙箱不清理观测历史。
