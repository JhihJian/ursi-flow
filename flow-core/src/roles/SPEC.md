# roles

## 功能意图

roles 管理供流程节点选择的角色定义，交付系统提示词、完整 Skills 文件包、结构化 MCP 配置、执行器和模型连接选择。
通过 storage 持久化本域数据，使用 domain 的共享契约。角色拥有配置及技能内容，节点产出物声明和审批规则归工作流定义。

## 关键功能与验收

### 角色创建、查询与修改

提供角色创建、列表、详情和修改接口，统一保存系统提示词、执行器选择和能力配置。
配置以完整定义提交，校验失败时保留原定义及其关联资源。

#### 验收

- 创建包含全部配置的角色后，列表可发现该角色，详情及重新打开存储后的读取结果一致。
- 修改提示词与能力配置后读取新值，查询未知角色返回明确的不存在结果。
- 提交非法配置时返回字段级原因，原定义及已保存资源保持一致。

### Skills 完整文件包与 MCP 配置

Skills 保存入口说明及其引用的脚本、模板和资源文件，包内相对目录结构随角色一起读取。
MCP 区分 stdio 命令参数与 HTTP 连接参数，敏感参数使用凭据引用，包内路径必须处于受控根目录。

#### 验收

- 写入含说明、脚本和嵌套资源的 skill 后，读取每个文件的路径和字节内容均与输入一致。
- 新角色的文件包须包含入口；缺少入口、重复文件路径、目录穿越或可逃逸的链接被拒绝。历史 `runtime-acp` 角色的空文件包仍可读回。
- 合法 MCP 配置保存后完整读回，非法字段或明文敏感参数被拒绝，错误信息保持脱敏。

### 模型连接选择

角色以连接标识和模型选择引用 connections，保存时校验连接存在性及可用的运行时能力描述，在同一事务中维护连接引用登记。
角色持有可供快照冻结的配置与凭据引用，凭据实体由 connections 的受控解析入口管理。

#### 验收

- 选择存在且能力匹配的连接后保存成功，详情返回连接标识和模型选择。
- 用于 Runtime 文本执行的角色显式选择 `pi` 和实际模型名。连接仍作为角色元数据校验与登记，模型服务地址与凭据由 Runtime profile 配置。
- 历史 `runtime-acp` / `runtime-profile` 定义可查询；通过 Server 写入该旧执行器类型时返回迁移冲突。
- 连接缺失或明确不支持所选能力时返回可定位原因，角色修改整体回滚。
- 更换、复制或删除角色时，连接引用登记与角色写入同事务提交，失败后一并回滚。
- 读取和导出角色定义时，DTO、日志及可冻结配置均不包含凭据明文。

### 角色复制与定义交付

复制生成独立角色标识，并复制完整提示词、Skills 内容和 MCP 配置，保留模型连接引用。
向运行创建方交付可冻结的完整定义与稳定内容引用，旧运行使用的内容由快照保留规则保护。

#### 验收

- 复制后两份角色初始配置等价，修改副本的提示词或文件不会改变源角色。
- 复制过程中内容保存失败时，查询不到缺少文件的副本。
- 冻结所需的定义导出覆盖全部文件与配置，后续角色编辑不改写已交付的内容对象。

### 引用登记与删除约束

roles 提供角色存在性检查、引用登记与解除登记接口，以及基于登记记录的删除检查。
调用方传入 storage 事务，流程定义保存与引用登记共同提交；角色删除在事务内检查已登记引用。
登记以引用方标识定位，重复登记保持幂等，roles 通过登记记录识别引用方。

#### 验收

- 无引用角色可以删除，被登记引用的角色删除返回冲突并保留完整定义与文件。
- 同一事务内登记后回滚，角色引用状态恢复原值；重复登记不会产生重复引用。
- 解除指定引用只影响对应登记，其他引用继续阻止角色删除。

## 交付与验收边界

- 独立环境使用临时 SQLite、临时内容目录和连接查询替身，运行真实 roles 与 storage 的存储路径。
- 独立交付覆盖 CRUD、完整文件包、结构化 MCP、复制、连接校验、登记及删除冲突。
- workflows 通过本模块登记接口维护流程引用，两者共享 storage 事务，roles 的依赖方向保持独立于 workflows。
- runs 或 server 的 app 组织真实 workflows、roles、storage 联调，验证并发删除角色与保存流程引用后不存在悬空引用。
- runs 或 server 的 app 组织快照联调，验证角色修改后旧运行读取旧定义与旧内容，新运行读取新定义。
- 凭据真实注入、执行器使用配置及快照旧内容保留由联合验收覆盖，替身结果仅证明本模块接口行为。
