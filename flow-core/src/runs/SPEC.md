# runs

## 功能意图

把可编辑的流程与角色配置变为一次可恢复、可审批、可观测的运行。拥有运行快照、节点状态、执行轮次、调度、租约与运行事件，engine 是本域内部实现。对外提供创建、启动、查询、取消、审批及事件读取服务。

## 关键功能与验收

### 运行创建与配置冻结

在一致读取事务中，经各域公开接口读取流程、角色和连接配置，固定角色能力、执行器与沙箱配置，保存完整运行快照。同一角色配置可被多个节点共享，节点输入、执行身份和会话各自独立。凭据保存引用。

#### 验收

- 给定合法流程和依赖配置，创建 queued 运行，可读回与创建时一致的完整快照。
- 修改或删除当前角色配置后，已创建运行仍使用原提示词、模型、技能内容和 MCP 配置。
- 执行器类型随角色冻结。生产 Server 仅分派显式 `pi` 文本角色；旧 `runtime-acp` 快照在准入时返回迁移冲突，补写当前角色不改变旧快照。生产路径不回退到 mock。
- 缺失角色、无法固定的技能内容或不支持的执行能力使创建失败，不产生可启动的半成品运行。
- 并发编辑配置时，生成的快照来自同一个一致性视图；快照、响应和事件中不出现凭据明文。

### 顺序执行与输入交接

按 DAG 依赖逐个调度就绪节点，agent 经 Agent Runtime 执行，script 经沙箱文件与命令入口执行。下游仅接收当前有效执行轮次的上游产物。

#### 验收

- A → B → C 运行中，记录型执行器按顺序各收到一次调用，全部成功后运行 succeeded。
- runs 的工作区执行器接收 run、node、generation、attempt、脚本语言和产物声明。它在该轮次的独立工作区执行脚本，随后读取声明文件并按该轮次身份提交给 artifacts。非零退出或命令报错时也收集输出，归档成功不改变脚本失败结果。
- 给定声明的必需产物缺失，节点失败，下游不执行。
- 脚本节点成功时，引擎只将执行器实际返回且与声明匹配的产物记入本轮归属和成功事件。未生成的可选文件不算本轮产出。
- 不同节点引用同一角色时配置一致，任务输入和会话身份不会串用。
- 任一节点最终失败时运行 failed，终态之后不继续调度新节点。

### 审批、重试与返工

审批节点进入 waiting_approval 后等待放行或打回。打回目标必须为传递祖先，重置目标及其下游的当前执行状态。失败重试受 MaxAttempts 限制，返工受 MaxReworks 限制。节点累计执行编号 attempt 单调递增，独立于单轮重试计数，返工时不清零或复用。

#### 验收

- 到达审批节点后运行 waiting，下游保持未执行；放行后继续执行。
- 对非等待审批节点操作，或打回自身、非祖先节点，返回状态冲突或校验错误且状态不变。
- 合法打回后目标与下游重新执行，历史产物仍可查询，旧产物不会自动成为新轮次输出。
- 在同一持有代数内返工后，旧 attempt 的迟到状态、事件或产物不能覆盖当前执行结果。
- 重试或返工达到限制后进入明确失败终态，不无限重复。执行器返回 `DoNotRetry` 时立即记录节点与运行失败，即使尚有可用尝试次数也不再调用。

### 状态提交、租约与取消

通过同一提交入口检查持有代数并原子保存状态和事件。活动执行期间续约，租约到期后可接管。同一引擎内每次运行只由一个调度者推进，不依赖发起请求保持连接。取消停止新调度，等待当前执行确认结束。支持取消的 Runner 接收取消意图；Runtime 文本路径通过同一会话发送取消通知并等待确认。

#### 验收

- 过期持有代数提交状态或事件被拒绝，当前运行结果不被覆盖。
- 注入事务失败，状态和事件均不提交；成功提交后才通知订阅方。
- 使用可控时钟模拟租约到期，重开存储后可接管，恢复沿用快照。
- 恢复时对结果未知的执行先查询或核实，不直接重复提交任务。没有可核实结果的在途 ACP 节点（包括历史 `runtime-acp` 尝试）保留 `running`，不重放 prompt。
- 运行正在调度时，重复启动、审批或打回返回状态冲突，租约代数不变。发起请求断开不会释放调度权。
- 取消等待期间不提交取消终态，执行确认结束后才原子写入取消状态和事件，下游不再启动。
- 执行连接中断或只剩无法确认的活动记录时，不报告取消成功。

### 查询、事件与资源收尾

提供运行列表、节点状态、当前执行身份及按游标读取的有序事件。持久事件在 TelemetryEvent 外封装运行标识和单调序号，序号在提交时确定，提交、查询和广播使用同一记录身份。运行终止后请求释放资源，记录独立的清理结果。

#### 验收

- 查询能区分当前节点状态和历史尝试，事件可按运行及游标顺序重放。
- 无广播订阅方或广播接收滞后时，已提交事件仍可从存储读回。
- 提交后广播前崩溃，重启查询仍能读到状态和对应事件。
- 部分归档失败时保留原工作区。终态收尾先对该运行的待归档轮次重试，按原幂等键复用已提交产物，全部确认后才请求释放。重试不重新执行脚本。
- 待归档的工作区句柄只在当前执行器实例内有效。重启后仍可查询已提交产物和清理状态，但不能据此恢复待归档文件。
- 资源释放失败时运行执行结果保留，清理失败可查询并重试，不报告资源已释放。

## 交付与验收边界

独立交付使用真实临时 SQLite、可控时钟，以及流程、角色、连接、产物、沙箱和执行接口替身。公开服务入口可完成创建、执行、审批、返工、取消和恢复闭环，无需 Web、Gateway 或真实模型服务。Server-only 执行验收使用生产 HTTP assembly 的显式测试注入入口，模拟脚本工作区和资源释放：成功须先归档再释放，失败时已确认的文件内容仍可查询。

联合验收分三组：与配置域及 storage 验证并发快照；与 transport 验证 SSE 重放、断线补读与去重；与真实 Gateway、Channel、Agent Runtime、CLI Adapter 及 artifacts 验证配置生效、执行结果、产物回收和资源释放。调度替身、ACP 协议对端与正式 Runtime 的证据分别记录，适用版本及边界见 [ACP 验收说明](../../../server/REAL-RUNTIME-ACP.md)。
