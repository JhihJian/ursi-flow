# flow-core

## 功能意图

`flow-core` 是 ursi-flow 的平台业务核心 crate，拥有跨模块领域模型、工作流与角色配置、运行状态机、产物、沙箱关联、连接配置和持久化边界。它只表达业务规则和可替换端口，不发起 HTTP、SSH、SFTP、ACP 或 Docker 请求。

## 关键功能与验收

### 共享领域契约

提供工作流结构、角色能力、运行状态、执行输入输出、产物声明和观测事件等共享类型，并集中执行纯校验。

#### 验收

- 合法工作流、角色和产物契约可以解析并通过对应纯校验，非法节点、环、缺失引用或必需产物返回可定位错误。
- 运行状态与节点状态的合法流转由统一类型和校验函数表达，调用方不需要重复定义状态字符串。
- 执行端口、资源端口和事件契约不包含具体网络客户端、凭据内容或基础设施实现。

### 平台业务服务

提供 workflows、roles、connections、runs、artifacts、sandboxes 和 storage 的业务服务与存储实现。业务模块通过窄接口协作，保存配置引用、运行快照、状态事件、产物内容和沙箱关联。

#### 验收

- 流程定义与角色引用登记共享事务。创建运行时保存冻结配置，后续角色编辑不改写已保存的快照。
- runs 可以使用内存替身、临时 SQLite 和可控时钟验证顺序执行、审批、取消、重试、租约和结果未知语义。
- sandboxes 只保存平台侧关联与资源操作结果，真实 Gateway 和 Channel 通过端口注入，core 不持有线协议 DTO 或密钥。

### 可替换执行与资源端口

定义 Runner、ExecutionEnv、GatewayClient、ChannelGateway 和 ResourceReleaser 等端口，供 `sandbox-access` 或测试替身装配。端口失败必须保留可核实状态，不能把未执行或未确认的操作报告为成功。

#### 验收

- 使用测试替身可以验证执行、事件回流、资源准备和释放的成功、失败及未知结果，core 不需要启动外部服务。
- 连接中断与明确任务失败保持可区分，未知执行结果不自动重放。
- 释放端口返回失败时，运行结果保持不变，资源清理结果单独记录并可重试。
