# Flow Core

## 功能意图

提供可独立安装的 TypeScript 库。宿主以 `ready` 生成待办，通过 `submit` 提交结构化结果并获得新快照；同一包的 `ursi-flow-core/engine` 入口提供运行协调、记录契约、预检与包加载。执行器、进程与存储实现始终由宿主提供。

## 关键功能与验收

### 单文档流程推进

#### 验收

- `ready` 接收 `FLOW.md` 和可选的流程标识、启动变量，校验定义并渲染首个待办。不支持的动作或包能力在此时拒绝。
- 普通新建 Agent 和人工确认通过同一接口选边。全局变量持续到后续步骤，边的局部变量只用于准备紧接着的待办。人工确认只提交结果名。
- 循环返回同一节点产生新 `stepId`；旧回执、未声明的结果或变量、缺失的下一步输入均拒绝且原快照不变。结束边清空 `current`，结果留在 `steps`。

### 独立安装与跨进程推进

#### 验收

- 在仓库外仅安装 SDK 压缩包，可从 TypeScript 导入接口，也可从 Node.js 直接调用，无需 Runtime 或 daemon。
- 新进程仅凭宿主传入的 JSON 快照和回执继续推进，无需原文、共享进程或 SDK 存储。

### 宿主运行协调

#### 验收

- `ursi-flow-core/engine` 提供运行协调器、运行与节点记录契约、预检、只读视图、包发现与加载，以及内存存储实现。Agent、命令、并行、子 Flow 与持久化由宿主注入。
- 引擎自身不启动进程、不打开模型会话、不写运行目录；节点动作交给注入的扩展执行，记录与路由由引擎产生。
- 引擎复用同一份图解析、模板渲染与变量规则，`ursi-flow-core` 与 `ursi-flow-core/engine` 对同一份 `FLOW.md` 给出相同的校验结论。
