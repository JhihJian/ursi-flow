# Flow Core

## 功能意图

提供可独立安装的无状态 TypeScript SDK。宿主以 `ready` 生成待办，通过 `submit` 提交结构化结果并获得新快照。宿主持有运行、存储和执行。

## 关键功能与验收

### 单文档流程推进

#### 验收

- `ready` 接收 `FLOW.md` 和可选的流程标识、启动变量，校验定义并渲染首个待办。移除的动作标记（`复用Agent`、`执行Flow`、执行器后缀）与非法字段在此时拒绝。
- 四种动作通过同一组接口推进：`新建Agent`、`confirm`、`执行自定义命令`、并行开始点。全局变量持续到后续步骤，边的局部变量只用于准备紧接着的待办。人工确认只提交结果名。
- 循环返回同一节点产生新 `stepId`；旧回执、未声明的结果或变量、缺失的下一步输入均拒绝且原快照不变。结束边清空 `current`，结果留在 `steps`。

### 命令与并行

#### 验收

- 命令步骤给出已渲染的 `request`：`{var.x}`、`{input.x}` 与 `{branch.x.y}`（仅汇合节点）在准备待办时代入，单独引用保留 JSON 类型。命令节点只有 `已执行` 一条结果边。
- `output: "variables"` 的命令结果从 stdout 的 `{"variables": {...}}` 信封解析；`readCommandVariables` 拒绝非 JSON、非对象、缺信封或非法变量名。
- 并行步骤一次给出每个分支的已渲染请求与本次入参；分支必须是仅由并行开始点进入的命令节点，汇合节点必须引用每个直接分支。
- 并行提交按分支给出 `{outcome: "已执行", variables?}`。缺失分支、非 `已执行` 结果、未声明变量一律拒绝；两个分支写同一全局变量时拒绝并保持原快照。
- 并行完成后合并分支写入的全局变量，分支局部变量按分支引用供汇合命令读取，汇合步骤沿用并行入参。

### 独立安装与跨进程推进

#### 验收

- 在仓库外仅安装 SDK 压缩包，可从 TypeScript 导入接口，也可从 Node.js 直接调用，无需 Runtime 或 daemon。
- 新进程仅凭宿主传入的 JSON 快照和回执继续推进，无需原文、共享进程或 SDK 存储。
