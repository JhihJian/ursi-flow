# workflows

## 功能意图

workflows 管理工作流图定义，提供定义 CRUD、纯结构校验和角色引用校验，交付可用于创建运行的完整流程定义。
模块位于 server/src，复用原位 server/crates/domain 的图模型与纯校验规则，通过 storage 保存定义。
流程定义的编辑与引用一致性归本模块，运行快照、节点调度和运行状态由 runs 管理。

## 关键功能与验收

### 图定义创建与查询

提供流程创建、列表、详情查询，保存节点、边及节点执行配置，分配稳定流程标识。
合法定义完整保存，查询保留图结构及引用信息。

#### 验收

- 提交包含 agent、script、approval 节点的合法 DAG，创建成功，详情完整返回节点与边。
- 创建多个流程后列表能区分各自标识，查询未知标识返回明确的不存在结果。
- 重新打开临时 SQLite 后，读取的定义及节点配置与提交内容一致。

### 纯结构校验

调用 domain 纯校验入口检查字段、节点标识、边端点、节点类型和 DAG 无环规则。
纯结构校验以输入定义为唯一依据，可独立于数据库和角色服务执行。

#### 验收

- 合法单节点、链式及分支汇合 DAG 通过校验，调用过程中没有存储或角色查询。
- 重复或缺失节点标识、缺失边端点、未知节点类型及缺少必需配置返回可定位错误。
- 自环与多节点环均被拒绝，校验失败的创建或更新不改变已保存定义。

### 角色引用校验

在纯校验通过后，通过 roles 查询及检查接口验证 agent 节点引用的角色存在且可读取。
错误结果标明节点与角色引用，角色查询失败和确定缺失具有可区分的错误语义。

#### 验收

- 所有角色存在时，合法定义可以保存；多个节点引用同一角色时定义完整保留。
- 任一角色缺失时保存失败，错误定位对应节点和角色，流程与引用登记均保持原值。
- 角色查询不可用时返回查询失败，存储中不会出现未经角色校验的新定义。

### 定义更新、删除与引用一致性

创建或更新在同一 storage 事务中完成角色存在性检查、流程定义保存及 roles 引用登记变更。
删除流程在同一事务中移除定义并解除其登记，更新只保留新定义实际使用的角色引用。
角色删除通过 roles 检查已登记引用，与流程保存共享事务约束以保证并发一致性。

#### 验收

- 将角色引用从 A 改为 B 后，流程详情只含 B，A 的对应登记解除且 B 的登记建立。
- 保存、登记或解除登记任一步失败时事务整体回滚，定义与登记始终一致。
- 删除流程后其登记消失，其他流程的登记仍然保留，重复操作按不存在语义返回结果。
- 并发删除角色和保存引用时，仅允许存在角色的引用提交，或删除成功且流程保存失败。

### 定义交付与编辑隔离

向运行创建方交付完整定义和角色标识，运行创建方负责读取角色并冻结运行配置。
流程更新对后续读取生效，已交付的定义值保持稳定。

#### 验收

- 读取定义后编辑原流程，旧的读取结果不变，新的读取结果反映修改。
- 交付结果保留所有节点、边及配置，运行创建方可以定位需要冻结的全部角色。
- 仅创建、修改、查询或删除流程时，不产生运行记录、执行会话或节点状态变更。

## 交付与验收边界

- 独立环境使用临时 SQLite 和角色查询、登记接口替身，验证真实 workflows 与 storage 的读写路径。
- 独立交付覆盖合法与非法定义、DAG 校验、缺失角色、CRUD 及存储失败回滚。
- 替身用于验证角色查询和事务接口的调用契约，跨模块引用一致性使用真实 roles 与 storage 验收。
- server/runs 或 app 组织并发联调，交错执行角色删除、流程保存和事务回滚，确认持久化结果无悬空引用。
- server/runs 或 app 组织真实快照联调，验证流程及角色修改后旧运行继续使用旧定义和旧内容，新运行使用新配置。
- 执行顺序、凭据真实注入、节点状态及当前输出归属由运行联合验收覆盖，图定义验收结果限于本域行为。
