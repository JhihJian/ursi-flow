# server

## 功能意图

server 是 ursi-flow 的 kernel：HTTP/WebSocket/SSE 接入、应用服务、工作流引擎与存储的单体 crate。它把一次运行从工作流定义实例化，按拓扑顺序调度节点执行，管理状态机流转与人工审批，处理失败重试、打回返工与崩溃恢复，并承担过程可观测（事件广播与订阅）。对外经 REST/SSE 暴露流程、运行与审批接口；对下经 agent-runtime 接口驱动 agent、经 sandbox-gateway 契约编排沙箱生命周期。

单 crate 内模块分层：`handlers`（接入与参数校验）、`engine`（调度、状态机、审批、恢复、事件总线）、`database`（存储接口与 SQLite）、`sandbox`（Gateway 客户端与运行资源关联）。Flow 定义解析由 domain 提供，engine 负责执行。server 装配 Channel 与 Agent Runtime，基础库不反向依赖 server。

## 关键功能与验收

### 工作流接口

提供工作流创建、更新、查询、删除接口；创建与更新时解析并校验流程定义，非法定义被拒绝并返回校验错误。

#### 验收

- 提交合法流程定义，返回成功并持久化。
- 提交含环或非法节点的定义，返回 4xx 与校验错误信息，不持久化。
- 查询接口返回已存流程定义与节点、边。

### 运行接口

提供创建运行、启动运行、查询运行与节点状态、审批操作接口。审批操作支持放行与打回，打回需指定目标环节。

#### 验收

- 创建并启动运行后，可查询到运行状态与各节点状态。
- 对处于等待审批的节点调用放行，节点继续推进。
- 调用打回并指定目标环节，返回成功并触发该环节重做。
- 对非等待审批状态调用审批操作，返回 4xx。

### 运行创建与快照冻结

从流程定义创建一次运行（Run）。创建时冻结流程快照：图结构、节点定义、节点引用的角色定义、执行器定义与沙箱配置，均复制进运行记录，后续对流程或角色的编辑不影响在途运行。

#### 验收

- 给定一条流程定义，创建运行后，运行内保存的快照与创建时定义一致。
- 创建后修改流程定义或角色定义，运行内快照保持不变。

### 顺序调度执行

按依赖关系计算就绪节点，依拓扑顺序逐个执行。单次过程把输入（上游产物、运行上下文）与配置（节点引用的角色）交给执行器。首版为顺序执行，不实现并行分支。

#### 验收

- 给定「A → B → C」的链式流程与 mock 执行器，节点按 A、B、C 顺序各执行一次。
- 节点 A 失败时，下游 B、C 不执行，运行进入 failed。

### 状态机流转

依据 domain 定义的状态机推动运行与节点状态流转，任何状态提交必须携带运行代数（generation）守卫，防止过期执行写入新状态。

#### 验收

- 运行从 queued 进入 running；全部节点成功后进入 succeeded。
- 任一节点失败且不可打回时，运行进入 failed。
- 存在等待审批节点时，运行进入 waiting。

### 人工审批与打回

审批节点执行后进入 `waiting_approval`，暂停推进。人工放行使节点 succeeded 并继续下游；打回按 `RejectTo` 指定的环节重置该环节及其下游为 pending 并重新执行。`RejectTo` 必须是打回节点的传递祖先，且用最大返工次数（`MaxReworks`）防止无限循环。

#### 验收

- 运行到达审批节点后，节点状态为 waiting_approval，运行状态为 waiting。
- 放行后，节点转为 succeeded，下游继续执行。
- 打回到上游环节后，该环节及其全部下游被重置为 pending 并重新执行。
- `RejectTo` 指向非祖先节点或自身时，打回请求被拒绝。
- 返工次数超过 `MaxReworks` 时，运行进入 failed。

### 失败重试

节点执行失败时按重试策略重试（`MaxAttempts` 限制次数），或按 `OnFailure` 策略失败或打回。

#### 验收

- 节点失败且未超过 `MaxAttempts` 时，自动重试该节点。
- 超过 `MaxAttempts` 后，节点进入 failed。

### 租约与崩溃恢复

运行被引擎实例持有期间维持租约（TTL + 心跳续约），并记录持有实例与代数。引擎重启后，租约到期的运行可被重新接管，按持久化状态继续调度。

#### 验收

- 引擎持有运行期间定期续约，租约不因正常执行超时。
- 模拟引擎崩溃后，另一实例可接管租约到期的运行并继续执行。

### 执行环境接入

`sandbox` 模块请求 Gateway 准备或释放资源并关联运行与沙箱标识，Gateway lifecycle 拥有资源状态与对账。文件和 script 命令通过 Channel 的 SFTP/SSH 完成，agent 任务通过 Agent Runtime 控制 session-service。生产使用网络客户端，测试使用可替换客户端。

#### 验收

- 节点执行前确认沙箱就绪并写入输入，执行后可回收产物。
- 运行结束后提交释放请求；释放失败可查询、可重试，不能把请求失败标记为资源已释放。
- 客户端替身可验证调用顺序，服务端不维护另一套基础设施恢复状态机。

### 存储与状态提交一致性

工作流定义、角色、运行与节点状态、观测事件持久化存储。节点状态更新与观测事件追加在同一事务中提交；状态提交携带运行代数守卫，拒绝过期写入。存储接口可在测试中替换为内存实现。

#### 验收

- 启动时自动建表，重复启动不报错；数据持久化到磁盘，进程重启后读回一致。
- 提交节点状态与事件时，二者要么同时成功要么同时失败。
- 携带过期代数的状态更新被拒绝，不覆盖新状态。

### 事件广播与订阅

engine 内置事件总线：运行事件（节点状态、工具轨迹、日志、产物发布）规范化为 domain 的 `TelemetryEvent` 后广播，订阅方（database 持久化、handlers SSE）按运行过滤消费。总线只广播不持久化，无订阅方时事件丢弃不报错。

#### 验收

- 上报一条节点状态事件后，订阅方按顺序收到该事件，事件带运行与节点归属。
- 无订阅方时上报事件不报错、不阻塞执行。
- 执行器经 agent-runtime 的事件入口上报工具轨迹，事件以 `TelemetryEvent` 契约到达订阅方。

### SSE 事件订阅接口

通过 SSE 提供观测事件的流式推送，支持按运行过滤。订阅顺序先于重放：先挂上 engine 事件订阅，再从 database 读回历史事件，保证不丢不重。

#### 验收

- 建立 SSE 订阅后，运行新产生的事件实时推送到客户端。
- 订阅参数指定运行后，只收到该运行的事件。
- 订阅建立瞬间的并发事件不丢失、不重复。

### 静态页面内嵌

web 构建产物经 rust-embed 嵌入二进制（feature 隔离，无产物时回退目录读取），单文件分发。

#### 验收

- 开启内嵌 feature 构建后，HTTP 服务可直接返回页面资源，无外部静态文件依赖。
- 无构建产物时不内嵌，接口与页面回退行为不 panic。
