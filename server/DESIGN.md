# Server 模块设计与交付边界

## 组织原则

server 是一个模块化单体。`server/src` 按业务对象和状态所有权划分内部模块，每个模块以公开服务接口和可观察结果作为交付边界。`server/crates` 保持现有布局和编译边界，基础库由主服务或沙箱会话服务按运行位置装配。

模块独立交付指可以用本域真实存储和外部依赖替身验证完整用例。独立交付不要求独立进程、独立数据库或独立 Cargo 包。模块规格定义目标行为，是否实现由测试和验收记录证明。

## 模块与界面

| 模块 | 对应界面能力 | 唯一所有权 |
|---|---|---|
| workflows | 流程列表、详情、定义编辑 | 可编辑的图结构、节点定义、角色引用 |
| roles | 角色列表、编辑、复制 | 提示词、Skills 文件包、MCP 配置、模型和执行器选择 |
| runs | 运行列表、详情、审批、日志和工具轨迹 | 快照、运行与节点状态、执行轮次、调度、恢复、持久化事件 |
| artifacts | 运行中的产物列表、预览和下载 | 产物内容、元数据及运行、节点、轮次归属 |
| sandboxes | 沙箱状态、运行关联、文件与连接入口 | 平台侧资源关联、控制请求和访问接入 |
| connections | 模型连接与凭据设置 | 模型服务连接、凭据引用及受控解析 |
| transport | API、SSE/WS、MCP、页面资源接入 | 协议解析、路由、错误映射和流传输 |
| storage | 无独立业务页面 | SQLite 连接、迁移、事务和内容存储基础能力 |
| app | 服务启动与就绪状态 | 配置加载、依赖装配、启动与关闭 |

网页功能以 web 的规格为准，业务服务可以先经接口验收。审批与事件属于 runs；engine 是 runs 内部的调度实现。产物模块返回内容和契约检查结果，runs 决定节点是否完成及哪些产物可用于下游。

## 依赖方向与公开边界

- app 组装 storage、各业务服务和 transport。
- transport 调用各业务域公开服务，MCP 工具通过同样的业务接口访问状态。
- runs 编排 workflows、roles、connections、artifacts、sandboxes 和 Agent Runtime。
- workflows 调用 roles 的引用校验与登记接口；roles 调用 connections 的配置查询与引用接口。
- sandboxes 通过 Gateway 契约与 Channel 接入资源和连接。
- 各域使用 storage 提供的事务和存储基础设施，业务表、查询与 repository 属于各自域。

被调用方不回调上游域，不访问上游 repository。各域通过构造时注入的窄接口获得依赖，独立测试可以替换这些接口。跨进程共享类型继续由 domain 等现有契约提供，领域内部类型留在所属模块。

模块内部可按规模拆为服务、模型、repository 和测试文件。transport 按业务组织协议适配文件。app 是实现选择与装配入口，各业务模块不读取全局服务容器。

## 一致性归属

### 配置引用与运行快照

roles 拥有角色引用登记，workflows 保存或删除定义时，在同一 SQLite 事务中同步登记或释放角色引用。删除角色与新增引用使用同一约束，保证并发操作只有合法的串行结果。connections 对角色引用采用相同原则。引用登记保存来源标识，不依赖来源域的内部类型。

runs 创建运行时发起一致读取事务，经各域支持该事务的查询接口读取流程、角色和模型连接，固定执行器定义、沙箱配置和技能内容，再保存快照。任一步失败都不产生可启动的运行。可变技能路径必须转为持久内容或可取回的不可变内容引用，角色名和文件路径本身不构成冻结。

凭据只冻结引用，执行时解析当前可用值。密钥轮换或撤销可以影响后续执行，外部模型和 MCP 服务的行为也不属于配置快照的可重现范围。快照冻结的是配置和受管内容。

### 状态、事件与产物

runs 在同一事务内校验持有代数、更新状态并写入有序事件，提交成功后广播。广播是实时通知，数据库事件是历史重放和断线补读的事实来源。提交后通知前崩溃时，恢复查询仍能读到已提交事件。

artifacts 按运行、节点、代数和执行尝试保存产物。generation 表示运行持有代数，attempt 是节点在该运行内单调递增且持久化的执行编号，重试、返工和恢复均不复用。单轮 MaxAttempts 计数与这个累计身份编号分开管理。

runs 依据当前执行身份决定有效输出，过期执行的状态、事件或产物不能替换当前结果。文件内容先稳定保存，再发布元数据引用；失败产生的孤立内容由存储清理，不向业务暴露缺失内容的已完成产物。

### 资源与会话

Gateway 拥有沙箱实际生命周期，sandboxes 保存平台侧关联和请求结果。释放请求失败或结果未知时保留待核实状态，通过 Gateway 查询与幂等操作确认。Channel 管连接，Agent Runtime 管客户端会话控制，沙箱 session-service 装配真实 CLI Adapter。

## 独立交付与联合验收

| 模块 | 独立验收环境与结果 | 联合验收边界 |
|---|---|---|
| workflows | 临时 SQLite、角色接口替身，验证 CRUD、DAG 与引用错误 | 与 roles、storage 验证引用并发一致性 |
| roles | 临时 SQLite 和文件目录、连接接口替身，验证完整配置管理与内容读取 | 与 workflows 验证删除约束，与 runs 验证配置冻结 |
| connections | 临时 SQLite、凭据提供方和能力描述替身，验证配置与脱敏 | 与 Agent Runtime、真实执行器验证凭据和模型生效 |
| artifacts | 临时 SQLite 和内容目录，验证读写、归属、幂等与契约检查 | 与 runs 验证返工和迟到产物，与沙箱链路验证真实回收 |
| sandboxes | Gateway、Channel 替身和本域真实存储，验证关联和失败处理 | 真实 Gateway、Channel 验证资源与文件连接行为 |
| runs | 本域真实存储、可控时钟和依赖替身，验证顺序执行、审批、重试和恢复 | 与配置域验证快照，与真实执行链路验证任务结果 |
| storage | 临时 SQLite 和文件目录，验证迁移、重开、回滚和并发事务 | 与各域 repository 验证业务原子操作 |
| transport | 进程内 HTTP 服务、业务接口替身，验证请求、错误映射和流协议 | 与 runs、storage 验证 SSE 重放，与业务服务验证真实 API |
| app | 配置夹具、可记录生命周期的组件，验证启动失败与关闭顺序 | 以真实 SQLite、HTTP 和执行依赖完成应用验收 |

独立验收测试应能单独选择运行，不要求先启动整个系统。真实 SQLite 的并发和重开行为使用数据库验证，替身用于外部服务的确定性返回和故障注入。transport 和 app 可以分别验证协议与生命周期，但产品可用性以联合验收为准。

server 总规格拥有四组联合验收：配置引用与快照、状态与事件、执行与产物、应用装配。参与模块在各自 SPEC 中列出边界，联合场景由主服务集成测试统一组织。真实 CLI、真实文件传输和真实资源回收分别需要对应环境证据。
